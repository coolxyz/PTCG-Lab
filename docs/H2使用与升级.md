在人机练习大厅选择自己的推荐预设，系统保存卡组版本；再选择 AI 卡组和默认 H2。对局顶部显示实际策略。旧局保持原发布和策略，更新后需新建对局。自定义版本只有卡牌印刷 ID 与数量全部匹配时才启用专家；改动后的卡表使用原 H2。环境不匹配也使用原 H2，不能通过放宽哈希检查强行启用。

五套卡表是项目配置，随源码包含在 `packages/battle/h2-presets-v1.json`；不是全卡池。运行仍需合法、可信、兼容的卡牌数据、效果实现和引擎资产。当前专家绑定的三项环境资产（plain-pokemon、effects、overlay-hashes）组合哈希为 `b99ea98fb92f1e0cdee7a7473f1aa3739dedb1226953871ac56dd5526da3ce85`。公开仓库不附带完整资产，准备方法见 [本地资产说明](GitHub发布与隐私.md)。

2026-10-20 同步了 [检索牌库浏览与历史对局名称改进](对战-检索牌库浏览与AI可见信息.md)。此次只扩展规则允许的观察与界面，五套策略版本不变；既有安装需要匹配的新运行资产及新的 API 发布。旧发布继续处理旧对局。

## 更新已有安装

先备份个人数据库、冻结发布，以及数据库同目录的 `h2-experts-rollout.json`（若存在）。原安装若没有活动发布、却已有未绑定旧对局，必须在更新源码前用旧源码保存 baseline；不要用新版源码冒充旧局运行环境：

```bash
.venv/bin/python -c "from packages.sync.service import SyncService; print(SyncService().baseline())"
```

更新源码并准备匹配资产后，重新安装／构建并检查：

```bash
bash start.sh --setup --check
.venv/bin/python scripts/battle/h2_manage.py publish
bash start.sh
```

Windows 对应使用 `start.ps1 -Setup -Check`、`.venv\Scripts\python.exe scripts\battle\h2_manage.py publish` 与 `start.ps1`。此前策略移植的验收平台为 macOS；2026-10-20 的 Windows 本地修复与验证记录见下文，两次验证范围分别记录。

`publish` 将当前源码和本地资产归档，使用临时数据库检查冻结 worker 的五套卡组建局与推进，备份用户数据库，再切换活动 API 发布。发布记录位于 `.catalog/sync/h2-publication.json`，包含新旧发布 ID 和备份位置。失败时不跳过校验。默认数据库是 `var/app.sqlite`；使用自定义数据库时，`--db` 与 `--home` 必须对应运行服务的数据库和同步目录。

如确认要使用当前本地源码和运行资产强制更新 H2，可执行（仅支持 `publish`）：

```powershell
.venv\Scripts\python.exe scripts\battle\h2_manage.py publish --force
```

`--force` 使用已有的本地引擎，在新的发布快照中把效果清单重新绑定到归档引擎版本，以处理 `EFFECT_ENGINE_MISMATCH`；不重建底层 PTCG 引擎，也不下载缺少的资产。工作目录中的 `data/`、旧发布和历史对局保持原样。五套预设建局与推进检查、引擎文件完整性检查、个人数据库备份和旧局 baseline 检查仍执行；检查失败不会激活新发布。专家策略仍按新快照的实际环境匹配，环境不匹配时使用原 H2，不强行启用专家。发布记录含 `forced`、原效果引擎版本、新引擎版本及五套预设实际策略；通过这些字段可以识别强制发布。该模式不代表已经通过配套资产的完整回归验收。完成后重启服务，并新开对局使用新版 H2。

首次安装不需要已有发布：兼容环境下直接启动即可使用 H2 与五套专家。若已有活动快照，只更新前端或刷新缓存不足以升级 API。更新后进入大厅，检查五套预设，并新开一局确认策略名称。

## Windows 换行与运行资产修复（2026-10-20）

此次本地安装存在两个独立问题：策略源码在 Windows 检出时被转为 CRLF，使按字节计算的策略包指纹与已验收配置不同；运行目录还保留旧版引擎和效果清单，与五套专家要求的环境不匹配。恢复 LF 后，策略包指纹重新匹配 `apps/api/h2-rollout.json`，无需改动策略逻辑或配置中的指纹。

仓库新增 `.gitattributes`，为 `apps/api/expert_policies/`、`apps/api/expert_service.py` 和引擎覆盖清单固定 LF。该规则兼容 macOS，不改变 `start.sh`、平台解释器选择或发布／回滚逻辑。已有工作区不会仅因新增规则就自动重写所有文件；应检查这些文件实际采用 LF，并保留其他本地修改。可用 `git ls-files --eol apps/api/expert_policies apps/api/expert_service.py` 检查，相关文本文件应显示 `w/lf`，空文件可能显示 `w/none`。

运行资产的修复使用本地可信、无源码修改的固定上游提交 `92c3cc4fe85a26f102d7bb6b3e8be7678512d2e5`，通过当前构建脚本重新生成引擎及覆盖清单，再生成与该引擎版本配套的效果清单。修复后引擎版本为 `243a0dbb3059c4c53c48cf4dd94fce562f4dcc2fed806956f504d333441cf4d4`，三项环境资产的组合哈希精确匹配上文的 `b99ea98f…`。本次采用普通 `publish` 完成切换，数据库先行备份，旧冻结发布保留。

这些引擎、卡池、效果清单、个人数据库和 `.catalog/sync/` 发布状态属于本地资产，不随本次 Git 提交分发。Mac 拉取源码后仍须在本机准备匹配资产、发布并重启；Windows 本机的切换不会替另一台机器完成升级。

## Mac 更新并启用五套专家

以下命令在 Mac 项目根目录执行，以启用当前五套专家为目标。跨系统迁移需在 Mac 重建 `.venv` 和 `node_modules`，不要复用 Windows 的依赖目录。使用自定义数据库或同步目录时，下面所有管理命令均需加上对应的 `--db`、`--home`，与服务的 `PTCG_DB`、`PTCG_SYNC_HOME` 一致。

1. 停止旧服务，备份数据库、冻结发布和 `h2-experts-rollout.json`。若旧安装尚无活动发布且存在未绑定历史对局，先按上文使用旧源码保存 baseline，再更新源码。
2. 保存好本地修改后执行 `git pull --ff-only`。准备与当前源码匹配的可信运行资产；Git 拉取和安装依赖均不会下载或升级完整对战资产。首次向空目录导入资产的方法见 [本地资产说明](GitHub发布与隐私.md)，导入工具会拒绝覆盖已有资产。已有资产不匹配时，需先备份并准备配套资产，维护者也可按下一节从固定上游重建。
3. 安装／构建并检查环境：

   ```bash
   bash start.sh --setup --check
   ```

4. 发布前检查策略包、环境和效果清单绑定。此检查不修改数据库或开关：

   ```bash
   .venv/bin/python - <<'PY'
   import json
   from pathlib import Path
   from apps.api.expert_policies import registry
   from packages.battle.service import runtime
   from packages.simulation.registry import RELEASE

   shipped = json.loads(Path('apps/api/h2-rollout.json').read_text(encoding='utf-8'))
   bundle, environment = registry.identity()
   assert bundle == shipped['bundleHash'], '策略包指纹不匹配；检查源码和 LF 换行'
   assert all(p.PROFILE['environmentHash'] == environment
              for p in registry.POLICIES.values()), '运行资产不匹配；先准备配套资产'
   assert RELEASE['engineVersion'] == runtime().ENGINE_VERSION, '效果清单与引擎版本不匹配'
   print('策略包、环境、引擎与效果清单检查通过')
   PY
   ```

   `start.sh --check` 成功只说明启动依赖和引擎可加载；上述检查进一步确认专家所需的资产身份。任一检查失败时先修复对应问题，不修改专家的 `environmentHash` 或默认 `bundleHash` 来绕过检查。

5. 发布本机新快照，然后启用五套专家并查看配置：

   ```bash
   .venv/bin/python scripts/battle/h2_manage.py publish
   .venv/bin/python scripts/battle/h2_manage.py enable
   .venv/bin/python scripts/battle/h2_manage.py status
   ```

   `enable` 会更新旧策略包的本地覆盖配置，也会将此前主动关闭的专家重新启用；若希望继续关闭专家，省略该命令。单独 `enable` 不会升级旧活动快照。`status` 仅显示开关配置，不证明正在运行的 API 已切换或对局已使用专家。发布成功也可能包含回退原 H2 的策略，仍须完成下一步确认。

6. 启动服务并刷新浏览器：

   ```bash
   bash start.sh
   ```

   保留原端口和浏览器身份，逐一选择五套推荐预设作为 AI 卡组并新开对局。顶部应分别显示长毛巨魔 v7、沙奈朵 v5、多龙 v9、N 索罗亚克 v2、电电虫 v1；确认能进入对战、推进并在刷新后恢复。旧对局仍使用其冻结版本。若显示“原 H2”，检查当前活动发布、覆盖配置、精确卡表及运行资产，而不是继续刷新旧局。

本次修复在 Windows 完成实机验证；上述 Mac 步骤依据现有跨平台脚本整理，未在此次修复后重新进行 Mac 实机验收。此前 Mac 上的策略移植验收记录仍见文末。

### 维护者：从已有固定上游重建匹配资产

此步骤用于仍持有旧运行资产、但已有完整可信卡池和固定上游源码的安装，不是从空源码目录初始化全卡池。先备份 `runtime/engine/`、`data/simulation/effects.json` 和 `artifacts/engine/overlay-hashes.json`；旧冻结发布不得改写。`vendor/engine-upstream` 必须位于上述固定提交，且 `src` 无修改。上游源文件应保持原始 LF 字节，否则生成的覆盖清单可能与已验收环境不同。

在 Mac 上运行当前构建脚本：

```bash
.venv/bin/python scripts/engine/build_engine.py
```

然后计算配套效果清单的候选内容，只有其组合哈希精确匹配全部五套专家时才写入：

```bash
.venv/bin/python - <<'PY'
import hashlib
import json
from pathlib import Path
from apps.api.expert_policies import registry
from packages.battle.service import runtime
from packages.sync.common import encoded, read, write

effect_path = Path('data/simulation/effects.json')
effects = read(effect_path)
effects['engineVersion'] = runtime().ENGINE_VERSION
candidate = encoded(effects)
profiles = [p.PROFILE for p in registry.POLICIES.values()]
for profile in profiles:
    hashes = {
        name: hashlib.sha256(candidate if name == effect_path.as_posix()
                             else Path(name).read_bytes()).hexdigest()
        for name in profile['environmentFiles']
    }
    environment = hashlib.sha256(json.dumps(hashes, sort_keys=True).encode()).hexdigest()
    if environment != profile['environmentHash']:
        raise SystemExit('候选资产与专家要求不匹配，未写入效果清单；准备配套资产或恢复备份')
write(effect_path, effects)
print('配套效果清单已写入，环境：', environment)
PY
```

该操作仅更新工作目录中的效果引擎绑定，不改变效果实现或专家配置。校验失败会拒绝写入效果清单；此时新生成的运行引擎仍在工作目录，需要准备匹配资产或恢复备份。成功后重新执行上节的发布前检查、`publish`、`enable` 和重启步骤，使用新的进程加载效果清单。`publish --force` 不代替这项精确环境验证。

## 关闭与回滚

```bash
# 所有新 H2 对局使用原 H2；已有专家对局继续其冻结策略
.venv/bin/python scripts/battle/h2_manage.py disable
.venv/bin/python scripts/battle/h2_manage.py status
# 恢复当前已检查的五套专家，拒绝代码或环境哈希不一致
.venv/bin/python scripts/battle/h2_manage.py enable
# 如需恢复整个 API，使用发布记录中的 previous ID
.venv/bin/python scripts/battle/h2_manage.py rollback --release PREVIOUS_RELEASE_ID
```

配置保存在数据库同目录的 `h2-experts-rollout.json`。没有本地覆盖文件时使用随源码发布的默认配置。策略开关不会切换活动代码版本；代码升级仍需 `publish`。若曾执行过 `enable`，本地覆盖文件仍绑定旧策略包；更新并发布后再执行 `enable`，以恢复新版本的五专家配置。若曾主动 `disable`，升级保留关闭状态。回滚旧发布时，恢复此前备份的覆盖文件；此前没有覆盖文件则移走新覆盖文件，让旧发布使用其自带配置，避免新哈希导致旧专家关闭。保留旧发布目录和用户备份，不改写冻结文件。回滚整个 API 后，新建局使用前版；已绑定的局仍由对应发布处理。

## 实现与验证范围

通用 H2 位于 `packages/battle/h2.py` 和 `h2_v4/`；卡表专家位于 `apps/api/expert_policies/`，只接收 AI 可见局面和合法动作，不读取对方手牌、牌库顺序和暗置奖赏。产品路由在建局时固定策略身份；恢复时检查卡表、环境和实现版本。异常或非法提案回退原 H2。内部手牌分析与候选计划不进入公开事件。

五套专家源自已完成的独立完整对局确认；首批实验中，长毛巨魔相对原 H2 得分提升35.6个百分点，多龙提升32个百分点，电电虫提升16个百分点。它们是固定卡表与环境内的比较，不代表竞技等级或所有对位均改善。后续 N 索罗亚克 v2 与沙奈朵 v5 均通过新种子独立确认：各200局（候选和原H2各100局），索罗亚克75胜对59胜，增益16个百分点；沙奈朵64胜对36胜，增益28个百分点。对应单侧95%正态近似下界为6.41和20.21个百分点；各自在固定五对手中的点估计均为正，不代表每个对位都单独达到统计显著。沙奈朵修正统一了手附、精神拥抱、撤退和攻击者计划；索罗亚克修正了后续主攻、供能与撤退衔接。本次移植不重新调参，也不以 A1 胜率继续提升 H2。

源码版同步还包含双方同时满足相同数量胜利条件时的平局显示，以及已支持胜利效果的终局识别。新测试不依赖私人训练目录或实验回放。外部 LLM 实验和本地端点不属于此次公开产品范围。
