在人机练习大厅选择自己的推荐预设，系统保存卡组版本；再选择 AI 卡组和默认 H2。对局顶部显示实际策略。旧局保持原发布和策略，更新后需新建对局。自定义版本只有卡牌印刷 ID 与数量全部匹配时才启用专家；改动后的卡表使用原 H2。环境不匹配也使用原 H2，不能通过放宽哈希检查强行启用。

五套卡表是项目配置，随源码包含在 `packages/battle/h2-presets-v1.json`；不是全卡池。运行仍需合法、可信、兼容的卡牌数据、效果实现和引擎资产。当前专家绑定的三项环境资产（plain-pokemon、effects、overlay-hashes）组合哈希为 `39b3a63ea316f17e834d67af0af8ba3862c36f4825ed144b741ce9be8f207d57`。公开仓库不附带完整资产，准备方法见 [本地资产说明](GitHub发布与隐私.md)。

## 更新已有安装

先备份个人数据库、冻结发布，以及数据库同目录的 `h2-experts-rollout.json`（若存在）。原安装若没有活动发布、却已有未绑定旧对局，必须在更新源码前用旧源码保存 baseline；不要用新版源码冒充旧局运行环境：

```bash
.venv/bin/python -c "from packages.sync.service import SyncService; print(SyncService().baseline())"
```

更新源码并准备匹配资产后，重新安装／构建并检查：

```bash
bash start.sh --setup --check
.venv/bin/python scripts/battle/h2_manage.py publish
bash start.sh
```

Windows 对应使用 `start.ps1 -Setup -Check`、`.venv\Scripts\python.exe scripts\battle\h2_manage.py publish` 与 `start.ps1`。脚本和路径分支已提供；本次实际验收平台为 macOS、Python 3.14、Chrome，未声称已完成 Windows 实机验收。

`publish` 将当前源码和本地资产归档，使用临时数据库检查冻结 worker 的五套卡组建局与推进，备份用户数据库，再切换活动 API 发布。发布记录位于 `.catalog/sync/h2-publication.json`，包含新旧发布 ID 和备份位置。失败时不跳过校验。默认数据库是 `var/app.sqlite`；使用自定义数据库时，`--db` 与 `--home` 必须对应运行服务的数据库和同步目录。

首次安装不需要已有发布：兼容环境下直接启动即可使用 H2 与五套专家。若已有活动快照，只更新前端或刷新缓存不足以升级 API。更新后进入大厅，检查五套预设，并新开一局确认策略名称。

## 关闭与回滚

```bash
# 所有新 H2 对局使用原 H2；已有专家对局继续其冻结策略
.venv/bin/python scripts/battle/h2_manage.py disable
.venv/bin/python scripts/battle/h2_manage.py status
# 恢复当前已检查的五套专家，拒绝代码或环境哈希不一致
.venv/bin/python scripts/battle/h2_manage.py enable
# 如需恢复整个 API，使用发布记录中的 previous ID
.venv/bin/python scripts/battle/h2_manage.py rollback --release PREVIOUS_RELEASE_ID
```

配置保存在数据库同目录的 `h2-experts-rollout.json`。没有本地覆盖文件时使用随源码发布的默认配置。策略开关不会切换活动代码版本；代码升级仍需 `publish`。若曾执行过 `enable`，本地覆盖文件仍绑定旧策略包；更新并发布后再执行 `enable`，以恢复新版本的五专家配置。若曾主动 `disable`，升级保留关闭状态。回滚旧发布时，恢复此前备份的覆盖文件；此前没有覆盖文件则移走新覆盖文件，让旧发布使用其自带配置，避免新哈希导致旧专家关闭。保留旧发布目录和用户备份，不改写冻结文件。回滚整个 API 后，新建局使用前版；已绑定的局仍由对应发布处理。

## 实现与验证范围

通用 H2 位于 `packages/battle/h2.py` 和 `h2_v4/`；卡表专家位于 `apps/api/expert_policies/`，只接收 AI 可见局面和合法动作，不读取对方手牌、牌库顺序和暗置奖赏。产品路由在建局时固定策略身份；恢复时检查卡表、环境和实现版本。异常或非法提案回退原 H2。内部手牌分析与候选计划不进入公开事件。

五套专家源自已完成的独立完整对局确认；首批实验中，长毛巨魔相对原 H2 得分提升35.6个百分点，多龙提升32个百分点，电电虫提升16个百分点。它们是固定卡表与环境内的比较，不代表竞技等级或所有对位均改善。后续 N 索罗亚克 v2 与沙奈朵 v5 均通过新种子独立确认：各200局（候选和原H2各100局），索罗亚克75胜对59胜，增益16个百分点；沙奈朵64胜对36胜，增益28个百分点。对应单侧95%正态近似下界为6.41和20.21个百分点；各自在固定五对手中的点估计均为正，不代表每个对位都单独达到统计显著。沙奈朵修正统一了手附、精神拥抱、撤退和攻击者计划；索罗亚克修正了后续主攻、供能与撤退衔接。本次移植不重新调参，也不以 A1 胜率继续提升 H2。

源码版同步还包含双方同时满足相同数量胜利条件时的平局显示，以及已支持胜利效果的终局识别。新测试不依赖私人训练目录或实验回放。外部 LLM 实验和本地端点不属于此次公开产品范围。

## publish 建局检查失败／引擎版本不一致

`publish` 不会自动把不匹配的效果数据重新标为兼容。`EFFECT_ENGINE_MISMATCH` 表示工作目录的引擎计算版本与 `data/simulation/effects.json` 的 `engineVersion` 不一致；该检查发生在建局前。失败不会激活候选发布。

运行只读诊断（Windows 项目根目录）：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\battle\h2_manage.py diagnose
```

报告默认写入 `.catalog/sync/h2-diagnostics.json`，包含 Git 提交、两项引擎版本、参与版本计算的逐文件哈希、换行统计、引擎覆盖层完整性及专家配置匹配情况。它不修改源码、效果绑定、用户数据库或活动发布。若仅下载独立诊断脚本，可使用 `python -X utf8 h2_diagnostics.py --root .`，不依赖新版管理脚本。

新版发布错误会显示 HTTP 状态、后台错误码和原因，并保存 `.catalog/sync/h2-publish-failure.json` 与 worker 日志位置。请先比较诊断报告，再区分代码版本、资产包、构建输出或文件格式差异。仅两个总哈希不能定位具体文件，Windows 换行转换也不是未经核验的既定原因。不要直接修改 `effects.json` 的 `engineVersion`、绕过校验或改写冻结发布目录。恢复匹配且经过验证的代码与资产组合后再发布。
