状态：P5.5 已按用户确认完成；本文保留为后续物理设备补验手册，尚未记录 Mac 与 Windows/WSL2 两台物理设备全部逐项通过。用户已报告完整对局测试完成，反馈修复与大厅优化已提交。阶段完成不替代以下逐项实测，范围见 [完成记录](P5.5产品整合完成记录.md)。

## 安装和启动

使用本次生成的 **完整产品验收包**，不要继续使用 P5 独立网络窗口测试包。两台设备各解压一份到较短的独立目录，如 `~/ptcg-p55`；Windows 端在 WSL2 的 Linux 主目录内解压，不在 `/mnt/c` 放凭据。首次安装需要 Python 3.14+、Git 和依赖下载网络；已带前端构建产物，不需要 Node/npm。不要复制一台设备已运行后的整个目录给另一台，否则会复制身份。

```sh
cd ~/ptcg-p55
python3 manage.py verify
python3 manage.py install
python3 manage.py run
# WSL2：
python3 manage.py run --no-browser
```

两台浏览器均打开自己电脑的 `http://127.0.0.1:18789/`。在“网络对战”输入本机终端的五分钟一次性授权码，然后创建各自游客身份。Windows 浏览器通过 WSL2 localhost forwarding 访问；如不能访问，先在 WSL 内访问同一地址确认后台状态，再检查 WSL 的 localhost 转发设置，不把 APP 改为监听 `0.0.0.0`。两台电脑都须能访问验收包 `connection.json` 中的 API 地址；不要关闭 TLS 校验或导入服务器私钥。

同一浏览器关闭重开直接访问该地址。换浏览器或授权过期，在另一个终端执行 `python3 manage.py reopen --no-browser` 获取新授权码。退出后台用运行它的终端 Ctrl-C；重启执行同一条 run 命令。端口冲突可用 `--port 18790`，不要终止其他产品服务。WSL2 下不能用 Windows 原生 Python 启动此包。

包内没有用户收藏、卡组数据库或游客身份。首次进入产品，使用平台已有的预设/卡组导入功能保存为“我的卡组”，再冻结版本。验收时两种模式都从这份平台卡组进入，不在网络大厅粘贴 JSON。有自己的卡组时可在构筑页面导入；不必复制旧用户数据库。真正的用户数据库升级回归应在本人批准的备份副本上进行，不能将这种干净安装冒充升级验收。

## 资源供应与离线检查

验收包附带明确批准的规则、显示卡表和部分已校验卡图；这是私有测试制品，不是已获许可公开分发的卡图发行版。安装先核验清单，再校验卡图 Git blob、SHA-256、格式与像素限制，合并到本机 `.catalog/sync/images`。首次安装 Python 依赖并非离线安装；可提前在对应平台下载两个 requirements.lock 及四个内部 wheel 的依赖闭包，通过 `install --wheelhouse /absolute/wheels` 离线安装。不要把 Mac 二进制 wheel 用于 WSL2。

卡图未覆盖全卡池，缺图降级文字。已安装卡图不访问图源；后续图源下载继续使用固定提交及 blob 校验，API v2 不供应图片。离线测试保留局域网连接，只阻断互联网图源（或断开互联网出口），并关闭浏览器缓存后重新加载已有图片；只看到浏览器旧缓存不算通过。确认网络请求只有本机卡图路径，没有浏览器直连图源或 API 图片请求。另选一张未缓存卡牌，确认缺图不阻断合法操作。

旧版目录快照、内容哈希图片和 `(commit, cardId)` 缓存都保留。新增资源包只合并，不清空缓存、不覆盖冲突版本；原地升级 APP 时保留 `app/var`、`app/.catalog` 以及批准的旧规则发行数据。资源更新后重启本机 APP，再检查旧回放的卡名和图片。旧 catalog 缺失时明确退回文字，不冒用新版卡表。只有远端返回 engineId 时按“平台默认卡面”显示，不能据此验收用户选择的闪卡卡面。

资源包单独生成/安装命令（APP 停止后安装，来源必须可信）：

```sh
python scripts/product/resources.py export --home /approved/sync-cache --pack /new/artwork-pack
python scripts/product/resources.py install --pack /approved/artwork-pack --home .catalog/sync
```

清单校验是完整性检查，不是发布者数字签名。第三方下载包须通过可信渠道核对归档 SHA-256。严禁用 `scripts/portable/pack.py` 生成供另一位玩家使用的包：那个工具是个人迁移工具，包含私有状态。

## 两台设备共同操作

1. 记录包的 `KIT-MANIFEST.json` 摘要、Mac/Windows/WSL/Python/浏览器版本、API 地址及规则版本。每台执行 `python3 manage.py report --report acceptance-mac.json`（另一台用不同文件名）生成待填写记录。
2. 打开收藏、资料库、构筑与网络大厅，确认同一本机 origin、单一本机 HTTP 后台。保存卡组并冻结，在人机模式开局；返回其他页面后再回来，确认状态连续，结束并查看回放。
3. 从同一份已保存版本进入网络大厅，核对提交卡组名称、版本及规则。Mac 创建房间，Windows 输入房间码加入，双方准备；记录 matchId。不要上传收藏数量、备注或本地数据库。
4. 完成一次**自然终局**，双方分别检查结果与只读回放；主动认输测试不能替代自然终局。回放拖动、翻页和重新打开后结果一致，无对手未公开手牌泄漏。
5. 对局中编辑原卡组或新建版本，确认当前对局和已提交版本没有改变。检查并发保存冲突；提交不合法版本应显示本地逐条检查及服务端拒绝，不能继续误用此前已提交卡组。
6. 测试刷新、复制标签页和新窗口取得控制权；旧窗口不能继续写。关闭浏览器、重新打开，后台重启后仍为同一身份；若提示未知操作，先恢复/核对回执，不另造请求。
7. 暂时断开一台设备网络，另一台与本地管理页面仍可用；恢复后核对序号及操作，无重复推进。仅在该设备阻断 API，验证收藏、构筑、人机仍能使用，不停共享 API 服务。
8. 按上节检查离线卡图、缺图降级和资源更新后的旧回放。最后恢复网络设置、结束测试对局，保留两台自己的数据和身份，勿互换凭据。

每项填 `passed/failed/not_tested`、操作时间、可复现步骤和本地证据位置；截图不要含授权码或私有凭据。本次阶段已按用户确认收口，原物理设备门禁移为保留的补验任务；不要据此将未测项改成 passed。后续新发现的显示问题独立记录，部署切换另行安排。
