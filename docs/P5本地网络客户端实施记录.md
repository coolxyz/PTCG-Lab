## 2. 代码边界与版本

`packages/online-client` 从 P1 骨架推进到 `ptcg-online-client==0.5.0.dev1`。运行仅依赖共享协议 `ptcg-battle-protocol==0.2.0.dev1`、JSON Schema 校验和原生 WebSocket；不导入 online-server、battle-core、engine-provider、AI、SQLite 或图片库。`IMPLEMENTATION_READY=False` 表示尚未完成端到端产品接入，并非本包仍无实现。

- `transport.py`：固定 origin 的原生 HTTP/WSS、TLS、大小限制和错误归一化。
- `vault.py`：本地 profile 独占锁、私有凭据、待确认请求和快照/游标的原子存储。
- `client.py`：身份、能力协商、卡组/房间、控制权、提交、回执核对、事件与回放。
- `contracts.py`：共享对战 DTO 校验和服务 envelope 校验。

共享 DTO 仍直接来自协议包，不新建另一套 Command/MatchSnapshot。认证、房间与 match envelope 仍由 P4 服务定义；客户端安装包包含三个 schema 的逐字节快照。修改这些服务合同必须同步对应客户端快照，并通过字节一致性门禁；本轮服务端合同、运行代码和 P2-D 冻结核心均未修改。未来可在明确的合同迁移阶段抽成独立版本包。

## 3. 连接与凭据

仅接受小写 ASCII 的规范 origin，不接受用户名、路径、查询、片段和显式默认端口。HTTPS 为默认要求；显式测试选项只允许回环 HTTP。自定义 CA 在创建 `Server` 时读取并固定，profile key 由 origin 与 CA 内容摘要共同决定，避免改变 CA 文件后悄悄沿用原凭据。不同地址和信任配置使用不同凭据、控制权、待确认命令及游标。

原生请求不使用浏览器 Cookie、环境代理或自动跳转；WSS 在 Authorization header 中携带 access token。公开 `status()` 和游客创建返回值仅提供身份元数据，不返回 token。包内凭据对象不是安全沙箱：本地可信 Python 调用方能访问内部存储，P5-B 必须限定允许向浏览器返回的字段和路由。

当前实现采用 POSIX 权限文件：目录 `0700`、文件 `0600`，拒绝不安全权限和目录/凭据文件自身的符号链接。文件为明文，尚未接入系统钥匙串；Windows 缺少凭据后端时返回 `CREDENTIAL_BACKEND_UNAVAILABLE`。没有修改现有用户 SQLite。单 profile 用文件锁限制一个原生 owner，同进程用锁合并刷新；后续多窗口由本地后台协调，不能各自打开同一凭据目录。

refresh 是服务器严格的一次性轮换：先写 `refreshPending`，再发送一次刷新，成功后原子替换凭据。并发请求复用刷新结果。若回复丢失、进程退出或写盘失败，保留不确定标记；重启不会再次提交旧 refresh，返回 `REAUTHENTICATION_REQUIRED`。当前游客没有账号找回，不能自动新建游客冒充恢复原对局。显式忘记身份会清除该 profile 的局部状态；有待确认命令/控制请求时默认拒绝，调用方必须显式选择丢弃。P5-B 需将此结果清楚展示给用户。

## 4. 提交、恢复与私有视角

命令提交前将 matchId、原始命令、commandId、controllerId、controllerEpoch 和动作类型写入私有存储。临时文件写入、文件 fsync、原子替换及目录 fsync 完成后才允许网络发送。写盘失败使 owner 停用，不能继续使用内存中的未落盘状态。

每个 match 仅一个待确认命令，全 profile 至多八个。响应丢失后新命令被阻止；`recover()` 先查原回执，404 时只重发完全相同的请求。成功回执核对 matchId、commandId 和类型后才清除 journal。新提交得到明确不可重试的拒绝可直接结束；旧的不确定请求要么拿到回执，要么通过 `resolve_rejected()` 确认服务器序号/控制 epoch 已推进，并再次核对回执，才能解除。不把网络异常等同于未提交。

控制接管也保存原 requestId 和 controllerId，重试保持不变，成功后重新获取当前快照。卡组及房间写入在单次调用内使用稳定 requestId；跨调用或重启重试需调用方保存 `request_id`，目前没有自动持久化大厅操作 journal。

所有快照由服务器给出，客户端不交换 PLAYER1/PLAYER2 字段，也不调用本地规则或 AI。快照与 streamCursor 一起持久保存；最多缓存八局快照。序号或控制 epoch 过旧时拒绝覆盖缓存；HTTP 先到而 WSS 后到时重新订阅当前完整快照。viewerSeat/ruleReleaseId 不一致直接拒绝。游标过期后发送空游标申请完整快照；私有回放分页与当前身份、规则和对局核对。

## 5. 有界网络行为

| 项目 | 当前限制 |
| --- | --- |
| HTTP 请求 / 响应体 | 16 KiB / 2 MiB；只接受 JSON，不解压响应 |
| HTTP 超时 | socket I/O 超时 10 秒；不是整次请求的绝对时间上限 |
| GET 与显式幂等大厅/控制写入 | 至多三次常规尝试，指数退避加抖动；401 另允许一次刷新后的认证重试 |
| 429 | HTTP 不自动重试；调用方展示等待状态 |
| 身份创建 / refresh | 不做网络失败后的自动重试 |
| 对战命令 | 普通提交一次；认证拒绝可刷新后重试，不确定结果走原回执恢复 |
| WSS | 握手 15 秒、关闭 2 秒、消息 2 MiB、接收高低水位由 queue=8 配置；不启用压缩 |
| 流空闲 / 失败 | 40 秒无消息重连；每次故障最多三次连接失败，收到有效快照后计数重置 |
| 本地文件 | 单 profile 最大 8 MiB；不无限保存历史回放 |

这些限制约束资源使用，不是服务器容量指标。慢速持续响应的总时长限制、系统凭据库、Windows 后端和长周期控制记录清理仍需后续完善。GUI 集成须在后台线程消费同步客户端，不能阻塞本地 UI 或人机处理。

复现（私有真实输入需既有批准文件）：

```sh
PTCG_V2_REAL_INPUTS_FILE="$PWD/var/p4b/real-inputs.json" \
  var/p4a/venv/bin/python scripts/migration/p4a_postgres.py \
  --output var/p5a/acceptance-new --python var/p4a/venv/bin/python --suite client

  tests/migration tests/portable/test_public_export.py -q

  --build-output var/p5a/build-new --dependency-wheelhouse var/p4a/wheelhouse
node scripts/migration/p3_package_smoke.mjs var/p5a/build-new
```

输出目录必须是新路径；公共 CI 缺少私有真实输入时明确跳过该一项集成，不能将 skipped 报为真实规则验收通过。

客户端覆盖认证刷新合并、刷新回复丢失、写盘失败、命令回复丢失与重启、服务器隔离、过期游标、HTTP/WSS 交错、TLS 校验、拒绝跳转、响应限制及安装包独立性。真实集成使用已有批准规则包的只读路径、临时 PostgreSQL 和随机回环 HTTPS/WSS 端口：两位客户端提交卡组、邀请、准备、取得控制权、完成两次命令与认输、下载双方私有回放；第二次命令在服务器提交后丢弃响应，重启客户端后核对回执并验证数据库没有重复记录。

该集成不声称自然终局；P4-D 自然终局已有独立证据，本地 APP 的自然终局仍属于 P5-D。测试 helper 只回收自己创建的 PostgreSQL 容器、进程与凭据文件，未触及原局域网、人机或 AI 服务。

发布门禁加入客户端对服务/核心/AI/本地数据库导入的反例、服务 schema 同步检查、P5 完成状态防误报；wheel 在 checkout 外的独立解释器验证 schema 和私有存储，不启动服务或导入引擎。CI 运行合成和 TLS 客户端测试；私有规则集成仍需显式批准输入，公共 CI 不携带这些资产。
