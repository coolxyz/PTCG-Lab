# 上游卡库同步

应用提供“数据与对战更新”页面，默认跟踪原仓库 `duanxr/PTCG-CHS-Datasets` 的 `main` 分支。在“数据与对战更新”输入公开 GitHub HTTPS 仓库地址并保存，可选择相同数据格式的 fork。已有安装会沿用现有缓存的来源，不擅自切换；应用只读取仓库，不向远端写入。资料同步与对战效果发布分别验收，未知规则不会因为资料下载完成而获得对战资格。

当前批准卡表来源、数量与摘要见 [RELEASE.json](../RELEASE.json)。维护者应同步校验本机产品、共享核心、图片索引和人机环境绑定；资料同步成功不替代效果发布。

## 日常更新

1. 用户先按需要更新 GitHub 上的 fork。
2. 在应用打开“数据与对战更新”，点击“检查更新”。检查仅记录目标提交。
3. 首次使用建议先运行“迁移预演”，查看身份差异、版本数、冲突和待实现规则。
4. 点击“同步并适配”。应用固定提交，生成候选资料，校验引用和工作进程，备份用户数据库，然后切换活动资料版本。
5. 对有候选效果的批次点击“验证候选对战效果”，完成独立运行时的 1,000 局验证。完整后端和浏览器回归通过后，才能“验收并发布对战效果”。
6. 点击“刷新卡库视图”加载当前目录。未知机制会继续列为开发任务；“部分完成”不会被改写成整个卡包已经可对战。

图片现由共用本机缓存按需从 GitHub Raw 或配置的静态 HTTPS 图源/CDN 获取，校验 Git blob、摘要、格式、体积和像素数。资料库、人机和网络共用，默认 1 GiB LRU，失败按冷却重试；不会逐图请求 GitHub REST 图片接口，也不预取全库。图源/缓存设置与资料仓库配置分别保存，ZIP 离线导入及上传优先级保留。操作见[按需卡图](按需卡图与本地缓存.md)。`GET /api/sync/image-status/{commit}` 是已存在同步快照的统计；随包索引和共用在线缓存统计使用 `/api/sync/artwork/settings`，两者不是同一计数。

“分配收藏版本”将已有持有数量划分到具体上游版本。原有收藏首先保持为未分配，不猜测闪卡工艺；分配不会增加持有总量。减少总量前，先把对应版本的分配数量减下来。对战卡组仍按印刷身份和同名限制计算。

## 目录和版本

下表相对实际 `SYNC_HOME`。桌面为 profile 的 `app.sync`；源码默认 `.catalog/sync`，自定义数据库未指定环境变量时为数据库同名 `.sync`；CLI 要显式传 `--home`/`--database`，不会自动读取服务环境。

| 路径 | 内容 |
| --- | --- |
| `.catalog/upstream/repo-<仓库摘要>` | HTTPS Git 对象元数据缓存，不是需要系统 Git 的工作区 |
| `snapshots` / `results` | 固定提交、标准化、身份映射、图片索引与机制任务 |
| `jobs.sqlite` / `verifications` | 批次、租约、发布与规则验证证据 |
| `releases` / `current.json` | 不可变发布归档及唯一当前发布指针 |
| `identity-archive.json` | 历史身份的显示信息，不授予旧规则执行资格 |
| `artwork` / `artwork-settings.json` | Raw/CDN 共用在线缓存、索引与额度/来源设置 |
| `images` | 既有同步图片缓存，仍校验并复用有效文件 |
| `display` | 已安装展示 ZIP、激活指针与内容对象 |
| `backups` | 同步发布前生成的备份；不是原生整套安装事务 |

资料同步默认 HTTPSource，通过 HTTPS 读取固定提交/树/文件并核对对象哈希，不依赖外部 Git。旧 GitSource/开发工具仍可显式使用，不作为 App 日常入口。

只执行当前批准发布；更新后不再符合规则或执行身份的旧局仅可查看已保存帧。回退必须是明确的配套发布/整套安装操作，不能按对局挑选历史 worker，也不改写旧摘要强行恢复。未经批准的候选不能经回退入口激活。见[单一当前规则](架构与维护.md)。

保留被历史展示/备份引用的归档，不自行清理身份资料。在线 artwork 缓存才有容量淘汰；不把完整规则归档、ZIP 或上传图片当作在线缓存删除。

## 命令行

以下命令在项目根目录执行。macOS 或 Linux 使用相应 Python 虚拟环境路径。

```powershell
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py check
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py plan
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py sync
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py status
```

指定 `--commit` 可使用已缓存的完整 40 位 SHA。`plan` 不切换正式目录；`sync` 在资料校验通过后应用更新。`--home` 和 `--database` 可把迁移演练放在独立目录与数据库中。

```powershell
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py build-battle --job <批次ID>
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py verify-battle --job <批次ID> --games 1000 --workers 4
.venv/Scripts/python.exe -X utf8 scripts/sync/regression.py
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py publish-battle --job <批次ID>
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py rollback --release <发布ID>
```

本机未安装 Playwright 自带浏览器时，可先设置 `PTCG_BROWSER_PATH` 为已经安装的 Chrome 或 Edge 可执行文件。完整回归脚本在运行前记录代码输入，后续修改会使旧回归证据失效。小于 1,000 局的验证仅用于调试，不满足发布门槛。

失败或中断的批次可从页面重试。输入变化时应创建新批次，避免把旧预演结果当成新实现的证据。CLI 的 `resume --job <批次ID>` 适用于未取消的中断批次。

## 新机制开发

`GET /api/sync/jobs/{id}/tasks` 返回完整 JSON 任务包，包括来源卡号、原文、规则指纹、涉及身份、环境和测试要求。当前按完整卡面规则合并，复杂规则的进一步机制拆分需要开发者审核。

确定性编译器目前接受普通基础宝可梦的完整费用与固定伤害，以及已经实现的自身回复和特殊状态恢复组合。遇到其余文本、未知规则字段、未知费用枚举或身份冲突时保留待办。

开发者在本地实现引擎效果、可观察 DTO 和 A1 行为，并增加费用、目标、失败行为、结算顺序、新旧卡交互及隐藏信息测试。使用现有注册表流程维护 `data/simulation/effects.json`；在 `data/sync/implementations.json` 中登记对应卡牌：

```json
{
  "schema": 1,
  "cards": {
    "上游卡牌ID": {
      "ruleHash": "任务对应的完整规则哈希",
      "effectKey": "已注册的本地效果ID",
      "engineLine": "注册表可识别的引擎卡牌行",
      "testFiles": ["tests/cardpool/具体机制测试.py"]
    }
  }
}
```

该文件只连接本地实现和源规则，不是跳过验收的白名单。重新预演后生成 C 类候选，再构建冻结运行时、运行定向与完整回归、完成版本绑定的 1,000 局验证，最后发布。原文规则指纹改变时旧登记不再生效。

显示层修正在 `data/sync/overrides.json` 中维护，使用 `baseHash` 检测陈旧补丁；它不能设置对战支持标志。明确身份映射使用 `data/sync/mappings.json`，不要直接改上游缓存。

## 备份与恢复

### 备份范围与离线卡图

日常图片无需 `cache-source` 或全库 Git 缓存。需要离线图片时使用已缓存的在线卡图、按范围制作的展示 ZIP 或个人上传；制作方式见[Git 工具](Git卡图下载与资源包工具.md)。开发 CLI 的 `cache-source` 会显式读取上游全部对象，存在 2 GiB 预算和 API 限流，不作为面向用户的推荐入口，也不代表生成了可导入 ZIP 或在线缓存。

下方 `sync backup/restore` 是已有的同步迁移工具，保存用户 SQLite、上传图、发布/快照/结果和既有 images 缓存；**不会自动包含新增 artwork 缓存/设置、display ZIP、独立网络身份或系统 Keychain**。要完整保留新资源和离线状态，先关闭目标后台，再备份整个实际 profile/数据库配套目录及独立在线目录；原生升级优先用 [C3 受控整套备份](安装升级与迁移.md)。不要把局部 ZIP 写成完整 App/身份备份。

```powershell
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py backup --bundle exports/sync-backup.zip
.venv/Scripts/python.exe -X utf8 scripts/sync/run.py restore --bundle exports/sync-backup.zip --destination exports/restored
```

恢复目录必须不存在。备份包含上述同步工具明确覆盖的数据库、上传图片和归档；读取 SQLite 使用一致性备份。恢复前验证归档文件和哈希，恢复后再次核验 release 清单。

用返回的数据库路径设置 `PTCG_DB`，同步目录设置 `PTCG_SYNC_HOME`，再启动源码项目。它不包含 Python/Node 环境及前述新增资源和在线身份；完整跨机迁移见[使用手册](启动使用与跨系统迁移.md#备份恢复与升级)。只有当前批准规则可执行。

## 仓库配置

资料仓库设置存于实际 `SYNC_HOME/repository.json`，不提交 Git。不同仓库使用隔离缓存。已创建任务固定其来源，切换设置后重试旧任务仍读取旧来源；已有图片按原快照来源读取。更新任务运行或排队时禁止切换。仓库必须提供 `main` 分支及兼容的 `ptcg_chs_infos.json`，当前不接受 SSH、本地路径、令牌、任意服务器或 URL 查询参数。保存地址不自动下载或发布；建议先迁移预演。

## 完整回归的平台选择

`PTCG_REGRESSION_WORKERS` 可将完整后端分区并发限制为 1–8，默认 2，不减少测试。`PTCG_TEST_PYTHON` 可为浏览器验证明确指定测试解释器。macOS 上需要执行 RLIMIT_AS 仿真合同的完整门禁时，设置 `PTCG_REGRESSION_SIMULATION_IMAGE` 为已安装依赖的本机 Linux 测试镜像；驱动固定其 imageId，以只读源码、无网络、1 CPU/2 GiB 临时容器运行两个仿真分区，其余分区和浏览器仍在本机运行。该配置不启动或修改在线服务；平台和分区写入回归输入清单。
