# P5.5 对局信息展示设计与实现

日期：2026-10-26。适用：PTCG-Lab 完整产品的网络对战、共享对战界面及私有回放。

## 目标与规则依据

对手操作后，玩家应能确认“用了什么、展示了什么、结算后有什么变化”，而不是只看到手牌数量变化或一瞬即逝的动画。信息需要可回看、可展开卡牌，并且不因后台通信抢走阅读位置。

官方《竞争用场地规则》Ver.1.2 第 2 章要求清楚声明招式和效果、对方作出回应，并禁止在没有卡牌指示时查看对手手牌或牌库。该文件适用于其指定赛事；这里参考其沟通和信息边界，不将本 APP 认定为官方赛事裁判系统。来源：[官方规则 PDF，2026-01-30，第 3 页](https://www.pokemon-card.com/assets/document/rules/floor-rule_20260130.pdf)。具体效果是否展示、展示哪些卡，仍由当前支持卡牌的效果实现和已授权投影决定。

“已阅”是本产品的阅读标记，不是规则结算的批准，也不暂停对手或替代合法操作；避免把每个普通动作变成需要双方点击的弹窗。

## 信息边界

| 情况 | 双方记录中展示 | 不展示或不推断 |
| --- | --- | --- |
| 从手牌打出宝可梦、进化、附能、物品、支援者、道具、竞技场 | 已接受动作、打出的卡、公开目标 | 其他手牌及手牌下标 |
| 招式、特性、撤退、竞技场效果 | 动作、公开来源/目标、已知招式或特性名 | 未选择的操作及候选列表 |
| 卡牌效果要求展示检索结果 | 规则输出 `publicReveals` 中本次新增的卡 | 被浏览但没有要求展示的牌库内容 |
| 普通抽牌、私人查看或排列牌库 | 已确认的数量变化；选择步骤使用通用描述 | 抽到的牌、私人检索结果、牌库顺序 |
| 效果要求展示手牌 | 当时公开的卡牌记录 | 不把历史展示当作当前手牌追踪 |
| 开局准备、重抽 | 通用准备步骤；规则公开的重抽手牌 | 尚未公开的开局放置卡 |
| 弃牌区、放逐区和场上变化 | 相邻帧中新增/移出的公开卡及数量 | 不把“进入弃牌区”自动认定为“使用了该卡” |
| 结算结果 | 可核对的 HP、特殊状态、能量/道具、数量、使用限制变化及公开投币结果 | 不根据 HP 差值编造伤害来源或完整计算公式 |
| 对局结束 | 权威终局状态、已记录的动作和结果，进入私有回放 | 不补出从未保存的动作 |

已展示的历史卡牌是历史事实。卡牌详情明确提示“不代表它仍在原区域或当前手牌中”。当卡牌转移、洗牌或公开记录补齐时，不推导新的隐藏信息。场上位置改变或无法区分同名实例时，宁可不归因 HP 变化，也不把替换后的宝可梦当作原来的对象。

## UI 与交互

右侧原裁定记录升级为 **对局信息**，保留“裁定记录”提示，便于已有用户找到入口。对手的步骤使用暖棕色边线，自己和系统步骤使用绿色系；角色、回合和步骤编号同时用文字表达。

每条记录按以下层次展开：

1. **动作标题**：例如“对手 · 使用物品 · 某卡”，或者“使用招式 · 某宝可梦 · 某招式”。服务器动作与效果后续选择可能是不同步骤，不强行合并为一个未经验证的因果链。
2. **使用 / 涉及的卡牌**：已公开来源和目标，可点卡图或名称打开详情。
3. **公开展示**：单独标注“按效果展示卡牌”“展示手牌”或“重抽前展示的手牌”，区别于弃牌区新增。
4. **投币与可见变化**：逐枚正反面；HP 前后值、状态、手牌/牌库/奖赏数量、场地与使用限制变化。

交互约定：

- 最新步骤在上，默认展开；历史步骤可独立展开/收起。
- 可筛选全部、本回合、对手动作、涉及公开卡牌。回合取动作前的已知回合，缺少前帧时不猜测动作属于哪个回合。
- 滚动阅读、展开记录或查看卡牌会暂停跟随，保留已展开内容。后来收到步骤只显示“n 条新记录 · 查看最新”。继续查看旧卡牌不会偷偷推进阅读截止位置。
- “本回合”筛选在暂停期间固定到暂停时的回合；点击“跟随最新”后恢复最新回合和列表顶部。
- “已阅 n 条”只修改当前组件内的阅读状态，不发送 API，不阻塞规则计算。新窗口/重新进入不承诺保留阅读状态。
- 卡牌详情使用可键盘关闭的原生模态框，Escape 关闭后回到原按钮；全屏下仍处于当前对战界面。
- 列表只有一个纵向滚动容器，预留滚动条空间；桌面侧栏 340px，窄屏排在牌桌与操作面板之后。后台到达通知使用小范围 `aria-live`，不反复朗读整份记录。
- 实时面板保留最近 200 条，完整历史通过回放查看。回放只传入当前游标之前的帧，不泄露后续步骤。

## 数据链路与兼容

### API v2

`ptcg-online-server==0.4.0.dev6` 补齐既有 `VisibleEvent`，没有增加接口、修改协议 Schema、规则身份或数据库结构。

1. 规则 worker 在命令成功后，从操作者命令前的授权视图解析实际选择的动作。
2. 仅允许明确公开的动作类型提取打出的手牌身份；目标限于场上公开区域。开局和私人选择仅输出通用描述，未知动作不放宽权限。
3. 卡牌字段只选印刷身份、招式及特性，不直接复制决策、隐藏引用、恢复对象或规则诊断文本。投币仅接受引擎两个完全匹配的公开消息；读取适配器内部信息集中在 worker 边界，后续引擎适配需要保持该约定或改用正式事件端口。
4. 两个座位获得相同公开动作声明，各自局面与私人决策仍分别投影。API 将事件步骤号设为提交后的 `matchSeq`，由现有 Schema 校验，并与回执、快照和推送一起原子提交。
5. 重试命中同一回执，不重复写事件；回放读取已持久化帧，不重新执行规则。

`publicReveals` 和开局展示沿用共享核心已经授权的记录。此轮不新增卡牌裁定；某个未支持效果没有产生公开事件时，不通过客户端猜测补齐。

### 客户端与共享界面

`online/history.ts` 汇总当前步骤的全部事件，以相邻授权帧补充公开变化，并对累积展示记录取新增部分。记录按步骤去重；有缺帧时不跨步计算变化，补回的公开卡标为“此前已公开，具体步骤待补齐”。后续恢复完整帧后重新计算。

显示目录负责中文名称、同一张卡的招式对应和本机卡图；没有可靠映射时保留原文。卡图依然从本机 APP 提供，远端 API 不传图片。名称替换缓存按显示目录对象隔离，避免每条记录重新构建全部卡名匹配规则。

`BattleLog` 是无网络和持久存储能力的共享 UI。人机练习适配器也提供已公开动作卡和展示分组；未改动 AI 决策实现。纯展示辅助函数通过 `@ptcg/battle-ui/presentation` 导出，供无浏览器的控制器验证使用。

### 旧服务和旧回放

新版客户端可以连接旧 API。旧帧缺少 `events` 时以具体公开结果作为标题，并明确说明动作声明未保存；只展示已知公开变化。不能从弃牌、数量或最终局面还原原本没有记录的操作。

要让后续网络操作显示完整动作声明，需要同时更新前端和 API dev5。此轮只构建新镜像并在独立数据库验收，没有重启当前局域网 API v2、v1 或原项目服务。不要在仍有未完成对局时替换运行实例；应在对局结束后的维护窗口使用现有配置更新，保留数据库、规则资产和身份。升级前的旧帧不会被追写或重算。

## 标题优化（2026-10-26）

记录折叠后，标题也应能说明本步发生了什么。标题按以下顺序选择：

1. 服务端明确记录的动作声明，保留卡牌、特性和招式名称，并按显示目录翻译。例如“使用物品 · 某卡”“使用特性 · 某宝可梦 · 某特性”。多个明确声明保留顺序。
2. 对只有通用声明或没有动作声明的记录，从相邻授权帧生成结果摘要，优先展示效果要求公开的卡牌，其次是 HP/状态、场上卡牌、弃牌区/放逐区等变化。例如“对手 · 按效果展示卡牌：某卡”“对手弃牌区新增：某卡”“你的战斗区 · 某宝可梦 HP：90 → 30”。没有其他结果时显示投币或数量变化。
3. 信息不足时显示“已完成选牌”“已完成效果选项选择”或“动作详情未记录”（用语已由下述审计修订）；缺帧时显示“恢复对局记录 · 第 n 步”，避免把历史展示错算到当前步骤。开局、终局有独立标题。

卡牌标题最多展开两个名字，其余用“等 n 张”表示，完整列表仍可展开。旧记录不能可靠知道具体使用了哪张卡或哪个特性时，只描述公开结果，不从弃牌、HP 或手牌变化猜测动作。实时记录和回放使用同一个标题逻辑。

此次标题优化只修改客户端，无需重启 API 即可让旧服务记录显示具体结果；准确的动作/特性名称仍依赖 dev5 服务保存的事件。新增标题与中文特性映射验证，以及旧记录折叠标题的浏览器用例。

标题优化验证：控制器与历史测试 6 项、浏览器回归 16 项通过；完整产品前端构建和发布边界门禁通过。新版客户端包为 `var/p55titles/PTCG-Lab-P55-information-titles.zip`，服务端沿用已验收的 dev5 镜像。


## “无新增公开结果”审计与补齐（2026-10-26）

### 实际进入通用标题的情况

通用标题不是一种规则结果。此前，任何没有明确动作声明、且没有命中客户端差分字段的步骤，都可能显示“无新增公开结果”；这不能说明没有发动效果、检索失败或选择了零张。

| 操作或阶段 | 原因/现状 | 当前显示与处理 |
| --- | --- | --- |
| 发动竞技场效果 | dev5 已支持 `UseStadiumAction`；即使局面没有变化，也应有动作声明。旧 LAN 服务未部署该版本时没有这一事件 | “使用竞技场效果 · 卡名”；本轮增加直接回归验证 |
| 竞技场效果后续选牌 | `selection` 过去仅记录通用选择文本 | dev6 核实真实提示来源是场上竞技场对象后，显示“竞技场效果 · 卡名 · 完成选牌” |
| 场上宝可梦/公开弃牌区卡牌引起的选牌 | 同上；不能直接信任私人决策的 `sourceId` 或名字 | 核实同一公开对象后显示“卡牌效果 · 卡名 · 完成选牌”；不宣称整段效果已经结算完毕 |
| 使用特性、招式、撤退、结束回合、移除竞技场 | 已有明确动作类型，即使等待下一阶段或没有局面变化，也应显示声明 | 保留动作和来源；新增不依赖局面差分的测试。使用特性保留已记录特性名 |
| 放置宝可梦、进化、附能、支援者、物品、道具、放置竞技场 | 七类手牌动作已经在接受命令后声明实际使用的卡 | 沿用现有记录，其他手牌不公开 |
| 特性已使用/重置、特性无效 | 公开 DTO 已有标记，但旧摘要没有比较 | 新增“特性使用标记：已使用/已重置”“特性无效标记：生效/已清除”；不据标记猜是哪一个特性 |
| 撤退/攻击限制、招式加减伤、保护、反击、中毒伤害、回复效果、受限招式 | 公开字段已存在，旧摘要遗漏 | 新增对应变化。展示当前效果参数，不冒充已实际结算的伤害或治疗量 |
| HP 上限、属性、备战容量、奖赏卡翻面公开 | 旧摘要遗漏 | 新增上限、属性、容量及已公开的奖赏卡；移除公开展示记录时，不推断卡牌去向 |
| 换回合 | 旧摘要依赖 `visualEffects` | 相邻授权帧的回合/行动方变化也能生成换回合记录 |
| 数值/模式/可选触发顺序 `NumberOption` | 该类型混合了公开模式、私人触发名称、排序/猜测等情况，没有统一可见性标记 | 有公开结果时显示结果，否则“已完成效果选项选择”。不直接转发原始 label/value，也不把它归给上一张使用的卡 |
| 私人检索、排序、逐次选牌、来源不在公开区域 | 选项与候选只授权给操作者；某些效果还未产生公共局面变化 | “已完成选牌”并说明未记录更多公开信息；不显示选择的私有卡名/数量/顺序 |
| 未识别的命令类型 | 不能保证未知类型的数据可公开 | “已完成对局操作”，仍展示已确认结果；没有宽泛复制原始命令 |
| 旧帧没有动作事件，或断线缺帧 | 服务端未曾记录，或历史尚未补齐 | 有相邻公开变化则生成具体摘要，否则“动作详情未记录”/“恢复对局记录”；不伪造竞技场发动记录 |

### 来源核实与兼容边界

`selection_source_ref` 在提交前将引擎提示的实际来源对象与两个座位的战斗区、备战区、弃牌区和公共竞技场逐一作对象身份比对，再取该视图中的引用。仅同名或同印刷 ID 不足以证明来源公开，测试覆盖隐藏区域有同名副本的情况。提交成功后仅写印刷身份，不输出候选、选择引用或引擎提示文本。该处理没有修改核心规则、协议 Schema 或规则版本。

新增的状态差分仍要求连续帧和可比的场上阵容。换位、替换或同名实例不能确认时不强行归因。客户端直接比较已授权的公开字段；没有读取对手的私人决策。

新版通用正文为“本步骤未记录其他公开变化”，并在通用效果步骤补充“不能据此判断效果未发生或未找到目标”。这比“没有结果”准确。

对 `NumberOption` 的具体选择、自动/可选触发的特性名、来源不在公共区域但规则要求宣告的效果，还需要核心提供明确的公开事件上下文，才能可靠细化。当前没有通过读取私人标签或沿用上一动作来源来假装覆盖这些情况。

当前网络实现使用 dev6；人机练习继续使用自己的既有动作日志，尚未接入本轮 worker 的选牌来源解析。共享面板的正文表述对两种模式生效。

新服务器镜像：`ptcg-lab-online-api:p55-action-details`（API `0.4.0.dev6`）。当前 LAN 实例未替换；要看到后续选牌的竞技场来源，需要更新 API 和客户端。旧帧不会回填缺失信息。
