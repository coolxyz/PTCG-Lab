## 产品范围与运行条件

这是运行在自己电脑上的网页应用，用于简中卡牌查询、收藏管理、卡组构筑和人机练习。浏览器只是界面，Python 服务和本地数据库负责保存资料；关闭终端会停止服务。默认仅监听本机 `127.0.0.1`，没有在线账号、云同步或互联网多人对战入口。

对战卡池由本地规则配置和效果实现决定。同步新的卡牌资料不会自动获得对战支持，具体可用性以应用中的校验结果为准。

源码包含应用代码、规则配置、工具和文档。`data/`、`runtime/engine/` 和引擎完整性清单需另行导入；`.venv/`、`apps/web/node_modules/` 与 `apps/web/dist/` 由安装脚本生成。个人数据和上游卡图由本地维护。A1 用于人机练习，A2 为实验搜索原型。

安装前准备：

| 项目 | 要求与用途 |
| --- | --- |
| Python | 3.14 或更新版本；安装脚本会检查 |
| Node.js / npm | 安装和构建网页；npm 应可直接调用 |
| Git | 下载上游资料和卡图；需能在终端运行 `git` |
| 浏览器 | 建议使用较新的 Edge 或 Chrome；需支持网页对话框与本地存储 |
| 网络 | 首次安装访问 Python/npm 依赖源；卡库和卡图下载访问配置的 GitHub 仓库 |
| 磁盘 | 使用可写目录；全量卡图会占用数 GB，备份、缓存和多次发布还会增加占用 |

## 获取源码与准备本地资产

首次获取源码：

```bash
git clone https://github.com/coolxyz/PTCG-Lab.git
cd PTCG-Lab
```

已在源码目录中时跳过克隆。接下来，从自己有权使用的可信、兼容完整环境导入本地资产。导入只复制 `data/`、`runtime/engine/` 和 `artifacts/engine/overlay-hashes.json`，不会携带个人收藏、对局或上游图片缓存。

macOS / Linux（将示例路径替换为实际目录）：

```bash
python3 scripts/public/import_local_assets.py /path/to/trusted-private-project
```

Windows PowerShell：

```powershell
python -X utf8 scripts/public/import_local_assets.py 'D:\Apps\trusted-private-project'
```

导入要求来源中的三项资产全部存在，目标三项资产均不存在；已有部分文件时会拒绝覆盖。成功后再执行下方安装步骤。当前没有从公开源码自动生成完整对战卡池的入口，下载上游 JSON 或卡图不能代替这些运行资产。

### 使用已有完整安装包

如果另行持有可信的完整安装包，可解压到独立目录，并在首次修改前核对其 SHA-256 和包内清单。完整包包含 `RELEASE-FILES.json`，在其根目录执行：

```bash
python3 scripts/release.py verify
```

Windows 将 `python3` 替换为 `python`。GitHub 克隆、GitHub 自动生成的源码压缩包和公开源码导出包不包含这份清单，不适用 `release.py verify`。`PUBLIC-SOURCE.json` 是源码导出清单，不能替代完整安装包的校验清单。

## Windows 安装

先安装 Python 3.14+、Node.js/npm 和 Git，并加入 PATH。重新打开 PowerShell，在已准备资产的项目根目录检查工具：

```powershell
python --version
node --version
npm.cmd --version
git --version
.\start.ps1 -Setup -Check
.\start.ps1
```

`-Setup -Check` 创建 `.venv`，安装锁定 Python 依赖，执行 `npm ci`、网页构建和运行检查；通过后再启动服务。终端保持打开，在浏览器访问 `http://127.0.0.1:8765/`。

若 PowerShell 阻止执行脚本，可仅对这一次调用放行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Setup -Check
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

若默认 `python` 不是需要的版本，指定真实安装路径，例如：

```powershell
.\start.ps1 -Setup -Check -Python 'C:\Python314\python.exe'
```

## macOS / Linux 安装

先安装 Python 3.14+、Node.js/npm 和 Git。Linux 还需确保对应解释器的 `venv` / pip 可用；系统默认 Python 不一定满足要求。macOS 的 Terminal 默认可用 zsh，以下启动命令仍通过 Bash 执行。

在已准备资产的项目根目录执行：

```bash
python3 --version
node --version
npm --version
git --version
bash start.sh --setup --check
bash start.sh
```

若使用独立安装的 Python：

```bash
PYTHON=python3.14 bash start.sh --setup --check
bash start.sh
```

安装脚本生成当前平台的依赖环境并构建网页。检查通过后访问 `http://127.0.0.1:8765/`。通过 `bash start.sh` 启动不要求额外执行 `chmod`。跨系统迁移时应重新安装依赖，不要复制 `.venv` 或 `node_modules` 使用。

## 第一次使用与日常启动

首次安装成功后，建议按下面的顺序熟悉应用：

1. 准备卡图源缓存（下一节“按需获取卡图”）。
2. 在卡牌库搜索一张卡，查看中文规则、扩充包和卡面版本。
3. 在详情中登记一张持有卡，进入“我的收藏”确认结果。
4. 在卡组页面从预组创建卡组，保存一个可对战版本。
5. 进入“人机练习”，选择该版本、AI 卡组及 A1，开始练习。

以后启动无需重复安装：

| 操作 | Windows PowerShell | macOS / Linux |
| --- | --- | --- |
| 启动 | `.\start.ps1` | `bash start.sh` |
| 仅检查环境 | `.\start.ps1 -Check` | `bash start.sh --check` |
| 改用 8766 端口 | `.\start.ps1 -Port 8766` | `bash start.sh --port 8766` |
| 安装但只做检查 | `.\start.ps1 -Setup -Check` | `bash start.sh --setup --check` |

在服务终端按 Ctrl+C 停止。端口改变后访问对应地址，例如 `http://127.0.0.1:8766/`。重复启动不会替你关闭已有服务。日常启动不重装依赖、不清空数据库。浏览器建议一直使用同一配置文件和 `127.0.0.1` 地址，避免因为换成 `localhost` 或清除 Cookie 而看不到原对局身份。

## 下载上游资料和卡图

### 先理解三种数据

- **卡牌资料**：名称、编号、规则文字、商品关系等；由兼容的本地资产或完整安装包提供。准备这些资产后再使用同步功能更新资料。
- **原始卡图**：位于上游 Git 仓库，默认不全部打包；可以按需下载，也可完整缓存后离线使用。
- **对战效果**：本地程序实现并验收的规则逻辑。下载资料或图片都不等于实现新规则。

原仓库为 `https://github.com/duanxr/PTCG-CHS-Datasets`。在“数据与对战更新”输入公开 GitHub HTTPS 仓库地址并点击“保存仓库地址”，随后检查更新或迁移预演。新安装默认原仓库；已有安装保留原来的 fork 配置。当前同步 `main` 分支，不接受包含凭据的 URL。fork 需由其维护者更新，应用只读取资料。

### 按需获取卡图（建议首次使用）

完成安装后，在项目根目录另开终端执行：

Windows：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/release.py fetch-images
```

macOS / Linux：

```bash
.venv/bin/python -X utf8 scripts/release.py fetch-images
```

此命令读取 `RELEASE.json` 中的固定上游提交，初始化所选仓库对应的 `.catalog/upstream/` 隔离缓存，准备按需获取的 Git 缓存。输出 `Pinned image source ready` 表示源缓存已准备好，**不表示已下载全部图片**。之后打开卡牌或版本预览时，应用读取相应图片对象，验证后存入 `.catalog/sync/images`。首次显示可能较慢；联网失败时保留错误信息，恢复网络后重试命令或重新打开卡图。

`fetch-images` 使用项目默认 `.catalog/sync` 中的仓库设置，不读取 `PTCG_SYNC_HOME`。若服务使用自定义同步目录且资料来源不同，应使用 `scripts/sync/run.py cache-source --home 实际同步目录 --database 实际数据库路径 --commit 完整提交号` 准备对应来源缓存。

该命令不会更新活动卡库，也不会改变对战支持。安装完成且需要的卡图均已缓存后，相应日常功能可离线使用；尚未下载的图片仍需要联网。

### 一次下载全部卡图（离线使用）

下列命令使用 `RELEASE.json` 中的基线提交。先执行上面的 `fetch-images`，再读取提交号；所配置的资料仓库必须包含该提交。

Windows：

```powershell
$cardCommit = (Get-Content .\RELEASE.json -Raw | ConvertFrom-Json).upstreamCommit
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py cache-source --commit $cardCommit
```

macOS / Linux：

```bash
card_commit=$(.venv/bin/python -c 'import json; print(json.load(open("RELEASE.json"))["upstreamCommit"])')
.venv/bin/python -X utf8 scripts/sync/run.py cache-source --commit "$card_commit"
```

这是整个固定提交的来源文件缓存，不只下载当前页面；可能耗时较长并占用数 GB。返回 `missing: 0` 和 `mode: local-git-objects` 表示该提交的对象已完整下载。首次显示仍需解码校验，但无需再次联网获取对象。中断后可以重跑相同命令。

完成应用内更新后，如需缓存新卡库，使用该更新批次的完整 40 位 `commit`（命令行 `status` 可查看），不要继续使用安装包的旧提交号。不同提交可同时保留。

可在浏览器访问 `http://127.0.0.1:8765/api/sync/image-status/完整40位提交号` 查看图片缓存状态。这里的计数是已校验的图片缓存数量，与 Git 已下载对象数量不同，不能据此判断全量源缓存是否完成。

### 更新到上游新资料

1. 在“数据与对战更新”点“检查更新”，确认目标提交。
2. 点“迁移预演”，先阅读新增身份、收藏版本、冲突、待核验和待实现数量。预演不切换正式卡库。
3. 点“同步并适配”。资料校验通过后会备份并发布资料版本；页面轮询显示批次进度。
4. 完成后点“刷新卡库视图”。若显示“资料已发布 · 对战适配未全部完成”，资料可查看，但新机制尚不可用于对战。
5. 有可复用或已实现的候选效果时，由维护者执行候选验证、完整回归和对战发布；普通用户无需为使用已配置的卡池重复这一步。

“重试”处理失败批次；“取消”停止当前任务；“查看待实现机制”展示开发任务。发布历史中的“回滚到此版本”只切换卡库/运行时，不恢复以前的收藏数量。不要手动修改发布指针或删除 release 目录。

命令行也可执行同一流程（macOS / Linux 将解释器替换为 `.venv/bin/python`）：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py check
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py plan
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py sync
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py status
```

这些命令访问上游，`sync` 会正式应用通过校验的资料。CLI 默认使用项目内的 `var/app.sqlite` 和 `.catalog/sync`；使用自定义数据库或同步目录时，必须显式传入 `--database` 和 `--home`，具体示例见下方备份说明。固定提交预演可以使用 `plan --commit 完整40位SHA`。开发者验收流程见 [上游卡库同步](上游卡库同步.md)。

## 卡牌库与图片

- 搜索名称、英文别名或卡牌编号；可结合系列、扩充包、属性、持有情况和卡图状态筛选。扩充包选项显示“名称 · 实际扩充包编号 · 卡数”，不会以内部 `chs-product` ID 代替编号。
- “系列”偏向印刷编号系列，“扩充包”按商品关系筛选；同一印刷身份可能属于多个商品。没有结果时先清除筛选。
- 页面顶部和底部都有分页入口。打开卡牌详情后关闭，应回到主页面原来的滚动位置。
- 详情展示卡牌身份、规则资料、效果支持、卡图及收藏。资料收录、规则审核和可对战是不同状态，以效果支持和组牌校验结果为准。
- 主图与“卡面版本与收藏”中的卡图均可点击放大，直接在当前页查看；按 Esc、点关闭按钮或背景可退出预览。卡图来源链接仍用于访问来源网站。
- 简中与繁中替代图会有标记；展示替代图片不会改变简中卡牌身份。

缺图处理：先确认已准备上游缓存和网络，再查看“卡图状态”筛选及“导出缺失卡图清单”。如来源确实缺图，在卡牌详情的“补充卡图”选择 JPG、PNG 或 WebP（最大 8 MB），检查预览后点“保存卡图”。上传仅保存在本机，点击“恢复默认卡图”撤销自定义展示。

当前上传功能针对这张印刷卡的默认展示图，不是逐个普通/精灵球/大师球卡面上传工具；它不会改写上游图片或规则说明。请核对名称、编号与版本后再上传。

## 收藏与卡面版本

“我的收藏”显示已登记的持有情况，可以搜索、管理品相、数量、备注及想要收集的卡牌。详情中的品相包括“未标注”“全新”“良好”“使用痕迹”。修改完成后按对应保存按钮，列表会同步更新。

同一卡号不同工艺作为不同收藏版本管理。151C 的显示顺序为 **普通版 → 精灵球版 → 大师球版**。`CHS:数字` 标识具体上游卡面；如 `CN:151C:002` 则标识聚合后的印刷身份，不要将二者当成同一种编号。

两种操作的含义：

| 按钮 | 用途 | 对总量的影响 |
| --- | --- | --- |
| 保存卡面数量 | 设置该品相下这一卡面的实际持有数量 | 相应增减总量 |
| 分配已有收藏 | 将以前只登记总量的卡，划分到具体卡面 | 总量不变 |

例如已登记 5 张、全部未分配：把普通版数量填 3 并“分配已有收藏”，再把精灵球版填 2 并分配，仍共 5 张。如果此时新买 1 张精灵球版，将该版本数量改为 3 并“保存卡面数量”，总量变成 6 张。输入的是该版本的最终数量，不是这次新增的数量。

不能将总量减到已分配数量以下。先减少相应卡面持有量或调整分配。出现“收藏已变化”时重新读取当前状态后再保存，避免多个页面同时覆盖修改。

“数据与对战更新 → 分配收藏版本”也能整理已有分配；此处数量输入失焦时保存。收藏工艺不增加卡组的同名限额，也不改变对战效果。

## 导入与导出

“我的收藏 → 导出 CSV”用于导出收藏清单；它不是包括图片、卡组、比赛的完整备份。建议先导出一份作为自己后续整理表格的格式模板。

收藏或卡组导入均支持选择 CSV/TXT（界面限 200 KB）或粘贴文本。推荐 UTF-8 编码，并使用应用认可的印刷身份：

```csv
printingId,quantity
CN:151C:001,2
CN:151C:002,1
```

也支持“数量 卡名 系列 编号”格式，例如：

```text
2 妙蛙种子 151C 001
1 妙蛙草 151C 002
```

操作步骤：粘贴或选文件 → “解析并预览” → 处理无法识别、同名多版本等项目 → 核对总张数与版本 → “确认导入”。不要跳过歧义确认。

收藏导入按数量增加；同一批次重复提交不会再次增加。之前只含总量的导入应随后分配卡面版本，不能自动推断普通/闪卡。可在“导入记录”查看批次并按界面允许的状态撤销；若后来已作其他修改而撤销被拒绝，应按当前实际持有量调整。

卡组导入会替换当前草稿，确认前先保存需要保留的构筑。收藏清单中的持有数量不一定符合卡组规则，不能直接当成合法 60 张卡组。

## 卡组构筑与管理

1. 打开卡组页面，从预组创建一副卡组，或新建/导入自己的构筑。
2. 在编辑器搜索卡牌并加入构筑，调整数量，填写名称。右侧显示总张数、类别分布、校验问题和缺卡清单。
3. 对照每条问题的说明及建议修正：例如张数、同名限制、环境合法性和效果支持。界面提供的校验结果是能否开始对战的依据。
4. 保存构筑版本；对战选择的是已保存版本，未保存草稿的修改不会自动进入已有对局。
5. 缺卡计算可选“按指定印刷版本”或“接受已审核规则等价版本”。它用于对照实物收藏，与规则合法性、引擎支持分别判断。

“我的卡组”提供删除功能；删除前有确认，已有对局和回放所需的历史版本记录会保留。相同卡表重复保存会复用已有版本（包括改名或调整排列顺序）；卡表改变才创建新版本。旧版本开局前自动按当前卡池与规则校验，无需为规则更新复制版本。不满足当前规则时显示具体原因，请修改卡表后保存。

### 删除卡组版本

在卡组构筑中打开“版本记录”，点击对应的“删除版本”并确认。该版本会从列表和新对局候选中移除，不影响当前草稿、已有对局或回放。再次保存相同卡表可以恢复原版本编号。删除时若草稿已被其他页面更新，会提示刷新后重试。

## 人机练习与回放

1. 进入“人机练习”，选择“对战卡组版本”。没有可选项时，先去构筑页面保存通过校验的版本。
2. 选择“AI 卡组”（预组或可用的已保存卡组版本）和“AI 策略”。建议使用 A1；A2 是实验搜索且未评级。
3. 点“开始人机对战”，按当前决策面板完成开局、选牌与行动。
4. 对战中只显示当前允许的操作。使用特性、训练家、攻击或撤退时，按提示选择目标、费用及牌，完成确认；“本次查看的卡牌”仅代表这次效果允许查看的范围。
5. 自动结算的特性由系统直接处理。硬币结果和 AI 动作会在桌面展示，可结合事件记录确认发生了什么。

AI 行动速度可选慢速 3 秒、标准 1.8 秒、快速 1.2 秒；这些是展示节奏，实际思考和复杂结算可能另外耗时。想看清过程时选择慢速。查看场上卡牌信息以确认 HP、伤害、能量、道具和状态，不要仅凭默认卡图判断当前效果。

每一步裁定都会保存。刷新页面、重启服务后可继续仍有对应运行时的对局；离开练习页会暂停 AI 推进。历史记录可进入“继续对局”或“查看结果 / 回放”。逐步回放支持上一步、下一步、步数/回合跳转、自动播放及 1×/2×/4× 速度。

被明确停用的旧引擎对局仅能看已保存帧，不能继续执行；可选择通过当前规则校验的已有卡组版本开新局。排查规则问题时，记录对局 ID、步骤号、卡牌编号、自己的选择和预期结果，方便维护者准确复现。

## 备份恢复与升级

### 备份个人数据与活动版本

先保存编辑并停止服务。Windows 执行（macOS / Linux 换为 `.venv/bin/python`）：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py backup --bundle ../ptcg-user-backup.zip
```

macOS / Linux：

```bash
.venv/bin/python -X utf8 scripts/sync/run.py backup --bundle ../ptcg-user-backup.zip
```

**自定义数据目录需要显式指定。** 网页服务读取 `PTCG_DB` / `PTCG_SYNC_HOME`，但 `scripts/sync/run.py` 不读取这两个环境变量。例如，对上一轮恢复后继续使用的数据做备份：

```bash
.venv/bin/python -X utf8 scripts/sync/run.py backup --database "$PTCG_DB" --home "$PTCG_SYNC_HOME" --bundle ../ptcg-user-backup-next.zip
```

该示例要求两个环境变量都已设置为实际路径。PowerShell 使用 `--database $env:PTCG_DB --home $env:PTCG_SYNC_HOME`。未设置变量时，直接填写实际路径；只自定义数据库时，网页服务默认将同步目录放在数据库路径去掉扩展名后加 `.sync` 的位置，也应将该目录显式传给 CLI。

输出文件必须不存在；每次用不同文件名保存，记录返回的 SHA-256。该备份包括用户数据库、上传图片、同步批次、卡牌快照、已校验图片缓存和保留的运行时。它不包含整个应用、Python/Node 依赖，也不包含 `.catalog/upstream` 的完整 Git 原始卡图缓存或旧 `.catalog/images` 静态素材。

因此需要同时保留匹配的源码与本地运行资产，或完整安装包；若要完整离线迁移，停止服务后另行复制 `.catalog/upstream` 及自己需要的 `.catalog/images`。仅保存 CSV 或重新下载安装包都不能恢复对局和完整收藏信息。

恢复示例：在新机器准备兼容源码和本地资产，运行安装及检查步骤后执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/sync/run.py restore --bundle ../ptcg-user-backup.zip --destination ../ptcg-restored
```

macOS / Linux：

```bash
.venv/bin/python -X utf8 scripts/sync/run.py restore --bundle ../ptcg-user-backup.zip --destination ../ptcg-restored
```

目标目录必须不存在。命令会核验备份及冻结运行时，返回 `database` 和 `home` 的绝对路径。随后在同一终端设置返回路径并启动：

```powershell
$env:PTCG_DB = 'D:\Apps\ptcg-restored\user.sqlite'
$env:PTCG_SYNC_HOME = 'D:\Apps\ptcg-restored\sync'
.\start.ps1
```

macOS / Linux 示例（路径替换为实际恢复位置）：

```bash
export PTCG_DB="/path/to/ptcg-restored/user.sqlite"
export PTCG_SYNC_HOME="/path/to/ptcg-restored/sync"
bash start.sh
```

`user-card-images` 必须与恢复的 `user.sqlite` 同级；恢复命令已经放好，不要只移动数据库。以上环境变量只对当前终端及其子进程生效，日后从新终端启动时需再次设置，否则会打开默认 `var/app.sqlite`。这常被误认为“收藏丢失”。

### 源码工作区完整迁移

如果使用的是带 `.git` 的源码工作区，可停止服务后执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/portable/pack.py ../PTCG-Lab-backup.tar.gz
```

macOS / Linux：

```bash
.venv/bin/python -X utf8 scripts/portable/pack.py ../PTCG-Lab-backup.tar.gz
```

该工具只遍历项目目录，包含目录内的源码、Git 历史、未提交改动、用户资料和上游缓存，排除可重建的依赖及部分缓存。通过 `PTCG_DB` / `PTCG_SYNC_HOME` 指向项目外的资料不会自动收集，应另行用显式路径的数据备份命令保存。输出必须在项目外，且不能覆盖已有文件。普通 release 不含根 `.git`，不要在普通解压安装上使用此脚本；改用上一节的数据备份。

此归档是私人备份，可能包含项目内的环境文件和本地凭据，不用于 GitHub 发布。脚本要求工作区有可读取的 Git 提交，并拒绝项目中的符号链接。

在新目录解压后，若包中有默认数据库 `var/app.sqlite`，先执行 `python3 scripts/portable/verify.py`（Windows 使用 `python`）核验迁移清单和数据库，再按目标平台重新安装及检查。该校验脚本依赖默认数据库；仅源码工作区或使用其他数据库路径的归档不适用，应复核归档 SHA-256，并按数据备份流程核验个人数据。依赖安装需联网，迁移归档本身不提供离线依赖环境。

### 浏览器身份与旧对局

收藏、卡组保存在数据库；对局列表还关联浏览器访问身份。换浏览器或清除 Cookie 后，可对实际使用的数据库运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/portable/recover_session.py --list
.\.venv\Scripts\python.exe -X utf8 scripts/portable/recover_session.py
```

macOS / Linux：

```bash
.venv/bin/python -X utf8 scripts/portable/recover_session.py --list
.venv/bin/python -X utf8 scripts/portable/recover_session.py
```

多个身份时按列表使用 `--owner 完整身份值`；自定义数据库还需在两条命令中都加 `--db 实际数据库路径`；此脚本也不读取 `PTCG_DB`。打开脚本提供的一次性本地链接完成恢复，会替换该身份的访问凭据，比赛内容保留。此工具的跳转地址固定为 `127.0.0.1:8765`，恢复时建议使用默认端口。

### 升级

先备份，再将新版源码或完整安装包放到独立目录，准备匹配的本地资产并重新安装依赖、检查运行环境。通过上述恢复流程在新目录试运行，核对收藏、卡组、上传图片与历史对局后再切换日常入口。不要直接用新包覆盖正在使用的 `.catalog/sync/current.json`、旧数据库或历史运行时；不要把“回滚卡库”当成“回滚个人数据”。

## 常见问题

| 现象 | 排查和处理 |
| --- | --- |
| `python` / `npm` / `git` 不存在 | 安装工具并加入 PATH，重新开终端；确认版本命令可以执行 |
| Python 版本过低 | 安装 3.14+，通过 Windows `-Python` 或 macOS / Linux `PYTHON` 指定 |
| Linux 无法创建 venv | 安装对应解释器的 venv/pip 系统组件，再执行 setup |
| 安装依赖联网失败 | 保留终端错误，修复网络、代理或依赖源可达性后重跑 setup |
| 浏览器无法访问 | 确认终端服务仍运行、地址和端口相同；首次安装不是双击网页文件 |
| 端口占用 | 使用已有服务，或通过 `-Port` / `--port` 换端口 |
| 网页仍显示旧界面 | 刷新或强制刷新浏览器，确认访问的是本次启动目录的服务 |
| 卡牌资料有但没有图片 | 执行 `fetch-images`，检查 GitHub 网络；离线前执行 `cache-source` |
| 全量缓存后状态仍显示未缓存图片 | Git 原图与已解码图片缓存是两层；以 `cache-source` 的 `missing: 0` 判断完整原始缓存 |
| 图片确实缺失或不正确 | 核对卡号、来源提交及卡面版本；必要时上传本地默认卡图并提供编号给维护者 |
| 上游缓存来源不符或有本地修改 | 不要强制覆盖；保留错误和现有目录，由维护者核对仓库配置与修改 |
| 同步部分完成 | 查看待核验/待实现任务；新资料不一定已经有对战实现 |
| 收藏修改冲突 | 刷新收藏数据后重新输入，避免多个页面同时编辑 |
| 没有可选对战卡组 | 保存通过当前环境与效果校验的卡组版本；不要只保留草稿 |
| 原有收藏或对局“消失” | 检查启动目录、`PTCG_DB` / `PTCG_SYNC_HOME` 和浏览器身份，不要先新建或覆盖旧数据库 |
| 缺少卡牌数据、生成引擎或哈希清单 | 按“准备本地资产”导入兼容文件；仅安装依赖无法补齐，不要删除校验或用不同版本引擎替代 |
| 保存提示权限不足 | 将项目放到自己的可写目录，检查磁盘剩余空间及文件权限 |

服务日志默认显示在启动终端，冻结版本工作进程日志在 `.catalog/sync/logs`。反馈问题请附系统、Python/Node/Git 版本、项目的 `RELEASE.json`、出错操作及错误文本；对战问题额外附对局 ID 和步骤号。

## 文件与进阶入口

| 路径 | 用途 |
| --- | --- |
| `start.ps1` / `start.sh` | Windows / macOS / Linux 安装、检查与启动入口 |
| `RELEASE.json` | 安装基线版本、上游提交和冻结对战发布标识 |
