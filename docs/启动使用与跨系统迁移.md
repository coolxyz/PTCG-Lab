# PTCG Lab：安装与使用手册

当前操作说明（2026-10-30）。覆盖 Tauri 桌面 App、源码 Web 与 API v2 网络对战。

## 产品范围与运行条件

本机提供中文卡牌资料库、收藏、构筑、人机练习和网络大厅。人机与网络共用已保存卡组和对战界面。远端 API 负责权威网络对局、身份、房间和回放；卡图在本机按需下载，不经对战服务器传输。

| 方式 | 用户需要安装什么 | 启停方式 |
| --- | --- | --- |
| macOS arm64 App | 维护者提供的完整 App/DMG | 原生窗口内含后台，关闭/退出回收自有进程 |
| Windows x64 预览 App | 完整 ZIP 和 WebView2 | EXE 与 backend 一起保留；无需 WSL2 或开发工具，实机验收待完成 |
| 源码 Web | Python 3.14+、Node.js/npm、Git、批准资产 | 终端启动，浏览器访问，Ctrl+C 停止 |
| API Server | 目标架构 Docker 与 Compose；kit 管理器需要 Python 3.11+ | 在独立服务器管理，不随 App 关闭 |

未缓存卡图和网络对战需要联网；已有资料、收藏、构筑、人机和已缓存图片可本机使用。新资料收录、新图片和对战支持是三件事，以卡组校验与当前批准规则为准。

## 桌面 App 安装与启动

### macOS

1. 核对同批 `SHA256SUMS`、`RELEASE-FILES.json` 和交付记录。App 支持 Apple Silicon；声明目标 macOS 12.0，最低版本/Intel 不等于已实机验收。
2. 使用 DMG 时，先保存并关闭已有 PTCG Lab，再运行介质中的 `Install PTCG Lab.command`。安装器备份数据、登记整包身份并输出当前 App 的启动路径。
3. 双击安装后的 App。原生壳自动显示启动页、启动自己的后台并完成同源授权，无需终端码或生成 HTML。
4. 新的独立用户目录可首次启动；已有数据出现 `DESKTOP_INSTALL_REQUIRED` 时按受控安装流程采用并备份，不能删除安装记录绕过校验。

App/ZIP 也是构建产物，单独换程序不等于完成受控升级。当前预览使用 ad-hoc 封套，未取得 Developer ID/Apple 公证；按本机可信软件策略处理，不关闭系统保护。升级和整套回退见 [安装升级说明](安装升级与迁移.md)。

### Windows

1. 使用 Windows 10/11 x64 与 WebView2，核对 ZIP 摘要后完整解压至普通用户可写的本地 NTFS 目录。
2. 阅读后运行随包 `Verify.ps1`，再双击 `PTCG Lab Preview.exe`；保持 EXE、`backend/` 和其他随包文件的相对位置。
3. 当前已交叉生成完整程序并核对 PE/依赖/图标；DPAPI、Job Object、WebView2、最低系统及完整产品仍需 Windows 实机确认，见 [Windows 手顺](Windows验证步骤.md)。
4. Windows 受控安装升级/迁移尚未完成实机验收。已有 preview 数据时先关闭并完整备份；若启动要求安装登记，不通过删除 profile、数据库或标记解决。

### 数据位置

| 内容 | 默认位置 |
| --- | --- |
| macOS profile | `~/Library/Application Support/org.ptcglab.desktop.preview` |
| Windows profile | `%LOCALAPPDATA%\org.ptcglab.desktop.preview` |
| 收藏、卡组、练习 | profile 内 `app.sqlite` |
| 同步、展示包、在线图片缓存 | profile 内 `app.sync/`；在线缓存为 `app.sync/artwork/` |
| 自行上传卡图 | profile 内 `app-card-images/` |
| 服务器配置 | profile 内 `connection.json` 和受信 CA 文件 |

原生后台每次使用新的随机 loopback 端口，请从 App 打开。macOS Keychain/Windows DPAPI 保护网络凭据，不能把加密文件直接复制到另一台设备当作身份迁移。

## 从源码安装与启动

公开仓库不含完整卡表、引擎资产或已构建网页。先从有权使用的可信兼容环境导入 `data/`、`runtime/engine/` 与完整性清单，再安装依赖。仅下载上游 JSON/卡图不能代替运行资产。见 [公开源码说明](GitHub发布与隐私.md#公开源码如何启动)。

macOS / Linux：

```sh
python3 scripts/public/import_local_assets.py /path/to/trusted-private-project
bash start.sh --setup --check
bash start.sh
```

Windows PowerShell（已有批准资产时）：

```powershell
.\start.ps1 -Setup -Check
.\start.ps1
```

Windows 首次资产导入使用 `python -X utf8 scripts/public/import_local_assets.py <可信目录>`。如组织策略禁止脚本，使用允许的审核流程或手工调用仓库 Python 入口，不改全局执行策略。

默认浏览器地址 `http://127.0.0.1:8765/`。后续无需重复 setup；检查环境用 `--check` / `-Check`，更换端口用 `--port 8766` / `-Port 8766`。安装会构建统一产品前端，生成环境只在当前平台使用，不跨系统复制 `.venv` 或 `node_modules`。本机基础 Web 不配置网络宿主时，网络大厅会提示其不可用。

### 源码 Web 的统一网络宿主

准备兼容配置文件，例如：

```json
{
  "servers": {
    "test": {"origin": "https://ptcg.example:8876", "ca_file": "/absolute/trusted-server-ca.pem"}
  },
  "manifests": []
}
```

替换地址与 CA 路径后，POSIX 源码环境运行：

```sh
bash start.sh --online-config /absolute/connection.json \
  --online-state /absolute/private-online-state --port 8765
```

统一宿主同时提供本地功能和网络桥接，不另起第二个本机产品服务。按启动提示完成本机浏览器授权；`--no-browser` 用于手工授权，`--reopen` 请求重新打开仍运行的相同宿主，不抢占端口。该源码路径与原生壳的自动授权不同，Windows 原生使用上一节 App 路径；早期 WSL2+浏览器测试保留在阶段记录中。

默认 Web 数据库为 `var/app.sqlite`、同步目录为 `.catalog/sync`；自定义 `PTCG_DB` 时，未设置 `PTCG_SYNC_HOME` 则使用数据库同名 `.sync` 目录。统一宿主的在线身份目录由 `--online-state` 指定，与本地产品数据库分别保存。换端口/浏览器会改变浏览器 Cookie 和本地偏好上下文。

## 第一次使用

1. 打开资料库，直接查看卡图，无需先准备 Git 缓存。
2. 查看中文详情，登记收藏或导入清单。
3. 构筑并保存通过校验的卡组版本，或在人机页面保存推荐预设。
4. 开始人机练习；要联网则先配置受信服务器，再到网络大厅使用同一份本地卡组。

## 卡图、离线资源与资料更新

### 默认按需下载

卡图使用固定版本的轻量索引，显示时由本机后台从 GitHub Raw 获取，校验 Git blob、文件摘要与图像后存入缓存。资料库、人机和网络共用，默认容量 1 GiB；已缓存图片断网后仍可用。读取卡表不会预取全库卡图。

在 **数据与对战更新 → 在线卡图与本机缓存** 查看数量/空间、展开“图片来源与缓存设置”、更改来源和额度后保存并刷新。Raw 仍可能限流或网络不可达，App 会退避；等待后点击“重试显示卡图”。不逐图调用 REST blob/tree 接口不等于永不限流。

### 图源与离线导入

- 静态图源/CDN：设置 HTTPS 基础地址，按固定仓库/提交/路径结构提供原始图片。证书、内容和来源检查保留，详见[按需卡图文档](按需卡图与本地缓存.md#静态图源cdn)。
- ZIP：在 **卡图与展示资源** 中选择资源 ZIP，粘贴对应 SHA-256，点击“校验并安装资源”，再“启用此展示”。安装不自动启用；一次只启用一份包，未覆盖条目继续使用在线来源。
- 个人上传：卡牌详情可补充卡图，最大 8 MiB；仅在本机保存，不改规则或上游。

优先级为个人上传 → 启用 ZIP 中对应条目 → 已存在的批准同步图片索引 → 随包精确索引 → 占位。在线缓存 LRU 清理不删除上传图片或 ZIP。当前随包覆盖 12,931 项，26 项歧义保留占位或已有展示。

资源 ZIP 最大 256 MiB、解压总量最大 512 MiB。遇到 `Images exceed App pack budget`，请缩小卡包/printingId 范围，或改用默认按需下载；多个小包不会自动叠加。离线制作见 [Git 工具](Git卡图下载与资源包工具.md)。运行 App 不需要先执行 `fetch-images`、`cache-source` 或全库下载。

### 更新卡牌资料与规则

“数据与对战更新”中的资料仓库默认公开上游，可设置同格式 GitHub fork；此设置与在线图片来源/CDN 设置分别保存。检查更新 → 迁移预演 → 同步适配 → 候选对战效果验证/验收发布是不同步骤。未知规则保持待办，不因图片显示成功而可对战。

卡表同步使用校验过的 HTTPS 元数据客户端，桌面运行不依赖外部 Git；元数据 API 本身仍可能限流。同步 CLI、规则维护和显式整套回退见 [上游同步](上游卡库同步.md)。

## 网络对战

### 连接服务器

由维护者提供受信 API kit 的公开连接信息和 CA；客户端不需要数据库密码或 TLS 私钥。

- macOS：保存并关闭 App，运行同批服务 kit 的 `configure-mac.command`；必要时按 kit 说明用 `PTCG_APP` 指定 App 路径。
- Windows：关闭 App，在完整 App 目录执行 `configure-server.cmd --client-kit "C:\path\to\client-kit"`。
- 已有配置时助手拒绝覆盖，需先备份并核对已有 `connection.json`/CA；不要为换服务器清除收藏、卡组或网络身份。

重新打开 App 后进入“网络对战”，选择已配置服务器并创建游客身份。原生自动完成本机授权；源码浏览器使用统一宿主的授权入口。用户身份、房间和卡组与所选服务器及规则绑定。

### 房间邀请与双人对战

1. 构筑页面保存通过校验的卡组版本。大厅选择平台上的卡组及具体版本，无需额外导出 JSON。
2. 一方新建房间，发送界面显示的房间码；另一方选择同一服务器并输入房间码加入。
3. 双方确认卡组并准备，服务器批准开局后进入共用对战界面。
4. 按合法决策行动。通信失败时保留待确认操作，以原 commandId 核对/重试；不要连续创建新操作代替未知结果。
5. 大厅可查看已有对局、恢复当前对局及已结束对局的回放。重新进入大厅不会自动跳到上一次已完成的对局。

卡组草稿后来修改不改变已开局的冻结版本。不同设备各自有本机收藏、卡组、图片与身份；当前没有自动云同步。转移身份使用受控加密交接，不直接复制 Keychain/DPAPI 文件，见 [Windows 运行时与身份导入](安装升级与迁移.md)。规则更新后不保证旧局续局，只保留获准的历史帧展示。

## 卡牌库与图片

- 搜索名称、英文别名或卡牌编号；可结合系列、扩充包、属性、持有情况和卡图状态筛选。扩充包选项显示“名称 · 实际扩充包编号 · 卡数”，不会以内部 `chs-product` ID 代替编号。
- “系列”偏向印刷编号系列，“扩充包”按商品关系筛选；同一印刷身份可能属于多个商品。没有结果时先清除筛选。
- 页面顶部和底部都有分页入口。打开卡牌详情后关闭，应回到主页面原来的滚动位置。
- 详情展示卡牌身份、规则资料、效果支持、卡图及收藏。资料收录、规则审核和可对战是不同状态，以效果支持和组牌校验结果为准。
- 主图与“卡面版本与收藏”中的卡图均可点击放大，直接在当前页查看；按 Esc、点关闭按钮或背景可退出预览。卡图来源链接仍用于访问来源网站。
- 简中与繁中替代图会有标记；展示替代图片不会改变简中卡牌身份。

缺图处理：先检查“在线卡图与本机缓存”的来源、重试状态和网络，再查看“卡图状态”筛选及“导出缺失卡图清单”。如来源确实缺图，在卡牌详情的“补充卡图”选择 JPG、PNG 或 WebP（最大 8 MB），检查预览后点“保存卡图”。上传仅保存在本机，点击“恢复默认卡图”撤销自定义展示。

当前上传功能针对这张印刷卡的默认展示图，不是逐个普通/精灵球/大师球卡面上传工具；它不会改写上游图片或规则说明。请核对名称、编号与版本后再上传。

## 收藏与卡面版本

“我的收藏”显示已登记的持有情况，可以搜索、管理品相、数量、备注及想要收集的卡牌。详情中的品相包括“未标注”“全新”“良好”“使用痕迹”。修改完成后按对应保存按钮，列表会同步更新。

同一卡号不同工艺作为不同收藏版本管理。151C 的显示顺序为 **普通版 → 精灵球版 → 大师球版**。`CHS:数字` 标识具体上游卡面；如 `CN:151C:002` 则标识聚合后的印刷身份，不要将二者当成同一种编号。

两种操作的含义：

| 按钮 | 用途 | 对总量的影响 |
| --- | --- | --- |
| 保存卡面数量 | 设置该品相下这一卡面的实际持有数量 | 相应增减总量 |
| 分配已有收藏 | 将以前只登记总量的卡，划分到具体卡面 | 总量不变 |

例如已登记 5 张、全部未分配：把普通版数量填 3 并“分配已有收藏”，再把精灵球版填 2 并分配，仍共 5 张。如果此时新买 1 张精灵球版，将该版本数量改为 3 并“保存卡面数量”，总量变成 6 张。输入的是该版本的最终数量，不是这次新增的数量。

不能将总量减到已分配数量以下。先减少相应卡面持有量或调整分配。出现“收藏已变化”时重新读取当前状态后再保存，避免多个页面同时覆盖修改。

“数据与对战更新 → 分配收藏版本”也能整理已有分配；此处数量输入失焦时保存。收藏工艺不增加卡组的同名限额，也不改变对战效果。

## 导入与导出

“我的收藏 → 导出 CSV”用于导出收藏清单；它不是包括图片、卡组、比赛的完整备份。建议先导出一份作为自己后续整理表格的格式模板。

收藏或卡组导入均支持选择 CSV/TXT（界面限 200 KB）或粘贴文本。推荐 UTF-8 编码，并使用应用认可的印刷身份：

```csv
printingId,quantity
CN:151C:001,2
CN:151C:002,1
```

也支持“数量 卡名 系列 编号”格式，例如：

```text
2 妙蛙种子 151C 001
1 妙蛙草 151C 002
```

操作步骤：粘贴或选文件 → “解析并预览” → 处理无法识别、同名多版本等项目 → 核对总张数与版本 → “确认导入”。不要跳过歧义确认。

收藏导入按数量增加；同一批次重复提交不会再次增加。之前只含总量的导入应随后分配卡面版本，不能自动推断普通/闪卡。可在“导入记录”查看批次并按界面允许的状态撤销；若后来已作其他修改而撤销被拒绝，应按当前实际持有量调整。

卡组导入会替换当前草稿，确认前先保存需要保留的构筑。收藏清单中的持有数量不一定符合卡组规则，不能直接当成合法 60 张卡组。

## 卡组构筑与管理

1. 打开卡组页面，从预组创建一副卡组，或新建/导入自己的构筑。
2. 在编辑器搜索卡牌并加入构筑，调整数量，填写名称。右侧显示总张数、类别分布、校验问题和缺卡清单。
3. 对照每条问题的说明及建议修正：例如张数、同名限制、环境合法性和效果支持。界面提供的校验结果是能否开始对战的依据。
4. 保存构筑版本；对战选择的是已保存版本，未保存草稿的修改不会自动进入已有对局。
5. 缺卡计算可选“按指定印刷版本”或“接受已审核规则等价版本”。它用于对照实物收藏，与规则合法性、引擎支持分别判断。

“我的卡组”提供删除功能；删除前有确认，已有对局和回放所需的历史版本记录会保留。相同卡表重复保存会复用已有版本（包括改名或调整排列顺序）；卡表改变才创建新版本。旧版本开局前自动按当前卡池与规则校验，无需为规则更新复制版本。不满足当前规则时显示具体原因，请修改卡表后保存。

### 删除卡组版本

在卡组构筑中打开“版本记录”，点击对应的“删除版本”并确认。该版本会从列表和新对局候选中移除，不影响当前草稿、已有对局或回放。再次保存相同卡表可以恢复原版本编号。删除时若草稿已被其他页面更新，会提示刷新后重试。

## 人机练习与回放

1. 进入“人机练习”，选择“对战卡组版本”。没有可选项时，先去构筑页面保存通过校验的版本。
2. 选择“AI 卡组”（预组或可用的已保存卡组版本）和“AI 策略”。建议使用默认 H2；A1 为基础策略，A2 是实验搜索且未评级。也可以先在“快速使用推荐预设”直接保存五套预设之一。
3. 点“开始人机对战”，按当前决策面板完成开局、选牌与行动。
4. 对战中只显示当前允许的操作。使用特性、训练家、攻击或撤退时，按提示选择目标、费用及牌，完成确认；“本次查看的卡牌”仅代表这次效果允许查看的范围。
5. 自动结算的特性由系统直接处理。硬币结果和 AI 动作会在桌面展示，可结合事件记录确认发生了什么。

AI 行动速度可选慢速 3 秒、标准 1.8 秒、快速 1.2 秒；这些是展示节奏，实际思考和复杂结算可能另外耗时。想看清过程时选择慢速。查看场上卡牌信息以确认 HP、伤害、能量、道具和状态，不要仅凭默认卡图判断当前效果。

每一步裁定都会保存。刷新页面、重开 App 或重启本机后台后，可继续仍符合当前批准规则与执行身份的对局；离开练习页会暂停 AI 推进。历史记录可进入“继续对局”或“查看结果 / 回放”。逐步回放支持上一步、下一步、步数/回合跳转、自动播放及 1×/2×/4× 速度。

被明确停用的旧引擎对局仅能看已保存帧，不能继续执行；可选择通过当前规则校验的已有卡组版本开新局。排查规则问题时，记录对局 ID、步骤号、卡牌编号、自己的选择和预期结果，方便维护者准确复现。

### 操作、桌面与公开记录

悬停卡牌查看完整卡面，点击可用卡牌或当前决策按钮进行操作。内部拖牌使用指针手势：基础宝可梦到备战区、能量/指定目标的卡牌到合法目标、竞技场到竞技场区，其余无目标操作到打出区。有多个合法选项时再选择；开局拖牌只设置选中项，仍需确认。非法目标、Escape、失焦或决策变化会取消拖动。

右上角“桌面外观”提供默认大师球浅紫、其他纯色、原创赛事风格 SVG 桌垫和个人图片导入，详见[外观说明](架构与维护.md)。

“对局信息”显示动作标题、公开卡牌、投币与可见结算，可筛选和暂停跟随，点击卡牌打开当时公开的详情；“已阅”不暂停对局。检索、竞技场和特性只展示规则允许公开的信息。道具招式同时列出攻击者及“招式来源 · 已附加道具”，进化与退化分别显示；没有合法效果目标时可能没有相应局面变化。缺失卡牌 ID 不会命中空名称条目。

历史公开帧可以在读取时补全展示，不改写原始事件、不重新执行旧规则。报错时请记录模式、对局编号和步骤号；不能仅凭相似卡图判断使用了哪张卡。

## 备份恢复与升级

### 桌面 App

先保存并关闭全部窗口，确认更新任务已停止。macOS 使用 DMG 安装器/受控安装工具生成整套 profile 备份并切换 App；profile、同步状态、上传图片、凭据密文和既有回放均保留。中断出现 `DESKTOP_RECOVERY_REQUIRED` 时按事务明确完成或撤销，不删除标记或单独换旧程序。

macOS Keychain 密钥不在文件备份内；Windows DPAPI 绑定用户/设备。跨设备或跨目录迁移网络身份必须用显式加密交接。Windows 原生受控升级及跨设备实机矩阵仍待验，不能把文件复制当作已支持的升级方案。整套回退合同和命令见 [安装迁移](安装升级与迁移.md)。

### 源码 Web

关闭目标本机服务后，明确指定实际数据库与同步目录，避免备份到另一个默认环境：

```sh
.venv/bin/python -X utf8 scripts/sync/run.py backup \
  --database /absolute/app.sqlite --home /absolute/app.sync \
  --bundle /absolute/private/user-backup.zip
.venv/bin/python -X utf8 scripts/sync/run.py restore \
  --bundle /absolute/private/user-backup.zip --destination /absolute/new-restored
```

Windows 改为 `.venv\Scripts\python.exe`。恢复目录必须不存在；核对后使用返回的 database/home 设置 `PTCG_DB` 和 `PTCG_SYNC_HOME` 再启动。上传图片需与恢复数据库一起保留，不能仅拷贝单个 SQLite 文件。同步备份不是完整 App 安装器，也不包含独立在线身份目录、系统钥匙串或开发依赖。现有同步 ZIP 也不自动收集新增 `artwork` 缓存/设置和 `display` 展示包；完整离线迁移应在关闭目标后台后另行备份整个实际 profile/数据库配套目录，不能仅依赖此局部导出。

收藏 CSV/卡组文本只用于清单交换，不是完整备份。私有 profile、备份、API secrets 和原始日志不提交 Git。源码升级需配套批准资产和本机依赖；旧规则对局不通过迁移或改写身份继续执行。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 卡图占位或加载失败 | 检查在线来源、退避与网络；等待后重试；26 个歧义条目不会强行选图，可用上传/经审核 ZIP |
| 全库 ZIP 超出预算 | 改用默认按需缓存；离线包缩小范围，多个 ZIP 不会自动合并 |
| 关闭窗口后旧 HTML/随机本机网址打不开 | 原生后台随 App 退出；重新打开 App。早期一次性 HTML 不是长期入口 |
| 网络大厅不可用 | 确认 native `connection.json`/CA，或源码启动是否带 `--online-config`；单独基础 Web 不含网络桥接 |
| 房间码无法加入 | 确认两端服务器、当前规则、房间状态与所选卡组版本一致，记录实际错误码 |
| `DESKTOP_INSTALL_REQUIRED` / `DESKTOP_RECOVERY_REQUIRED` | 关闭 App，按受控安装/事务恢复处理；保留数据和标记 |
| 收藏存在但对局列表空 | 核对所用 profile/数据库、浏览器 Cookie 或服务器身份；不要先新建游客替代待恢复身份 |
| 只刷新页面仍是旧版本 | 界面、随包后台和批准规则是配套制品；原生重新安装整包，源码核对活动发布，不能只替换单个 JS |
| 同一张卡不能在新版继续旧局 | 核对规则和执行身份；旧规则停用后可查看已存回放并新开对局 |

发现问题请提供模式、App/制品来源、对局 ID、步骤号、卡牌编号、可见操作及预期结果；不提供 token、密钥或完整私有存档。打包与状态见 [打包说明](构建与发布.md)、[架构与维护](架构与维护.md)。
