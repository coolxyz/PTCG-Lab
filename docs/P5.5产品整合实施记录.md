## 本轮交付

### 统一启动和授权

- 一个本机 HTTP 进程同时提供完整产品、收藏/卡组 API、人机练习、网络大厅及桥接。产品导航新增网络对战，版本弹窗可分别选择人机或网络模式。
- `start.sh --setup` 安装原产品依赖和 protocol/provider/online-client/desktop-api 内部包，构建产品与诊断前端。`npm run product:build` 生成 `apps/web/dist` 和 `apps/desktop-web/dist`。内部 Python 包用普通 wheel 安装，不依赖 editable 或原项目。
- 正常产品入口为 `/#online`。首次启动只需将终端显示的五分钟一次性授权码输入大厅，不再打开临时 HTML。授权码通过同源 POST 换取 HttpOnly/SameSite=Strict 本机会话；窗口能力只在内存中，远端 access/refresh token 留在后台。
- 同一浏览器关闭重开可继续使用有效会话。终端输入 `r` 或相同命令追加 `--reopen` 可重新授权；后者通过 0700 状态目录中的 0600 Unix socket 与已有实例通信，配置摘要须一致。独占文件锁防止双 owner；正常退出释放，非正常退出后的残留 socket 由取得独占锁的新实例清理。
- 依然校验精确 Host/Origin、回环来源、重复头及代理头。HTTP 只能消费原生生成的授权码，没有免认证签发接口。端口已占用时拒绝启动，不终止占用者。Mac/Linux/WSL2 支持此流程；原生 Windows 不在本轮支持范围。

示例（在具备批准规则资产的产品部署目录运行）：

```sh
bash start.sh --setup --port 18789 --online-config /absolute/online.json
# 已完成安装时省略 --setup；WSL2 可追加 --no-browser。
# 重新打开已经运行的同一实例：
bash start.sh --port 18789 --online-config /absolute/online.json --reopen
```

默认私有状态目录是部署下的 `var/product-online`；可通过 `--online-state` 显式指定已有凭据目录。配置保持 `servers/manifests` 格式，HTTPS 和 CA 信任配置由用户明确提供。应选择较短的状态目录路径，避免 Unix socket 的平台长度限制。启用组合模式仍需明确提供 `--online-config`；默认入口的最终切换在 P5.5-D 验收后进行。

### 共用卡组

- 平台 SQLite 是唯一卡组源。网络大厅直接列出已有卡组、冻结版本，可冻结已保存卡表；未保存草稿须先在构筑页保存。已有版本弹窗的两个入口分别交给人机或网络模式。
- 选择版本后调用现有本地校验，逐条展示涉及卡牌和建议；服务器作最终准入裁定，不自动替换卡牌。当前 API v2 拒绝卡组只返回 `INVALID_PAYLOAD`，界面明确说明服务端没有逐卡明细，不把本地检查冒充服务端诊断。
- 产品适配器读取并校验不可变 revision 摘要，仅将 `printingId/quantity`、规则版本与幂等请求编号交给 native client。卡组名称、收藏数量、备注、数据库路径和本地 ID 不上传。
- 新增 `online_deck_requests` 表，映射按服务器 origin/CA 信任摘要、服务器身份/用户/设备、规则版本和规范化卡表哈希隔离。远端 revision 与本地 revision 分开。提交前持久化请求、版本及 entries，响应丢失后沿用原请求，编辑或删除原卡组也不会改变这次提交。
- 未确认请求可由后台返回给新窗口恢复；确定的 400/422 拒绝清除待确认项，未知结果保留。不同规则、身份或服务器不复用映射。
- 本地查询、检查和冻结不占远端 profile 通信锁，避免初始化能力查询与卡组加载相互报忙。网络调用在线程池执行。

### 共用显示资源

- `apps/api/product_online.py` 装配平台 `CardMedia` 和已有固定提交图源。原生客户端包不直接导入 SQLite、规则引擎或资料库。
- 使用共享 provider 对平台卡表作语义投影并计算摘要，只在与远端 `displayCatalogVersion` 匹配时接入；对局快照及回放帧切换版本时重新解析，缺版本降级文字。
- 按 engineId 聚合显示信息，优先选择有本地 URL 的卡面，再按 printingId 排序；协议没有原始印刷身份时标注为“平台默认卡面”，不声称是用户实际选择的闪卡或印刷。
- 固定提交图源沿用 `/api/sync/images/{commit}/{cardId}` 和平台本机缓存；下载时校验 Git blob，缓存命中重新校验 SHA-256。用户上传/本地文件卡图进入原生内容哈希缓存，后续删除原文件不破坏已生成资源版本。
- 显示目录按内容摘要持久保存，更新后旧版本仍可查询。缺图、版本不匹配和缓存容量不足不阻断合法对战。浏览器只请求本机地址，远端 API v2 不承担卡图或整张显示卡表传输。

## 数据迁移与回退

首次新增网络映射表前，通过 SQLite backup API 生成 `<数据库>.before-product-online.sqlite`，包括已提交的 WAL 数据；备份权限 0600，不覆盖已有备份。迁移失败留下备份时停止并要求先检查，不静默覆盖。已有卡组、收藏、版本表语义不变；新增索引/表可被旧产品忽略。

回退前关闭本 APP，保留当前数据库、备份和私有凭据，按匹配的旧制品/备份恢复。不可在仍有未知网络操作时删除新表或凭据；这会丢失幂等恢复依据。远端状态不会随本地 SQLite 回退。测试使用新数据库，未复制用户收藏数据库，也未重启原项目或运行中的 v1/API v2 服务。
