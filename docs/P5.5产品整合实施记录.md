# P5.5 产品整合实施记录

更新：2026-10-26。基线提交：`101b588`。P5 已按用户确认的范围验收，见 [P5-D 用户记录](../releases/p5d-user-acceptance.json)。当前 P5.5-A **in_progress**，B/C/D 尚未实施。用户报告的对战画面显示问题安排在 P5.5 完成后集中修正，不在本次进行视觉修改。

## 已实现的第一批代码

- `ptcg-desktop-api==0.5.0.dev6` 新增 `create_product_app`：注入现有产品 ASGI 应用，在同一 HTTP 进程/端口提供产品根页面、本地 API、`/online` 页面、网络桥接和相关静态资源。没有反向代理或第二个客户端服务。
- 产品工厂 `apps/api/product.py` 显式装配 `apps.api.main:create_app`。原生客户端包继续不依赖本地数据库、引擎或 AI；产品内人机 API 可以直接演进，无需绕过原项目运行边界。
- 根启动器增加 `--online-config`、`--online-state`、`--online-build` 和 `--no-browser`。显式启用组合模式；未启用时仍保留已有启动方式，直到后续产品整合完成后切换默认入口。
- 统一管理产品和网络 owner 生命周期，产品启动失败也清理一次性票据/owner，Ctrl-C 正常退出。已有服务端口被占用时拒绝绑定，不终止占用进程。
- 本地产品入口增加精确 Host/Origin、回环 peer、重复头和代理头校验；无 Origin、null Origin 和跨站写入均不能借旧路由绕过。网络一次性启动与能力签发仍使用原安全校验，未添加免认证授权接口。
- 产品和网络静态资源共用 origin；同名不同内容的资产启动时拒绝，避免错误覆盖。产品 API 查询参数保留。

## 当前可用入口与限制

具备原产品运行依赖、已批准规则资产及已安装内部 wheel 的测试部署，可使用：

```sh
bash start.sh --port 18789 \
  --online-config /absolute/online.json \
  --online-state /absolute/private-product-state \
  --online-build /absolute/online-web-dist --no-browser
```

配置格式沿用 P5 的 servers/manifests。当前依赖安装仍需在目标 `.venv` 安装 `apps/desktop-api/requirements.lock` 与 protocol、online-client、desktop-api 的对应 wheel；原 `--setup` 尚不自动安装整合包，此项属于 A 阶段剩余工作。Windows 测试在 WSL2 使用 Bash，不宣称已实现原生 Windows 凭据后端。

首次仍使用统一后台输出的授权 HTML，授权后进入产品根页面；同端口 `/online` 可进入网络窗口。用户目前仍须主动选择网络页面，卡组仍采用 P5 输入方式。根产品导航、正常产品内的窗口授权交付、无额外 HTML 的完整使用流程、已有实例重新打开和正式安装流程尚未完成，因此不将 P5.5-A 标为完成。

状态目录默认使用部署下独立的 `var/product-online`，也可明确指定原 P5 状态目录；重用之前必须先关闭持有该目录的原客户端 owner，不自动扫描、复制或替换现有凭据。现有 P5 测试包及已运行后台未自动升级。

## 验证证据

本机证据位于 `var/p55a/`，测试使用新副本、新 SQLite 与自己的临时 HTTP 进程，未复制用户数据库。

- 宿主、启动器与资源测试 31 项通过：产品/网络同源、授权签发、卡组查询参数、跨站/缺 Origin/错误 Host/代理头/重复头拒绝、失败启动清理、原独立窗口回归。
- 从构建 wheel 安装的组合宿主通过实际 HTTP 检查：同一进程访问产品和网络页面，冻结人机预设、以 H2 开局、认输、读取回放时间线；同一端口的网络桥接获取运行中 API v2 的 capabilities，仍能读取刚建立的本地卡组。该检查不是自然终局或共用卡组选择器的验收，也不是两台物理设备验收。
- 迁移和公开导出回归 89 项通过；源码/边界/协议/TypeScript/源码归档门禁通过。新宿主 wheel 已构建并在测试副本通过安装后验证。
