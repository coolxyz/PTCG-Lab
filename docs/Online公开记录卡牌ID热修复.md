## 问题与修改

竞技场等公开卡牌缺少显式 `id` 时，牌面投影一直使用 `set_name-number` 作为标识；公开动作记录却回退到卡牌名称。名称含空格时不满足协议 `Identifier`，结果帧在事务内校验失败，整条命令回滚，客户端保留原待确认请求。规则计算成功不等于命令已持久化。

协议投影模块提供 `card_identity`，保留原有 ID 优先级和投影格式；公开动作／公开来源选择统一调用它。多角色引用同一卡牌时也使用这一标识去重，名称相同但不同编号的印刷版本继续分别展示。公开记录的 presentation 仍保留原允许字段，不复制私有诊断、手牌或选择候选。

不修改规则核心、Provider、规则制品、数据库结构、会话身份、TLS CA 或客户端协议。既有对局可以继续使用原 commandId 和原待提交正文恢复，不需要重开。
