## 1. 实施原则和阶段依赖

2026-10-26 范围确认：不再将“保留当前人机练习和 AI 任务的运行边界”作为 PTCG-Lab 开发限制。人机、产品后台、启动入口与资源访问均可直接重构；已有数据、规则版本、认证与回归要求继续保留。下文 P0—P5 的旧入口保留/隔离描述记录当时实施范围，不是未来冻结产品的要求；归档验收不回写。

按可验证的小变更推进，先定义边界、证明等价，再切换调用方。禁止用一次全目录移动同时修改规则、AI、协议、存储和发布方式。每阶段有独立回退点；测试未通过不宣布完成，也不以“下一阶段会修”跳过当前门槛。

```text
P0 设计及边界确认（已完成）
  → P1 基线、包骨架、导出门禁（已完成）
  → P2 共享协议和规则核心（已完成本地验收，生产仍走旧路径）
  → P3 共享 GUI 与本地产品适配
  → P4 纯 API 服务
  → P5 本地网络客户端与资源管理

  → P6 多局调度、推送和持久化优化
  → P7 小配置容量与故障验收
  → P8 Tauri 2：macOS／Windows 完整版优先，随后 iOS；独立发布与运维
```

P2 合同稳定后，P3 与 P4 可以由不同工作项独立推进；P5 依赖二者。P5 完成后先进入 [P5.5 产品整合](P5.5产品整合实施设计.md)，P5.5 完成后进入 P6。P6 的测量工具可提前准备，但性能结论必须在功能和持久化语义正确后形成。不按固定日期承诺完成，阶段是否结束由验收证据决定。

## 3. P1：建立迁移基线、包骨架和发布门禁

### 工作项

1. 记录 PTCG-Lab 起点提交、工作树变更和可用依赖；为后续步骤建立独立开发分支。已有用户修改不能清理、覆盖或自动纳入基线。
2. 生成本地 baseline 报告：现有 H2 五套预设、收藏构筑、卡图、同步发布、真实人机对局与历史回放。需要真实数据的测试单独标为资产依赖测试；没有合法匹配资产时标记缺项，不伪造通过。
3. 整理来源功能白名单和移植映射，逐项记录来源提交；未提交实现则用内容哈希快照。只复制经过检查的代码、原创测试及必要说明，不复制整个工作目录。
4. 创建目标包元数据和目录骨架；生产代码仍走旧路径，兼容接口暂不切换。选择唯一协议 schema 源，确定 Python/TS 生成器及其锁定版本。
5. 更新公开导出的目录和文件允许列表，覆盖新 pyproject、schema、Compose 和 Docker 文件。为原创合成测试数据设专属允许目录，继续拒绝现有第三方 fixtures。
6. 建立依赖边界检查、源码与制品敏感内容扫描、文档状态校验；扫描新增未跟踪文件，避免现有 audit 只检查已跟踪内容的盲点。

### 验收

- 原有本机服务没有重启；测试用单独数据库、资源缓存和空闲端口。
- 新项目骨架可独立构建最小包，导出源码能包含全部必要配置。
- 合成的“秘密/私人目录标记”测试证明制品白名单拒绝它们，错误输出不打印秘密正文。
- baseline 记录实际环境、测试范围和未覆盖项；公开摘要不含机器路径、私人卡组和账号信息。

### 回滚与范围

删除本阶段新增骨架/配置或回退相应提交即可，不涉及真实用户数据库。暂不改动任何规则效果、H2 策略、已冻结发布或研究运行状态。

建议拆分 PR：P1-A 基线及来源清单；P1-B 包骨架与依赖检查；P1-C 导出/审计门禁。

## 4. P2：提取共享规则和通信合同

P1 提交 `83e3fb2`；当前 P2-A 的变更、合同限制和本地验收见 [P2 实施记录](P2共享协议与规则核心实施记录.md)。P2-C 核心提取和显式兼容层已完成本地验收，见 [P2-C 记录](P2C核心提取与兼容层验收.md)。P2-D 专项验收已通过，详见 [验收记录](P2D等价与隔离验收.md)；未切换现有 APP。

### 工作项

1. 从当前 PTCG-Lab 提取 core/provider 接口，先保持既有行为。把纯查询、校验与本地收藏持久化分开；展示卡图和资源下载不进入核心。
2. 使用显式 RuleBundle/CatalogProvider，移除运行时对根目录路径、构建脚本位置、sys.path 和工作区可变文件的依赖。引擎资产须核验且固定版本，不能静默降级到未打补丁的上游。
3. 建立 protocol 的命令、本人视角、错误码、资源/能力协商、回放 schema；Python/TS 从同一输入生成。增加未知字段、过大输入、无效候选和不兼容主版本的测试。
4. 实现旧导入路径的薄兼容层，禁止出现两套继续各自演进的规则实现。兼容层只委托，不复制效果代码。P2-C 使用新 worker 显式旧名委托，原生产文件按哈希冻结保留；不在已运行的 APP 中热替换。
5. 记录新旧规则身份关系。旧执行发布保持不变，拆包后的新版本只用于明确的新局；不得仅修改历史摘要以使旧记录“通过”。
6. 审计随机状态、全局缓存、注册表和引擎补丁的多实例行为。训练专用 fork/search 接口放在单独适配层，不能扩大在线客户端权限。

### 验收

- wheel 在仓库外、无开发路径的干净环境中安装运行；服务器侧测试不安装 AI 或 GUI 依赖。
- 同一冻结种子、卡组和命令序列，新旧实现的规则状态/合法选项/两位玩家投影等价；对有意改变的 envelope 或身份字段逐项说明，不能忽略所有差异。
- 两局交错推进与单独推进的摘要一致；领赏、替补、检索和非回合方决策都有覆盖。
- 对手手牌、牌库顺序、奖赏内容、种子和私有恢复记录均不出现在未授权 DTO。
- 本地既有人机回归和规则回归通过；不以 UI 截图代替规则验证，不宣称 AI 棋力提升。

### 回滚

本地仍可切回旧导入/冻结运行时。新格式记录单独标识，旧程序不能错误读取。若规则有差异，留在测试分支定位，不用更新预期结果掩盖行为变化。

建议拆分 PR：P2-A 协议与合成夹具；P2-B 数据/资源 Provider；P2-C 核心 wheel 与兼容层；P2-D 等价与隔离验收。

### 工作项

1. 将研究环境房间、双人编排、授权、PostgreSQL schema 和恢复逻辑按清单移植到 online-server；删除对网页静态资源和本地单用户 API 的依赖。
2. 实现 v2 capabilities、游客设备会话、令牌刷新/撤销、控制权和限流。旧网页 v1 继续留在原服务，不修改它的 Cookie/Origin 约束。
3. 实现显式规则依赖与镜像启动配置；online-server 只加载批准的 ruleReleaseId。没有规则包时 readiness 失败，错误说明不泄露路径和凭据。
4. 移植双人卡组校验、房间版本、准备幂等、唯一开局任务、随机种子预先持久化和成员授权。
5. 固定短事务提交协议：双方帧、私有恢复数据、命令回执、定向 outbox 原子写入；先正确实现事件一致性，P6 再优化分发和吞吐。
6. 对已开局房间初始化失败、认输、服务恢复和技术中止给出明确状态。技术故障不自动算玩家输。

### 验收

- 仅通过 HTTP/WSS 的两个独立身份完成邀请、准备、完整自然终局、认输和私有回放；不依赖服务器 GUI。
- 并发准备只能生成一个 matchId；同 ID 同内容重试只提交一次，不同内容返回幂等冲突。
- 会话到期、撤销、刷新竞争、第三人访问、错误座位、非法选项均拒绝且不泄露私有状态。
- 强制重启 API/规则进程，已接受命令不丢失、未知提交可核对，种子和起手不能因重试重抽。
- `/api/battle`、收藏、更新、模型和训练接口均不存在；镜像不装 GUI/AI 依赖。

### 回滚

只停止专用测试 Compose 项目，新数据不合并回现有局域网库。数据库 migration 使用版本表，不能改已应用的历史 migration。测试部署不开放当前 80/443 或占用已有端口；外部部署属于 P8。

4. 实现显示目录/图片缓存按内容哈希与版本获取，支持缺图、离线已有图、增量更新与旧资源保留。不能从当前用户图片目录批量上传给服务器。
5. 本地待确认命令按服务器、身份和 matchId 隔离；重启后先核对原命令，再允许新提交。切换服务器不得串用令牌、卡组 revision 或游标。

### 验收

- 两台设备运行本地 APP，连接独立 API，完成房间码邀请和自然终局；任一方成为 PLAYER2 时显示和操作正确。
- 丢命令响应、断 WSS、刷新页面、APP 重启、多窗口接管和服务器换地址均有明确恢复行为。
- 浏览器看不到远程 refresh token；恶意网页不能通过本地桥接创建身份、读取凭据或代发操作。
- 外部图源不可用时对战继续；同一资源第二次展示命中本地缓存；纯 API 流量中不含图片和全量卡牌目录。
- 网络模式故障不阻塞本地收藏或人机练习，网络客户端不调用 AI advance。

### 回滚

新增网络入口可关闭；凭证和缓存与本地 SQLite 分离，移除功能不删除收藏、人机记录或旧运行时。对局结束前不强制清理仍在使用的资源版本。

## 8. P5.5：产品整合（P5 完成后实施）

1. **P5.5-A 统一宿主**：组合已有本地 API 与网络桥接，统一启动命令、回环端口、GUI origin、授权和后台生命周期；审查并调整迁移期文件冻结门禁，使本仓库人机功能可正常演进。
2. **P5.5-B 共用卡组**：两种模式使用平台已有卡组及冻结版本，网络模式自动校验/提交，不再要求手工 JSON；隔离本地版本与各服务器、身份、规则下的远端 revision。
3. **P5.5-C 共用资源**：通过本地资源适配层复用卡表、卡图和缓存，检查 printingId/engineId 和版本映射；远端仍为纯 API，不传卡图。

本机服务可以管理内部人机/规则执行进程；普通用户不启动第二个网络后台，也不启动远端 API/PostgreSQL。用户数据迁移须备份并可验证恢复；产品源码可重构，已归档规则和历史回放不能通过改摘要伪造兼容。完成后更新默认入口和组合发布清单，再开始 P6。

## 9. P6：多局调度与低配置优化

P6-A 已完成并提交，P6-B 已完成并提交，P6-C 已完成并提交，P6-D 常驻 worker 与缓存已完成并提交（`f7ce35d`），P6-E 冷热维护带权调度、字节预算、回放与清理预算及 HTTP/WSS 独立准入已通过完整验收，P6 总体 completed；子阶段与实测结果见 [P6 实施记录](P6多局调度与性能实施记录.md)。

### 工作项

1. 固定基线负载并记录 SQL 次数、连接创建、计算与重放耗时，避免凭主观感觉优化。
2. 引入有界数据库连接池；空闲连接不持有数据库事务。认证采用批量到期／撤销复核；仅在后续证明确有必要时引入有界缓存，不能取消实际帧读取与命令鉴权。
3. 用 durable outbox + 通知唤醒替换逐连接查库。全局补漏按游标批量读取；重连 snapshot 与 streamCursor 原子关联。
4. 实现按局 FIFO、跨局公平轮转、每用户/每局/全局准入预算。队列外等待不占数据库连接；超载明确返回可重试错误。
5. 工作进程数可配置，matchId 亲和分配。每进程轮流处理局，超时只终止对应进程；重放和普通命令分别预算，避免冷恢复长期占用所有计算槽。
6. 按内存水位及活跃时间管理缓存，结束局及时释放。淘汰后只能从已提交记录恢复；未提交候选不得成为下一步基线。
7. 提交后按本人 outbox 推送必要快照，并设置每连接发送字节预算；慢连接断开后按游标补齐或重取快照。P6 沿用完整快照 DTO，delta 编码和持久恢复记录追加化留待测量后另行设计。
8. P6-E 按热／冷／维护默认 2:1:1 调度，为已准入且未过期的可执行任务提供轮转机会，不保证过载请求都能执行。历史回放限制并发、速率与页大小；清理限制批量、频率与 SQL 时间，统计只保留固定聚合桶。HTTP、WSS、握手分别准入，传输上限由配置推导并保留连接余量；实际余量在 P7 压测验证，不能直接无限放开。

### 验收与回滚

按并发文档完成乱序、双重提交、两个 worker、冷缓存、杀进程、提交后断连、DB 不可用和慢客户端测试。优化前后同输入结果一致；逐项启用开关并保留基线指标。

队列策略、进程数、推送机制和缓存大小分开提交。数据库正确性约束不允许通过性能开关关闭；性能不达标时可以降低新局准入，不能回退到先响应后保存。
