## P6-A 起点审计

P6-A 开始时，本仓库每条规则命令启动一次独立子进程，重载规则并重放已提交记录；不是研究环境的常驻 32 局 LRU。WSS 每连接每秒查询一次本人 outbox 并复核认证；每事务原先新建 PostgreSQL 连接，且两条 schema/部署身份校验 SQL 不缓存。容量文档中的研究环境数字不冒充本仓库实测。

先建立观测再优化：数据库连接建立、获取等待、事务（含提交/回滚）及显式 `execute` SQL 次数/耗时；规则进程调用、规则加载、恢复与计算分别计时。指标只保留固定名称的计数、总时长、最大值及固定桶直方图，不保存样本队列、matchId/userId、SQL 文本、凭据或手牌。内部 BEGIN/COMMIT 不计入显式 SQL 数，网络端到端延迟与 IPC 开销不能当成规则 CPU 时间。规则子进程仅返回内部计时，父进程移除后才交给服务，计时不进入持久记录、摘要、回执或 DTO。

## 有界连接池

采用固定版本 `psycopg-pool==3.2.8`，复用现有 `psycopg==3.2.10`。生命周期：API 启动显式 open，min_size=0，按需建立连接；退出时 close，唤醒等待者。构造对象不连接数据库。一次性迁移/脚本 `Repository` 未 open 时仍使用短连接；长期工具通过上下文管理器显式持有并关闭池。

| 环境变量（前缀 `PTCG_ONLINE_V2_`） | 默认值 | 范围 |
| --- | --- | --- |
| DB_POOL_ENABLED | 1 | 0/1；0 使用有界 NullConnectionPool，不复用连接 |
| DB_POOL_SIZE | 4 | 1–32 |
| DB_POOL_WAITERS | 16 | 1–256，禁止 0 代表无限等待者 |
| DB_POOL_TIMEOUT | 1 秒 | 大于 0、不超过 5 秒 |

Compose 对应 `PTCG_V2_DB_POOL_*` 参数。连接池按 API 进程计数；部署仍保持单 API，不增加副本，也不把 max=4 当成整个部署数据库连接总预算。后台维护线程 1 个，额外空闲连接 30 秒后回收。获取池超时/等待队列满映射为现有 `CAPACITY_EXCEEDED`、HTTP 503、retryable=true；数据库故障仍为脱敏 `INTERNAL_ERROR`。不自动重试 SQL 写入；客户端使用原幂等请求恢复未知结果。

每次事务退出前完成提交或回滚，池中空闲连接不持有事务。schema 校验、成员授权、控制权、版本比较、原子回执与 outbox 提交保留。规则计算仍在数据库事务外。失效连接由池淘汰，当前失败请求不会伪装成功。驱动日志滤掉原异常文本，聚合指标保留错误次数。

连接池 API 行为依据 [Psycopg 官方连接池文档](https://www.psycopg.org/psycopg3/docs/api/pool.html)，本地对固定版本执行事务与生命周期回归，不仅依赖最新文档描述。

## P6-B：集中补漏与提交通知

基线提交 `5f1c16f`；新增服务版本 `0.6.0.dev2`，共享 core/provider/protocol、数据库 001—003 migration 和客户端协议均不变。范围限于推送调度；FIFO、公平准入、常驻 worker、缓存和发送字节预算仍在 C/D/E。

### 数据流和权限

- 每个 API 进程持有一个 `StreamHub`，只登记至多 `MAX_STREAMS` 条订阅元数据：内部键、令牌摘要、matchId、已发送游标、错误和一个合并唤醒事件。不保存跨连接快照或消息队列，也不持有数据库连接等待消息。
- 每轮以一个 SQL 查询所有订阅的令牌、会话和本人 `match_members.stream_cursor`；连同原有 schema／部署校验为 3 次显式 SQL。没有订阅时不查库。查询不读取 `matches.recovery`、`match_frames.snapshot` 或 `match_outbox.snapshot`。
- 订阅初次接入始终调用原有 `Matches.stream`；之后仅在游标变化时读取本人的 durable outbox。读取仍在事务内校验当前令牌、成员关系和游标归属，并保留现有锁。快照与游标保持一致；控制权事件即使 matchSeq 不变也会更新收件人游标。
- 批量查询是通知提示，不是授权缓存。访问令牌／会话到期、令牌轮换、撤销及成员不存在都会唤醒连接并返回原有错误。写命令、实际帧读取继续独立执行完整鉴权；数据库不可用时关闭受影响订阅，恢复后按持久游标重连。
- 扫描按每位收件人的最新游标比较，不引入提交前分配的全局序列水位，因此没有较早事务较晚提交而被水位跳过的问题。通知丢失、跨进程写入及 API 重启通过下一轮补漏或重连恢复。

### 唤醒与有界资源

`_publish`、发令牌／轮换及撤销在事务中标记变动；`Repository.db` 只有在成功提交并释放连接后发出本进程提示。回滚和只读事务不唤醒，不增加 SQL。线程间提示先合并再投递 event loop，扫描之间保留 50 ms 间隔，避免提示风暴；无通知时约每秒补漏一次。实际撤销发现时间还包括连接池获取和 SQL 执行时间，沿用现有超时预算，不承诺数据库阻塞时仍能在一秒内送达。

每条连接独立接收 ping 和发送更新；每次最多取 8 条 outbox，达到一页后继续补齐。保留每次发送 3 秒超时、15 秒心跳和每秒最多读取一条应用 ping 的节流；Uvicorn 入站队列仍为 2。慢消费者不阻塞全局扫描或其他消费者；游标只在成功发送后前移。积压超过 outbox 保留范围时返回 `RESYNC_REQUIRED`，客户端重新取得快照。完整发送字节／回放预算留到 P6-E。

API lifespan 启动和停止 Hub，退出时清除订阅并解除提交回调；Hub 不新增常驻数据库连接。当前部署仍为单 API 实例；其他写进程只能由周期补漏发现，不声称已实现多副本跨进程实时通知。

### 开关与验证方法

默认 `PTCG_ONLINE_V2_STREAM_HUB_ENABLED=1`，Compose 使用 `PTCG_V2_STREAM_HUB_ENABLED`。仅接受 `0/1`；设为 `0` 并重启本次独立部署，即恢复原来的每连接每秒轮询。两种模式使用相同的持久游标、身份校验、错误和快照合同，无需变更数据库或回退数据。

新增用例覆盖成功提交才唤醒、回滚不唤醒、通知缺失补漏、他人游标拒绝、令牌与会话过期、撤销、成员隔离、数据库失败关闭、慢消费者隔离、生命周期清理以及轮询回退。既有完整服务回归继续验证控制权、游标截断、真实自然终局、HTTPS/WSS、进程死亡、未知响应与私有回放。

固定空闲微基线使用同一场原创合成对局，分别注册 1／8／32 条订阅、执行 10 轮检查，对比相同游标的旧 `Matches.stream` 轮询。不发送网络数据、不计算规则、不模拟 32 个真人或 32 场独立活跃对局，因此不能作为容量验收。

## P6-C：按局队列、公平轮转与分层准入

基线提交 `3ca9ca0`；服务版本 `0.6.0.dev3`，数据库 migration、共享规则包与线上协议不变。当前仍是单 API、单规则执行通道，每次规则调用仍启动受限子进程；常驻 worker、代次隔离和冷热缓存留到 P6-D。

### 准入、排队和提交

1. HTTP 边界继续限制请求大小、在途数与持久速率。命令入队前使用当前令牌查成员和同用户持久回执；这一步不读取 recovery 或快照，也不锁住对局等待。已有同内容回执直接返回，不受计算队列满、计算进程暂不可用影响；同 ID 不同内容冲突。
2. 内存去重键为 `(matchId, authenticatedUserId, commandId)`，内容摘要包含完整命令与 controllerId。相同在途请求共用一次执行，不重复占据任务槽；不同内容立即返回 `IDEMPOTENCY_CONFLICT`。每个等待者先鉴权，返回结果前再次鉴权并读取自己的持久回执，不能靠另一个会话的成功结果绕过到期或撤销。
3. 每局采用 FIFO；每轮只取一个任务。正在执行的对局若又有排队任务，完成后回到就绪队列尾部，排在已就绪的其他局之后。排队只持有请求闭包和 Future，不占 SQL 连接或线程池工作线程，不预加载隐藏规则状态。
4. 真正轮到执行时，原 `Matches.command` 重新读取已提交基线并执行原有鉴权、控制权、版本和合法选项检查。计算后再复核，原子提交恢复记录、双方私有帧、回执和 outbox；队列不能替代数据库约束。
5. 认输、控制权接管和内部技术终止继续通过已有短事务及时处理，不等待慢规则计算。它们可能使正在执行或排队的命令失效，旧命令在执行／提交时得到原有错误，不产生第二次推进。

执行者使用最早进入的有效请求身份。若该会话后来撤销，合并请求会一起收到该次执行的失败；不会自动换身份重新计算。调用方可用原 commandId 查回执或重新提交，持久幂等规则继续有效。

### 单规则通道与公平范围

卡组校验、开局初始化、初始投影与重新探测规则进程同样进入该调度器，避免它们从旁路争抢单个 worker 的非阻塞锁。卡组任务按已认证用户分组，后台任务使用独立内部组；初始化和投影分别占一个轮转机会。后台任务未轮到就超时，不会先领取 SQL 初始化 lease 或消耗初始化重试次数。

公平性覆盖就绪且未过排队期限的任务，不是 CPU 抢占。单次规则子进程仍有原有 20 秒超时；它运行期间其他任务可因排队预算耗尽而得到可重试 503。当前只证明轮转顺序和资源有界，不声称已实现多 worker 吞吐、长局低延迟或冷恢复的带权调度。

### 默认预算与回退

服务变量前缀为 `PTCG_ONLINE_V2_`；Compose 对应 `PTCG_V2_`。

| 后缀 | 默认 | 有效范围／含义 |
| --- | --- | --- |
| COMMAND_QUEUE_ENABLED | 1 | 0/1；0 回到原直接调用路径 |
| COMMAND_QUEUE_TOTAL | 32 | 1–256；执行中与排队的不同任务总数 |
| COMMAND_QUEUE_PER_MATCH | 2 | 1–16；每组一条执行加一条排队起步 |
| COMMAND_QUEUE_PER_USER | 4 | 1–32；同用户跨对局及卡组任务合计 |
| COMMAND_QUEUE_WAITERS | 64 | 1–512；所有原请求与合并重试等待者合计 |
| COMMAND_QUEUE_DUPLICATES | 4 | 1–32；每个任务最多 4 个等待者，含原请求 |
| COMMAND_QUEUE_SECONDS | 2 秒 | 大于 0、不超过 10；只限制未执行的排队等待 |

后台组也计入全局预算。每组上限同样应用于某用户的卡组校验组；不同组的任务仍共用每用户上限。预算满或排队超时返回 `CAPACITY_EXCEEDED` / 503 / retryable=true。计时器在超时移除排队任务，执行前再次检查期限，避免事件循环繁忙导致迟到计时器放行。

所有等待者离开时，尚未执行的任务立即移除；已经执行的任务继续到成功提交或明确失败，不能因 HTTP 断连提前释放规则通道。关闭服务拒绝新任务、清除排队者，并等待当前有界操作退出；重启后通过持久回执和 outbox 恢复，不恢复内存队列。失败和完成均释放任务、用户和组计数。新增指标只记录固定名称的接收、合并、拒绝、排队耗时、过期和取消数量，不输出身份或命令内容。

设 `COMMAND_QUEUE_ENABLED=0` 并重启该独立部署可回退；不会关闭数据库鉴权、幂等和提交检查。`MAX_INFLIGHT` / Uvicorn 长连接准入仍沿用既有规则，拆分连接与 HTTP 预算留到 P6-E。

## P6-D：常驻规则进程、代次屏障与已提交缓存

基线提交 `691fc0a`；服务版本 `0.6.0.dev4`。core/provider/protocol 和数据库 migration 不变。仍为单 API 部署，默认一个规则进程，可显式配置两个。每个进程只执行一个任务，规则包按批准摘要加载一次；不增加引擎线程并发，不共享生成器对象。

### 亲和与串行边界

调度器按稳定 SHA-256 将分组映射到执行通道；同一 matchId 的命令和初始投影使用同一个分组。各通道分别轮转其就绪分组，同局仍为 FIFO。卡组校验和初始化也经过调度通道，不绕过 worker 锁。两个通道可同时推进不同局；同一通道中的慢任务仍会影响该通道的其他局，单 worker 模式仍会短暂阻塞所有规则任务。当前没有抢占和工作窃取。

每个 worker 使用独立私有管道，输入上限 16 MiB、输出上限 8 MiB；每轮校验父进程生成的代次与递增请求序号。规则包目录、批准摘要和规则身份在一个代次内固定。子进程只接收白名单环境变量，不接收数据库凭据，不开放网络接口。父进程为管道读写设置 20 秒截止时间；异常、EOF、超时或错误代次均终止并回收该子进程。父进程死亡后子进程看门狗退出。下一请求从 SQL 已提交记录恢复，另一通道不被同步重启。

### 缓存不能先于提交

缓存键包含 matchId 与**完整规范化 recovery 的摘要**，不是仅比较 stateDigest。命中仍以服务刚读取的持久记录为基线；恢复配置被修改时不能复用旧实例。当前冷热请求均传输完整 recovery；减少 IPC 和长记录存储成本仍需独立实现与验收。

命令取走已提交缓存并产生最多一个待确认候选，候选不会立即成为下一命令的基线。父进程执行原有授权、版本和合法性复核，将 recovery、双方私有帧、回执及 outbox 原子提交；**事务退出后**才发送确认。确认必须同时匹配进程代次、候选票据、matchId 和完整记录摘要。确认失败不改写已成功的 SQL 结果；下一次按持久记录冷恢复。回滚显式丢弃候选；丢失确认、旧确认或进程退出不能推进局面。私有票据和内部计时不会进入 DTO、回放或 recovery。

缓存采用 LRU、闲置回收、条目数与序列化恢复记录字节预算。终局不保留缓存。记录字节不是 Python 对象图大小；另按进程峰值 RSS 水位决定在本次结果返回后回收整个进程。RSS 是采样回收条件，不是硬内存限制；硬限制仍依赖部署容器。峰值不会因释放对象下降，所以越过水位后重启才能清零。每个 worker 最多额外持有一个待确认候选，亦受闲置期限限制；管道上限约束单条记录，不等于引擎对象的硬大小上限。

### 默认预算与回退

服务前缀 `PTCG_ONLINE_V2_`，Compose 对应 `PTCG_V2_`。

| 后缀 | 默认值 | 有效范围／说明 |
| --- | --- | --- |
| WORKER_PERSISTENT | 1 | 0/1；0 回退每次独立子进程 |
| WORKER_COUNT | 1 | 1–2；重启后生效，回退模式固定单通道 |
| WORKER_COLD_LIMIT | 1 | 1–worker 数；全局同时冷恢复任务上限 |
| WORKER_CACHE_ENTRIES | 8 | 0–64／worker；0 禁用缓存，保留常驻加载 |
| WORKER_CACHE_RECORD_BYTES | 8388608 | 1024–67108864／worker；序列化记录预算 |
| WORKER_CACHE_IDLE | 60 秒 | 大于 0、不超过 600；闲置回收 |
| WORKER_RSS_MB | 256 | 64–1024／worker；进程回收水位 |
| WORKER_RESTORE_SECONDS | 10 秒 | 大于 0、不超过 20；冷恢复时间预算 |
| WORKER_COMPUTE_SECONDS | 5 秒 | 大于 0、不超过 20；命令／初始化时间预算 |

冷恢复许可证从恢复前一直持有至该次计算结束；热命中不占许可证。满额立即返回可重试 `CAPACITY_EXCEEDED`，不会持有数据库连接等待。冷热检查之间若缓存过期，拒绝该次执行并清理该 worker，不能绕过冷恢复准入。恢复与计算分别有子进程闹钟，父进程另负责 IPC 截止时间；超时返回规则暂不可用，不能判玩家失败或重抽种子。

这是保守的冷热准入实现：尚未实现设计目标中的带权冷热队列，不保证持续过载下冷任务无饥饿。该项明确纳入 P6-E 的调度预算收尾，在 P7 混合冷热容量测试前处理；P6-D 只验收并发上限、热任务可绕过被占用的冷预算和错误可重试。全记录 IPC／追加记录存储优化维持后续专项，不计作已完成收益。

设 `WORKER_CACHE_ENTRIES=0` 可单独停用缓存；设 `WORKER_PERSISTENT=0` 回退原来一次一进程的执行方式。两者均需要重启本次部署，无需数据库迁移。`COMMAND_QUEUE_ENABLED=0` 仅关闭排队，不关闭 worker 并发锁与持久提交屏障。

## P6-E：带权调度与资源预算

基线提交 `f7ce35d`；API 版本 `0.6.0.dev5`，客户端维持 `0.5.0.dev6`。共享 core/provider/protocol、001—003 migration 与对外 DTO 不变。沿用完整私有快照和原子提交，没有新增 delta 编码、帧合并或规则 checkpoint，也没有把显示快照当作恢复状态。

### 冷热调度和维护隔离

每条规则通道按热任务／冷任务／维护任务默认 **2:1:1** 轮转，各局内部仍为 FIFO。分类只查看父进程中有界的缓存提示：matchId、worker 代次与最近确认时间；不加载规则状态。子进程仍核验实际已提交记录；提示失效时清除提示并执行受限冷恢复，冷许可证不足返回可重试错误，不自动重新执行命令。丢失提交确认或进程死亡后只能从 PostgreSQL 的已提交基线恢复。

跨空闲通道的冷任务按就绪顺序取得全局冷恢复名额；忙通道不能预占名额，其他通道的热任务仍可运行。维护类包括规则探测、开局初始化和初始投影，最多同时存在 2 个维护任务（执行加排队），同时受原全局队列上限约束。无饥饿范围是已准入、未过期且具备执行条件的任务；不承诺 CPU 抢占或过载时每个请求都执行。排队超时／取消会释放配额并唤醒相关通道。

`WORKER_WEIGHTED_ENABLED=0` 回到 P6-D 的跨局轮转策略，保留维护准入上限；`COMMAND_QUEUE_ENABLED=0` 回到直接调用，worker 最终许可证及数据库正确性检查继续有效。开关只接受 0/1，修改后重启对应独立部署。

### HTTP、WSS 与发送

HTTP 在途、WSS 总连接、未完成订阅的 WSS 握手各自计数。Uvicorn 总上限由 `MAX_INFLIGHT + MAX_STREAMS + CONNECTION_RESERVE` 推导，保持有限。余量用于传输层连接和 keep-alive，不是额外命令槽；真实生产入口测试覆盖 HTTP 上限 1、WSS 上限 2，双方订阅占满后命令仍能提交并推送。

每条 WSS 使用独立字节令牌桶，发送前检查单消息大小，等待补充令牌最多 1 秒，然后沿用 3 秒发送超时。等待后重新鉴权，集中订阅发生撤销错误时停止发送。小于等于 4 KiB 的错误和心跳保留控制消息额度，包含快照的控制事件仍计入正常预算。发送或预算失败会报告现有错误并断开，只有成功发送才推进游标；重连读取持久 outbox，超出保留范围则按原合同重取快照。关闭连接也有 3 秒超时，失败和取消释放握手、连接和预算对象。

字节值指紧凑 UTF-8 JSON 载荷，不包括 TLS/TCP 开销，不是 Python 堆内存硬上限，也不是全服务带宽 SLA。每连接仍只有顺序发送者和有界读取页，没有无界待发队列。总内存和带宽需在 P7 结合连接数、页大小、完整快照大小及规则进程水位测量。

### 回放、可见读取与清理

- 回放请求独立限并发与持久速率。并发上限为 `min(REPLAY_INFLIGHT, max(1, MAX_INFLIGHT-1))`；默认回放最多占 2 个 HTTP 槽。`MAX_INFLIGHT=1` 时只能串行，不承诺额外预留槽。速率按可信连接对端地址的摘要及全局两级限制，不信任 forwarded headers，也不是按用户计数。回放预算先检查，已被回放配额拒绝的请求不会再消耗普通命令额度；获准回放仍受普通总配额约束。
- 回放／outbox 先读取有上限的游标和快照字节元数据，再读取可容纳的连续前缀。回放每页最多 3 帧、outbox 最多 8 帧；JSON 封装保守预留后再次检查精确输出大小。页未满但仍有数据时继续补漏，保留本人游标与隐藏信息隔离，绝不静默跳过帧。单帧超过预算明确拒绝，需调整预算才能读取。
- 展示、回执、回放与推送鉴权只读取对局所需元数据，避免连带加载整份规则恢复记录；身份、成员授权和原一致性行锁保留。非空历史页增加一次元数据查询，空闲扫描的 P6-B 查询次数结论不改写。
- 清理为单个后台循环，不与规则任务共用执行通道。每轮在一个事务内分别清理至多 `MAINTENANCE_BATCH` 条过期限流键、过期访问令牌和过期 waiting 房间，默认合计最多 192 条。使用 `FOR UPDATE SKIP LOCKED` 跳过竞争行；限流读改同样持有行锁，避免被清理删掉后漏记请求。前台限流清理也有批量上限，未被批量触及的过期键会在使用时正确重置。
- 清理 SQL 默认各自 1 秒超时，每轮结束后等待 10 秒；原事务的 schema 校验仍使用既有超时，这不是整个维护事务 1 秒的保证。停止时排空循环再关闭连接池。保留刷新令牌重用检测历史、对局帧、回执、恢复记录及已开局房间，不执行历史压缩或数据库灾难恢复。
- 统计继续只有固定名称的计数／耗时桶，不保存身份或逐请求样本；没有新增统计查询服务。

### 新预算参数

环境变量前缀 `PTCG_ONLINE_V2_`；Compose 对应 `PTCG_V2_`。原 HTTP／流数量、队列、冷恢复和缓存参数继续有效。

| 后缀 | 默认 | 有效范围 |
| --- | --- | --- |
| WORKER_WEIGHTED_ENABLED / WORKER_HOT_WEIGHT | 1 / 2 | 0/1；热权重 1–8，冷／维护权重各 1 |
| CONNECTION_RESERVE / STREAM_HANDSHAKES | 8 / 8 | 各 1–64 |
| STREAM_MESSAGE_BYTES | 1 MiB | 4 KiB–2 MiB，且不超过突发／页预算 |
| STREAM_PAGE_BYTES | 2 MiB | 4 KiB–8 MiB |
| STREAM_BYTES_PER_SECOND | 1 MiB | 1 KiB–16 MiB |
| STREAM_BURST_BYTES | 2 MiB | 4 KiB–16 MiB |
| STREAM_BUDGET_WAIT | 1 秒 | 大于 0、不超过 3 秒 |
| REPLAY_INFLIGHT | 2 | 1–16；还受 HTTP 总槽位约束 |
| REPLAY_PAGE_BYTES | 1 MiB | 4 KiB–2 MiB |
| REPLAY_PER_MINUTE / REPLAY_GLOBAL_PER_MINUTE | 120 / 360 | 各 1–10000 |
