## 当前基线审计

本仓库目前每条规则命令启动一次独立子进程，重载规则并重放已提交记录；不是研究环境的常驻 32 局 LRU。WSS 每连接每秒查询一次本人 outbox 并复核认证；每事务原先新建 PostgreSQL 连接，且两条 schema/部署身份校验 SQL 不缓存。容量文档中的研究环境数字不冒充本仓库实测。

先建立观测再优化：数据库连接建立、获取等待、事务（含提交/回滚）及显式 `execute` SQL 次数/耗时；规则进程调用、规则加载、恢复与计算分别计时。指标只保留固定名称的计数、总时长、最大值及固定桶直方图，不保存样本队列、matchId/userId、SQL 文本、凭据或手牌。内部 BEGIN/COMMIT 不计入显式 SQL 数，网络端到端延迟与 IPC 开销不能当成规则 CPU 时间。规则子进程仅返回内部计时，父进程移除后才交给服务，计时不进入持久记录、摘要、回执或 DTO。

## 有界连接池

采用固定版本 `psycopg-pool==3.2.8`，复用现有 `psycopg==3.2.10`。生命周期：API 启动显式 open，min_size=0，按需建立连接；退出时 close，唤醒等待者。构造对象不连接数据库。一次性迁移/脚本 `Repository` 未 open 时仍使用短连接；长期工具通过上下文管理器显式持有并关闭池。

| 环境变量（前缀 `PTCG_ONLINE_V2_`） | 默认值 | 范围 |
| --- | --- | --- |
| DB_POOL_ENABLED | 1 | 0/1；0 使用有界 NullConnectionPool，不复用连接 |
| DB_POOL_SIZE | 4 | 1–32 |
| DB_POOL_WAITERS | 16 | 1–256，禁止 0 代表无限等待者 |
| DB_POOL_TIMEOUT | 1 秒 | 大于 0、不超过 5 秒 |

Compose 对应 `PTCG_V2_DB_POOL_*` 参数。连接池按 API 进程计数；部署仍保持单 API，不增加副本，也不把 max=4 当成整个部署数据库连接总预算。后台维护线程 1 个，额外空闲连接 30 秒后回收。获取池超时/等待队列满映射为现有 `CAPACITY_EXCEEDED`、HTTP 503、retryable=true；数据库故障仍为脱敏 `INTERNAL_ERROR`。不自动重试 SQL 写入；客户端使用原幂等请求恢复未知结果。

每次事务退出前完成提交或回滚，池中空闲连接不持有事务。schema 校验、成员授权、控制权、版本比较、原子回执与 outbox 提交保留。规则计算仍在数据库事务外。失效连接由池淘汰，当前失败请求不会伪装成功。驱动日志滤掉原异常文本，聚合指标保留错误次数。

连接池 API 行为依据 [Psycopg 官方连接池文档](https://www.psycopg.org/psycopg3/docs/api/pool.html)，本地对固定版本执行事务与生命周期回归，不仅依赖最新文档描述。

## 基线与验收方法

`tests/online_v2/test_p6_baseline.py` 在独立 PostgreSQL 上分别使用不复用／复用连接；每种重复 3 次，每次 5 场原创合成对局，每场 20 次双方空闲轮询、4 条有效命令及 4 次原请求重试，核对同样的终局、全部私有帧与隐藏信息隔离。只改变连接复用开关，连接/等待上限相同。未通过 HTTP/WSS 发送链路，也未使用真实规则计算，耗时结果仅衡量该固定服务/SQL 负载。

另用批准规则、固定种子和 5 步操作采集冷加载、恢复、计算指标；每步重新恢复并比较双视角，不导出牌组或恢复记录。完整 P4-D 回归继续包含自然终局、HTTPS/WSS、真实进程死亡、撤销/过期、镜像隔离。保留既有 schema、core/provider/protocol 版本，新增服务版本为 `0.6.0.dev1`。

未启用认证缓存、集中推送、公平队列、常驻 worker、热缓存或缩小帧等优化，不将 SQL 连接建立减少描述为已经解决空闲轮询成本。旧版本和新版本采用相同数据库 schema，可通过 DB_POOL_ENABLED=0 回退连接复用，或回滚 API 镜像；任何回退都不回退持久化正确性检查。


## P6-A 验收结果（2026-10-27）

- `ptcg-online-server==0.6.0.dev1`；隔离镜像 `ptcg-lab-online-api:p6a`，镜像摘要 `sha256:9be5a98f9b167f74f093302d29d4c926ac0cd2fda5f4ed9169be1d9255696ff5`。构建完成但未部署到既有 LAN。
- 完整独立服务验收 **120 项通过、无跳过**，包括原有自然终局、HTTPS/WSS、真实进程故障、提交回执、撤销与过期、私有投影，以及新增连接池、计时与 A/B 负载。
- 专用 PostgreSQL 17 容器限额为 1 CPU / 512 MiB；API 与规则进程在 macOS 宿主运行，未限成整部署 2 vCPU / 2 GiB，不能形成 P7 容量结论。
- 每模式 3 个样本，每样本相同的 **300 个事务、3,040 次显式 SQL**；关闭复用建立 **300 次连接**，开启复用为 **1 次连接**。每 20 次空闲轮询仍需 **180 次 SQL**，因此 P6-B 仍有明确优化目标。
- 固定合成负载的总耗时中位数：不复用 **3.775 秒**，复用 **1.003 秒**。这是顺序服务/SQL 微基线，不含真实规则计算和网络端到端延迟。
- 另以批准规则执行 5 步，包含 15 次冷恢复与 6 次计算/初始化观测；恢复后的双视角与候选投影一致，内部计时不进入规则记录或服务输出。长局冷恢复、稳态负载与多人公平性尚未验收。
