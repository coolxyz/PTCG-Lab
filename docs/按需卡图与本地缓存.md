# 按需卡图与本地缓存

默认不下载全卡库，也不需要 Git、GitHub Token 或资源 ZIP。App 提供固定版本的轻量图片索引，只有实际显示卡图时才由本机后台下载原图，验证后保存在用户资料目录。资料库、人机练习和网络对战共用这些本地地址与缓存；对战 API v2 不承载卡图流量。

## 使用

安装本版后直接打开资料库或对战即可。“数据与对战更新 → 在线卡图与本机缓存”显示图片索引数量、缓存数量与已用空间，可展开“图片来源与缓存设置”修改来源和额度。默认 GitHub Raw、1 GiB 在线缓存，可选择 256 MiB、512 MiB、1/2/4/8 GiB。点击“保存设置并刷新卡图”生效。

未缓存图片需要联网；已缓存图片可离线使用。空间不足时按近期使用情况淘汰在线缓存，之后再次显示时重新下载。不会清理用户上传卡图或已安装 ZIP 资源。Raw 仍可能被 GitHub 限流；遇到限流或网络错误会退避，现有图片继续可用，待倒计时结束点击“重试显示卡图”。不会循环高频请求。

优先级：用户上传卡图 → 当前启用的 ZIP 中对应条目 → 本机已有的批准同步快照 → 随包精确图片索引 → 占位。ZIP 未覆盖的卡牌仍可使用在线缓存，不必将全卡库打成一个 ZIP。ZIP 原有的摘要、身份、大小限制及手工安装/启用流程保留；Git 卡图打包工具仍可作为可选离线工具，其外部 Git 缓存不自动导入 App。

## 静态图源/CDN

将来源选为“静态图源 / CDN”，填写无凭据、无查询参数的 HTTPS 基础地址。例如基础地址为 `https://images.example.org/ptcg`，图片将从下列结构获取：

```
https://images.example.org/ptcg/<仓库所有者>/<仓库名>/<40位固定提交>/<原图片路径>
```

图源需保留原始文件字节；不能自动转码、压缩重写或以 HTML 占位图代替缺失图片。App 会检查固定 Git blob 身份、SHA-256 缓存身份、图片格式、大小和完整解码。改变来源不会改变卡牌规则或内容哈希，也不必重下已缓存的相同图片。不跟随下载重定向；HTTPS 证书正常验证，自定义静态图源必须解析到公开地址；默认的固定 GitHub Raw 域名使用正常主机名 TLS 连接，支持本机 VPN 的虚拟 DNS，证书和内容哈希仍完整校验。配置存放在当前用户的 `app.sync/artwork-settings.json`，浏览器不会接触远程凭据。

## 实现边界

- 随包索引：`resources/artwork/builtin-index.json`，固定源提交 `3f9648f364caa750a18b56bb8e9d562c4c17689f`。按批准内置卡表精确匹配 12,931 项；26 项牌面歧义不自动选图，保持现有展示或占位。索引只含 printingId、engineId、路径和 Git blob，约 1.7 MiB，不含全库图片或新规则。
- 图片经 `raw.githubusercontent.com`，不逐图调用 GitHub REST blob/tree API。卡表更新仍使用原有独立的数据同步流程及审核门禁；同一功能不会隐式替换规则。
- 本机不可变地址 `/api/sync/artwork/<索引条目摘要>` 与同步图片地址都经过同一内容缓存，单图最多 8 MiB、2000 万像素。并发下载最多两个，同图合并请求；失败保留短期退避。请求在异步队列中等待，避免占满卡表及对战命令使用的线程池。
- 图片响应支持私有不可变浏览器缓存；设置与失败响应不缓存。缓存对象按 SHA-256 命名并原子写入，损坏时拒绝展示并从固定源修复。既有有效同步图片缓存保留；ZIP 资源仍由原有不可变资源管理器管理。
- 图片下载与卡表/图片身份索引分开；读取元数据不会预取图片。新安装包中旧资料链接指向尚未安装的同步快照时，使用匹配的随包图片索引；本机真实存在的批准同步快照优先。

## 维护索引

开发者在已有的固定 Git 对象缓存上运行，无需下载全图：

```sh
python -B scripts/product/build_image_index.py \
  --catalog <批准资产目录>/data/catalog/catalog.json \
  --cache <专用Git缓存目录> \
  --commit <完整固定提交> \
  --output <新的索引JSON路径>
```

检查未匹配条目与索引差异后更新随包索引。生成器不覆盖已有输出、不修改用户资料。两个平台的打包器都会再次将索引绑定到所选批准卡表的文件摘要和 engineId；来源摘要覆盖该索引。App 运行时无需 Git，也不执行任何上游文件。

## 备份与更新

在线缓存可重新下载，但要完整保留离线状态和设置，需要在关闭目标后台后备份整个实际 profile/同步目录。原生 C3 整套备份会包含这些资料；旧 `scripts/sync/run.py backup` 是局部同步导出，尚不自动覆盖新增 artwork/display 目录和 artwork-settings.json，不应当作完整离线/身份备份。安装新 App 不自动清除已有上传、ZIP 或缓存，目录/凭据迁移按[使用手册](启动使用与跨系统迁移.md#备份恢复与升级)执行。
