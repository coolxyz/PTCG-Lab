## 2. Wire 合同及边界

- **Command**：commandId、expectedMatchSeq、expectedStateVersion、controllerEpoch、decisionId、choice。choice 必须恰为 optionId 或 selectedRefs 之一；不能自报 seat、伤害、卡牌元数据或局面补丁。
- **DeckSubmission**：只接受 printingId/quantity、规则身份、请求 ID 和可选名称。拒绝重复条目、非整数和不合 60 张的提交；这不是赛制/效果准入，基础宝可梦与同名上限等由 P2 的 CatalogProvider/规则层处理。
- **MatchSnapshot**：明确 viewerSeat、规则身份、四种互不替代的序号/游标以及可见局面。本人手牌为卡牌列表；对手手牌只能是 null；双方牌库/未公开奖赏只有数量。没有种子、完整牌库、恢复记录、引擎对象或可任意扩展的 raw 字段。
- **Decision**：options 与 selection 分开；只能给当前视角的行动者。隐藏候选仅有不透明 ref，不带名称、位置或搜索内容。可见搜索使用显式、无序的 DeckInspection，不能输出牌库顺序。
- **Capabilities**：精确支持版本列表、可开局规则身份、展示目录和资源清单版本、功能开关、开局准入及命令字节上限。当前只支持 `2.0`；未知主/次版本都拒绝，不能静默按 v1 解析。
- **ProtocolError**：有限错误码、可选关联请求 ID 和 retryable，不携带自由格式异常、原请求、令牌或引擎日志。
- **ReplayPage**：`visible-replay-v2`、本人座位、规则身份、递增的只读帧和分页游标；无 decision、controllerEpoch 或 streamCursor。终局不会将对手隐藏资料自动解锁。

卡图、完整文字和卡牌下载地址留在本地展示目录。线上卡牌对象只传显示所需的身份和明确的可见状态。当前 CardState 是 P2-A 的最小合同，并非旧界面所有效果字段的无损替代；P2-C 保留完整旧可见投影；P2-D 须逐项完成可见效果、明示奖赏选择、事件动画到 v2 的无损映射并验证，才能接入 GUI。不能直接把旧 DTO 字段删除后称为等价迁移。

房间、会话、认证、流事件 envelope 与数据库错误映射由 P4/P5 在本协议体系内扩展，本阶段没有实现这些路由。

## 3. 校验与调用约定

```python
from ptcg_protocol.validation import decode, validate_command, ProtocolViolation

# kind 由固定端点决定，不能让请求指定任意 schema。
command = decode("Command", request_body_bytes)
# 调用方先完成认证、成员授权，以及已提交 commandId 的幂等查询。
# 若已有相同命令回执，应先返回回执，不因其旧版本而拒绝合法重试。
checked = validate_command(
    command,
    trusted_view=current_server_projection,
    authenticated_seat=member_seat,
)
# checked 仍需交给规则核心执行，并在持久化时再次比较版本/操作权。
```

decode 只接受 UTF-8 bytes，拒绝重复 JSON 键、NaN/Infinity、错误类型、超过安全整数范围的序号及不受支持的版本。整数不接受 bool、浮点数或字符串。validate 对进程内 JSON 值进行同样校验，返回脱离原对象的副本。

| 消息 | 最大 UTF-8 字节数 |
| --- | ---: |
| Command / DeckSubmission / Capabilities | 16,384 |
| ProtocolError | 4,096 |
| MatchSnapshot | 524,288 |
| ReplayPage | 2,097,152 |

另限制嵌套深度 32、节点 100,000、回放页 32 帧、候选 60、普通选项 2,048。传输层仍须在读取/解压请求体时限流限大小，不能先无界读入内存再调用校验器。这些是合同初始预算，不是性能测得的最优阈值。

运行依赖为 jsonschema 4.25.1 与 referencing 0.37.0，传递闭包在协议目录 requirements.lock；未修改旧 API 依赖锁。schema 从 wheel 本地资源读取，固定使用无远程获取器的 Registry。按官方 [JSON Schema 对象约束](https://json-schema.org/understanding-json-schema/reference/object)和 [jsonschema 引用机制](https://github.com/python-jsonschema/jsonschema/blob/main/docs/referencing.rst)使用封闭对象及本地引用。

结构校验不能识别“把秘密放进合法 text/name 字符串”的语义泄露，也不能证明实际引擎已正确过滤对手信息。当前例子只证明 wire 拒绝显式隐藏字段；P2-D 必须使用真实引擎的双方视角、选择及回放进行验证。

## 4. 本地验收与复查

在 PTCG-Lab 的独立工具环境安装，不使用人机或局域网服务环境：

```sh
python3.14 -m venv var/p2/tools
var/p2/tools/bin/python -m pip install -r scripts/migration/requirements.lock
npm ci --ignore-scripts
var/p2/tools/bin/python -m pip install --no-build-isolation --no-deps ./packages/battle-protocol
var/p2/tools/bin/python -m pytest tests/protocol tests/migration tests/portable/test_public_export.py -q
var/p2/tools/bin/python -m pip download --only-binary=:all: \
  -r packages/battle-protocol/requirements.lock --dest var/p2/wheelhouse
var/p2/tools/bin/python scripts/migration/gate.py \
  --build-output var/p2/new-build --dependency-wheelhouse var/p2/wheelhouse
```

新构建器在临时目录构建各包，在另一个全新 venv 通过离线 wheelhouse + 完整版本约束安装；从仓库外以 `python -I` 加载协议、校验九个样例，确认没有导入 APP、规则引擎、数据库或 AI。wheelhouse、报告和构建物均留在忽略的 var/p2，不随公开源码发布。

修改 schema 后运行 `scripts/protocol/generate.py`，检查生成差异；gate 会检查 Python/TS 漂移并编译 `tests/protocol/types.ts`。TypeScript 类型无法表达全部大小与互斥约束，运行时 JSON Schema 校验仍必需。
