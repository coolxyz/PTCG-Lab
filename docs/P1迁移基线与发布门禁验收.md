新增 3 个 npm workspace：desktop-web、battle-ui、battle-protocol/ts，版本 `0.0.0-p1`、private=true。根 workspace 不包含旧 apps/web，不改变其依赖解析和启动流程。P1 包仅导出“实现尚未就绪”的元数据，不提供伪造的 GUI、规则或在线能力。

项目清单与允许导入位于 [projects.json](../releases/projects.json)，阶段状态位于 [migration-status.json](../releases/migration-status.json)。初期只允许协议生成代码使用 typing 等明确列出的模块；P2 增加实际依赖时须同步更新合同、锁文件及测试。

唯一手写协议示例位于 `packages/battle-protocol/src/ptcg_protocol/schema/scaffold.schema.json`，采用 JSON Schema 2020-12。它只是 P1 构建元数据，不是对战协议 v2。Python TypedDict 和 TypeScript 类型均生成，禁止手工维护第二套 schema。

生成工具固定为 datamodel-code-generator 0.35.0、json-schema-to-typescript 15.0.4；Python 生成目标语法为 3.12（运行环境仍为 3.14），禁用时间戳。Python 工具依赖闭包在 scripts/migration/requirements.lock，Node 工具及传递依赖在根 package-lock.json。类型生成不等于运行时输入验证，实际命令 schema 和验证留在 P2。

## 5. 发布门禁

- source_files 与 audit 共用 deny-first 策略。新增项目配置、源码、schema、精确登记的合成 JSON、Docker/Compose 及 CI 文件可进入公开包。
- 用户数据目录、第三方 fixtures、构建目录、环境文件、私钥、凭据目录等继续排除；符号链接与越界路径拒绝。
- 扫描同时覆盖 tracked 与未忽略的 untracked 文件；忽略的私人运行状态不作为公开候选，也不把它读进报告。
- 导出前扫描秘密模式和本机绝对路径，错误仅返回相对位置与类别；完成 ZIP 后再校验路径、文件集合、逐文件 SHA-256、清单本身和重复条目。
- Python/JS 依赖及阶段合同检查只覆盖新 P1 包。它是静态架构门禁，不是通用恶意代码沙箱；P2 引入真实功能时需扩展检查和运行时合同测试。
- 构建器在临时目录按明确输入生成 wheel/sdist/npm 包，检查许可、成员路径和内容；wheel 的验证环境没有仓库路径与 editable 安装。
- 已配置 `.github/workflows/publication-gate.yml`，只需要公开源码与合成数据，不启动产品或加载真实卡池；不上传原始日志、用户数据或制品。

已有 Git 历史仍由 audit --history 单独检查；当前源码门禁不等于对整个历史或第三方授权的全面证明。发布前仍按原开源流程复核最终内容。

## 6. 复查命令

在 PTCG-Lab 根目录使用独立工具环境；Windows 使用对应的 Python/venv 路径。

```sh
python3.14 -m venv var/p1/tools
var/p1/tools/bin/python -m pip install -r scripts/migration/requirements.lock
npm ci --ignore-scripts
var/p1/tools/bin/python -m pytest tests/migration tests/portable/test_public_export.py -q
var/p1/tools/bin/python scripts/migration/gate.py --build-output var/p1/recheck-build
```

构建输出目录必须是新目录，不覆盖已有制品。协议修改后先运行 `scripts/protocol/generate.py`，审核生成差异；门禁中的 `--check` 只检查，不自动修复差异。

单独导出与检查：

```sh
var/p1/tools/bin/python scripts/public/export_source.py --output exports/p1-source-check.zip
var/p1/tools/bin/python scripts/public/audit.py --check --artifact exports/p1-source-check.zip
```

本地迁移基线工具不启动服务：

```sh
var/p1/tools/bin/python scripts/migration/baseline.py --output var/p1/new-baseline
# 需要真实产品基线时，仅使用已有、可信、兼容资产：
var/p1/tools/bin/python scripts/migration/baseline.py \
  --output var/p1/new-app-baseline --stage-app --with-runtime-assets
```

在生成的 app 副本内安装原运行依赖后，复查本次 Python 测试选择：

```sh
PYTHONPATH=runtime/engine:.:tests/rules python -m pytest \
  tests/collection tests/catalog/test_card_details.py tests/api/test_h2_experts.py \
  tests/battle/test_h2_presets.py tests/battle/test_service.py \
  tests/sync/test_runtime_release.py tests/portable/test_public_export.py -q
```

浏览器基线选取 battle.spec.ts、card-artwork.spec.ts、h2-experts.spec.ts、replay.spec.ts、workflows.spec.ts；配置独立数据库、空闲端口和指定测试解释器，不复用现有服务。该环境的实际配置保存在私有 baseline-app 副本，公开文档不附带机器绝对路径。
