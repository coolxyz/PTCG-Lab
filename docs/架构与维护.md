# 产品架构与维护

## 运行边界

- `apps/web`：资料库、收藏、构筑、更新与产品导航；生产构建接入共享练习界面。
- `apps/desktop-web`：人机练习与网络大厅/对局客户端。`packages/battle-ui` 提供统一桌面、公开过程记录与回放。
- `apps/api`：本机产品 API 与练习服务；`apps/desktop-api` 负责同源授权、网络身份桥接、原生 IPC 和私有资料目录。
- `apps/native-shell`：Tauri 2 原生窗口，启动/回收自身后台，macOS Keychain、Windows DPAPI/ACL、管道与 Job Object 约束。
- `apps/online-server`：纯 API v2，对局权威裁定、房间邀请、身份认证、私有推送与回放；PostgreSQL 保存版本化命令、事件和恢复记录。不传输卡图，不包含训练功能。
- `packages/battle-protocol`：Python/TypeScript 协议及权限投影；`engine-provider`：受 pin 约束的规则输入；`battle-core`：独立共享规则执行；`online-client`：连接、命令幂等和恢复。
- 根 `packages/rules`、`battle`、`collection`、`simulation`、`sync` 等仍是本机产品依赖。名称中含 simulation 的模块也支持现有人机与规则验证，不能当作可删除的研究目录。

## 数据与规则

公开源码保留卡图精确索引，完整卡表、效果资产、引擎运行文件独立提供。打包器显式接收批准资产，验证卡表与索引的绑定；不从用户 profile 或邻近工作树自动寻找资源。

资料收录、图片展示与规则可用分别处理。图片走本机 Raw/CDN 缓存或离线 ZIP。规则更新需经过机制审核、测试与发布，卡图包不能授予对战能力。仅执行当前批准规则；运行身份和内容哈希变化时拒绝不匹配的旧局恢复，保留授权范围内的只读历史帧。

## 多局并发

API 的排队、数据库连接、流订阅、回放分页和 worker 内存均有界。每局使用独立身份、版本与幂等键，命令在持久化提交后广播。进程缓存不是持久化真相，worker 恢复仍核对规则身份和记录完整性。调度、公平性及资源预算配置见 `ops/online/compose.yaml` 和服务配置源码；容量上限需要针对最终机器和镜像测量，不能按本机开发阶段报告承诺。

## 构建与回归

`npm run product:build` 同时构建主界面与网络对局界面，解析当前工作区源码，避免意外打入另一个工作树的旧包。`scripts/native/layout.py` 列出随包数据与内部项目，`scripts/public/policy.py` 控制公开源码边界。

`scripts/packaging/source_identity.py` 对允许发布的完整当前源码计算摘要，构建、审计与平台验证统一使用，不依赖开发阶段报告。更改产品源码后需重新生成候选证据，不能复用旧产物摘要。必要回归测试源码保留在 `tests/`，生成结果、真实卡组和测试数据库均不提交。

main 不含开发过程文档与环境副本；完整过程保留在开发分支。构建、安装迁移与具体用户操作分别见 [构建与发布](构建与发布.md)、[安装升级与迁移](安装升级与迁移.md)、[使用手册](启动使用与跨系统迁移.md)。
