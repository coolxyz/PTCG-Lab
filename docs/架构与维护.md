# 架构与维护

React/TypeScript 前端位于 `apps/web`，FastAPI 服务位于 `apps/api`，SQLite 保存收藏、卡组、会话与对局。日常使用根启动脚本。

| 路径 | 职责 |
| --- | --- |
| `packages/collection` | 目录领域逻辑、收藏、卡组、图片和持久化 |
| `packages/rules`、`packages/engine_adapter` | 规则执行和引擎适配 |
| `packages/battle` | A1、对战服务、合法选择与运行时 |
| `packages/simulation` | 效果注册、安全分叉、回放事件、A2 原型 |
| `packages/cardpool` | 目标卡池准入、机制支持和训练导出辅助 |
| `packages/sync` | 上游同步、身份与卡面映射、不可变发布和进程隔离 |
| `data`、`rulesets` | 版本化目录、映射、效果及规则 |
| `runtime/engine` | 核验后的第三方生成引擎及许可证 |
| `artifacts/engine/overlay-hashes.json` | 运行时必需的引擎完整性清单 |
| `.catalog/sync/releases` | 对局引用的冻结执行版本 |
| `tests`、`apps/web/e2e` | 回归测试，持续保留 |

Python 环境为 `.venv`，用户数据及临时文件为 `var`，引擎上游为 `vendor/engine-upstream`，生成源码为 `runtime/engine`。重建引擎使用 `scripts/engine/build_engine.py`，需固定上游源码；日常启动直接使用已校验的生成源码。

## 维护验证

Windows 示例：

```powershell
$env:PYTHONPATH='runtime/engine;.;tests/rules'
.venv/Scripts/python.exe -X utf8 -m pytest tests/portable tests/collection tests/sync -q
npm --prefix apps/web run build
```

Linux 改用 `.venv/bin/python`，`PYTHONPATH` 分隔符为 `:`。浏览器测试在 `apps/web` 执行 `npm run test:e2e`，需先安装 Playwright 浏览器。测试必须使用独立数据库。规则变更仍按 `scripts/sync/regression.py` 和同步发布门禁验证，启动检查不能替代规则回归。

更新 `RELEASE.json` 后，运行 `python scripts/release.py build --include-restricted-data` 构建完整本地安装包。公开源码包使用 `python scripts/public/export_source.py` 导出。已有包不会覆盖。构建只收集指定源码和冻结依赖，不读取个人对局数据库。解包后先校验，再安装和启动。
