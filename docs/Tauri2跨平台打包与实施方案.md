## 1. 产品决策与交付顺序

使用 **Tauri 2** 作为原生应用壳，复用当前 React GUI 和共享 Arena。优先交付 **macOS、原生 Windows 完整版**；随后交付 iOS／iPadOS 版，**不要求支持人机练习**。用户已授权 P7 运行期间在独立工作树开展 P8-A；正式服务发布仍须引用 P7 验收结果。P8 内先完成桌面交付，再实施移动端。

| 能力 | macOS | 原生 Windows | iOS／iPadOS |
| --- | --- | --- | --- |
| 卡牌资料库、卡图与离线缓存 | 完整支持 | 完整支持 | 支持 |
| 收藏、愿望清单、卡组构筑与冻结版本 | 完整支持 | 完整支持 | 支持，通过移动存储适配 |
| 导入／导出、资源更新、桌面外观设置 | 完整支持 | 完整支持 | 支持系统文件选择／分享及移动资源更新 |
| A1／H2／A2 人机练习、暂停、单步及人机历史回放 | 保持当前产品功能 | 保持当前产品功能 | 不纳入交付范围，不显示练习入口 |
| 房间码邀请、双人网络对战、恢复及本人私有回放 | 完整支持 | 完整支持 | 支持 |
| 本机卡库同步、规则适配与效果验证流程 | 保持当前产品功能 | 保持当前产品功能 | 仅更新展示目录和资源，不运行本地规则适配／人机验证 |
| Python 运行时、规则引擎与产品 AI 推理依赖 | 随包携带 | 随包携带 | 不携带 |
| 远程 API v2 与 PostgreSQL | 使用独立服务 | 使用独立服务 | 使用相同独立服务 |

“完整版”指保留目前本地产品功能，不引入 AI 研究、训练或实验平台。Windows 首次交付必须是原生安装和运行，WSL2 验收不代替原生 Windows 验收。iOS 的人机历史导入／回放不作为首版要求，网络对局的私有回放必须支持。

收藏、卡组与远程游客身份继续按设备管理；本次不加入云收藏、账号同步或跨设备自动合并身份。导入卡组不等于迁移网络身份。

## 2. 当前架构与打包差距

当前产品通过 React 静态 GUI、本机 Python 3.14 宿主及原生网络客户端工作。`scripts/start.py`、`apps/desktop-api` 与 `scripts/product/manage_kit.py` 管理启动和资源；人机、收藏和更新功能仍依赖本地产品 Python 代码。仅将 `dist` 放入 WebView 无法提供这些完整功能。

已核对的桌面前置差距：

- `packages/online-client/src/ptcg_online_client/vault.py` 当前仅接受 POSIX，依赖文件权限与 `fcntl.flock`；尚无原生 Windows 凭据后端。
- `apps/desktop-api/src/ptcg_desktop_api/reopen.py` 使用 `getuid`、Unix domain socket 和 POSIX 锁；需替换为平台抽象。
- 现有安装器明确要求 macOS／WSL2 和外部 Python、Git，不能直接称为原生 Windows 安装器。
- 当前界面与产品测试主要运行在浏览器中；Tauri 的 macOS WKWebView、Windows WebView2 及 iOS WKWebView 均需单独验证。

Tauri 官方支持捆绑 Python CLI／API 辅助程序（sidecar），但要求准备目标平台对应的可执行文件。[外部程序打包](https://v2.tauri.app/develop/sidecar/)

Tauri 的移动端 shell 不提供通用子进程启动；Python 在 iOS 需要嵌入式集成。因此本方案让 iOS 使用原生服务适配，而不移植当前 Python 后台。[Shell 平台支持](https://v2.tauri.app/plugin/shell/)、[Python iOS 运行方式](https://docs.python.org/3.14/using/ios.html)

## 3. 仓库归属与可复用边界

以下为 P8 目标结构；P8-A 已开始实现原生壳、平台合同及随包后台，注册清单按实际新增项目更新：

| 位置 | 责任 |
| --- | --- |
| `apps/native-shell/` | Tauri 2 Rust 宿主、桌面／移动入口、窗口生命周期与平台能力 |
| `apps/native-shell/src-tauri/` | 应用标识、平台配置、权限、签名配置模板及原生服务实现 |
| `packages/platform-services/` | GUI 使用的 TypeScript 平台服务合同与适配器；不包含裁定引擎 |
| `scripts/native/` | 分平台运行时组装、辅助程序构建、签名、安装与制品检查 |
| `apps/web`、`apps/desktop-web` | 保留现有完整产品壳层、网络大厅、人机页面及共享布局 |
| `packages/battle-ui`、`packages/battle-protocol` | 继续作为共享显示与协议合同；不直接访问系统凭据或执行程序 |
| `apps/desktop-api`、本地产品 Python 代码 | 桌面后台；逐项消除平台绑定，而非为每个操作系统复制一套实现 |

GUI 通过明确的产品服务接口访问目录、收藏、卡组、资源、网络对局与文件选择。桌面适配复用本机 API；移动适配调用受限的 Tauri 原生命令。同一组件不散布操作系统判断，也不为 iOS 复制一套独立大厅和 Arena。

网络控制器继续依赖 `OnlineAPI` 一类接口；iOS 实现相同语义的原生适配，不伪造一个 Python 后台。平台能力区分 `localPractice`、`localRuleVerification`、`onlineDuel`、`privateReplay` 和资源更新等。iOS 构建剔除练习入口和练习控制器依赖；能力标记只控制界面，不授予服务端权限。

## 4. 桌面运行方式

推荐首版路径：**Tauri 窗口 → 由壳管理的单一本机 Python 产品宿主 → 本地数据／人机及远程 API v2**。

1. Rust 主进程定位随包运行时，校验组合清单，将可写数据放入稳定的用户数据目录。
2. 取得用户级单实例所有权，启动明确路径的产品辅助程序；只绑定 `127.0.0.1`，通过原生启动通道获取实际端口、进程状态和一次性启动授权。
3. 完成健康／就绪检查后，在 WebView 加载该进程提供的本机 GUI。继续使用现有 HTTP 同源业务路径，避免为首个桌面版本重写所有产品接口。
4. 由受控启动页与一次性授权契约完成 WebView 会话初始化。无需终端授权码或生成 HTML 文件；授权不放 URL、命令行、日志或持久浏览器存储。P8-A 必须验证 WebView 原生引导或一次性表单的可行实现、Cookie 归属、重开及过期行为，再固定接口。
5. 双击应用重开现有窗口，或使用明确的第二配置启动独立身份；不能根据“某端口响应了 HTTP”就认领已有进程。配置、所有者及启动实例须匹配。
6. 关闭窗口与退出 APP 的行为明确区分；退出时等待已提交／未知命令完成持久记录，关闭 WSS、连接池及自有子进程。异常退出后依原 commandId、回执和游标恢复，不自动认输或新建游客。

现有浏览器启动路径继续作为开发／兼容入口。WebView 默认不获得任意 shell、文件路径或远程页面的原生权限；产品页只加载当前壳确认的本机 origin，外部链接交给系统浏览器。一次性授权入口如需接受特定启动 origin，只精确扩展该入口的验证契约，业务 API 的同源／所有者检查继续保留。[Tauri 能力边界](https://v2.tauri.app/security/capabilities/)

原生运行时必须支持正常 GUI 的当前窗口、全屏 Arena、回放、关闭重开、文件导入导出和图片缓存。不能以“已经出现一个窗口”完成桌面验收。

## 5. macOS 与 Windows 平台适配

| 模块 | macOS | 原生 Windows | 一致性要求 |
| --- | --- | --- | --- |
| 数据目录 | 应用专属 Application Support，缓存分离 | 应用专属 AppData，缓存分离 | 与安装路径／版本目录无关；支持中文、空格及非管理员用户 |
| 凭据保护 | Keychain 保护凭据或加密密钥，数据文件保留用户权限 | 用户级 DPAPI 等平台保护，配合专属 ACL | 长期 token 不进入 GUI；原 vault schema、待确认日志与恢复语义可迁移 |
| 单实例及互斥 | 原生单实例／文件锁适配 | 用户级命名互斥量或等价原生锁 | 同一身份只存在一个写入所有者；不同配置可独立测试 |
| 重开与 IPC | 本机受限 IPC | 带用户访问控制的命名管道或等价 IPC | 验证配置与所有者，不暴露公共控制端口 |
| 进程生命周期 | 明确子进程及退出回收 | Job Object 或等价进程树管理 | 崩溃、超时与退出不遗留规则进程，不终止其他应用 |
| 文件写入 | 受限目录、原子替换、落盘与锁 | 适配 Windows 共享／锁／替换行为 | 写盘失败与断电不清除幂等日志或覆盖有效凭据 |

DPAPI 通常绑定同一用户及计算机，不能把受保护状态目录复制到另一台电脑当作身份迁移方案。[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

抽象实现必须覆盖启动器、vault、重开及本地运行路径，不能仅在 Windows 跳过权限检查。当前规则加载、临时文件、子进程信号、路径和所需第三方 wheel 同时做平台审计；测试失败时记录真实缺项，不用 WSL2 替代。

## 6. 桌面依赖、资源和版本

桌面安装包携带版本固定的 Python 运行时、实际产品后台、网络客户端、规则／provider、GUI 和产品人机所需推理依赖。首版优先验证“独立运行时目录＋已安装 wheel＋明确启动程序”；PyInstaller 等冻结工具只有在动态规则加载、资源定位、源码身份和重启测试通过后才能作为实现选择。

用户不需要自行安装 Python、Node、Rust 或 WSL2。完整卡库更新如果仍调用 Git，需携带经核验的平台工具，或先实现等价的固定快照下载流程；不能保留未声明的系统 Git 依赖。正式构建及测试工具与用户运行依赖分开。

安装目录只读；SQLite、用户卡组、凭据、缓存、已安装资源与日志位于各自用户目录。卡图和授权规则资产按现有 Provider／清单边界分发，公开源码安装器与授权资源包分开。没有可分发资源时明确资源安装步骤，不把个人测试目录直接装进应用。

原生壳版本、应用组合版本、Python／核心版本、`ruleReleaseId`、`catalogVersion` 和资源清单分别记录。外壳更新不冒充规则更新；解释器 patch 或规则执行依赖改变时沿用现有身份计算和兼容性验收，不能改写历史哈希。规则更新后的旧对局仅展示已保存可见帧，不保留旧执行核心，也不要求跨规则续局。

## 7. iOS／iPadOS 运行方式

移动端采用 **Tauri WebView＋共享 React GUI＋原生平台服务**，不启动 Python HTTP 后台，不捆绑规则引擎、人机策略或训练依赖。

- **本地数据**：原生持久层管理目录、收藏、卡组、冻结版本与缓存；沿用产品领域合同和版本迁移规则。通过导入／导出与桌面交换卡组／收藏，不承诺两端数据库文件或凭据可直接互换。
- **网络对战**：原生网络适配实现当前 API v2 的认证、HTTPS／WSS、幂等命令、控制权、回执查询、游标补漏及私有回放。令牌保留在原生安全存储；GUI 接收既有可见投影，不直接发带浏览器 Origin 的远程请求。服务端不为 iOS 开放 CORS 或下载卡图。
- **卡组校验**：本地显示可执行的结构检查，开局准入仍以服务器返回的规则版本和校验结果为准；不为复用桌面校验流程引入移动规则引擎。
- **卡图及目录更新**：使用版本化目录／资源包、校验和与本地缓存。原生层适配现有显示资源合同；图片从配置的资源源获取，继续与对战 API 流量分离。移动“数据更新”不包含规则适配、编译或人机验收按钮。
- **前后台切换**：不假定 iOS 会一直保活 WSS。发送前持久化原请求；回到前台重新鉴权、核对回执／控制权并按原游标恢复；未知结果不自动换 commandId 重发。网络断开不清除身份和卡组。
- **交互**：适配安全区、横竖屏、触控、软键盘、文件分享和图片选择；卡牌信息可点击查看，不依赖鼠标悬停。手机与 iPad 的 Arena 布局分别实测。

现有两台 APP 测试不能视作移动验收；iOS 开发与构建使用 macOS 和完整 Xcode。[Tauri 前置环境](https://v2.tauri.app/start/prerequisites/)

## 8. 构建与交付矩阵

| 目标 | 第一批交付目标 | 构建及验证环境 |
| --- | --- | --- |
| macOS Apple Silicon | `.app`／DMG，完整功能 | 原生 macOS arm64；验证随包运行时和 WebView |
| macOS Intel | 独立 x86_64 包，完整功能 | 匹配目标的构建环境与 Intel 实机；不能仅以 Rosetta 运行代填 |
| Windows x64 | 原生安装器，完整功能 | 原生 Windows、WebView2、平台运行时及干净用户环境 |
| iOS／iPadOS arm64 | 后续签名移动包／测试分发 | macOS＋Xcode；iPhone 与 iPad 真机 |
| Windows arm64、其他平台 | 后续单独扩展 | 未验证前不列为受支持目标 |

最低系统版本由 Tauri、Python、推理依赖、目标 wheel 及实际设备共同确定，在 P8-A/B 锁定，不从单个框架的最低要求直接推导全产品兼容性。构建机需要 Rust／前端／平台 SDK；这些工具不成为用户手动安装要求。[Tauri 环境要求](https://v2.tauri.app/start/prerequisites/)

锁定 Rust、Tauri CLI／crate、插件、前端和 Python 依赖；每个目标单独组装并验证，不将一台 Mac 的虚拟环境复制给 Windows。发布物包含文件清单、兼容信息、依赖许可／SBOM、制品摘要及签名结果；Tauri 的分平台分发流程作为基础，不把构建成功等同签名、公证或商店审核通过。[Tauri 分发](https://v2.tauri.app/distribute/)

签名凭据、证书私钥与分发账号通过受控构建环境注入，不写入项目。第一批可审阅本地制品先生成并验证；外部分发沿用已有发布授权规则。

## 9. 安装、升级与回退

1. 新安装选择稳定的数据位置；导入旧测试包需显式选择来源并先备份。迁移卡组、收藏、资源索引与匹配版本；原身份目录通过专用迁移器处理，不自动创建新游客掩盖迁移失败。
2. 凭据保护后端变化采用受控迁移并验证新后端可读，保留安全回退点；不把旧明文 vault 或私钥放进普通导出包。应用签名／Keychain 访问身份变化同样需要升级测试。
3. 应用更新、展示资源更新和规则更新分开。先完整下载和校验，再切换匹配的 GUI／后台组合；不在运行中的目录逐文件覆盖 Python 程序。
4. 更新前排空自有后台的在途操作并保存未知结果，停止后替换程序；重启沿用原身份、commandId、回执与游标。数据库迁移前备份，降级需兼容的旧程序与备份。
5. 卸载默认保留用户数据；用户主动删除数据是单独动作。断网、升级失败、磁盘不足或应用被系统终止都不能默认重建数据库或重置身份。
