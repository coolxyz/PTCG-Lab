## macOS

开发机使用 Python 3.14+，先安装仓库前端依赖、锁定的 Rust 工具链和打包脚本使用的 Python 依赖。运行时压缩包来源与 SHA-256 固定在 `scripts/native/runtime-lock.json`；`--assets` 必须明确指定批准的产品卡表与规则资源目录，不得指向用户状态目录。

```sh
python3 scripts/packaging/macos.py \
  --runtime /approved/cpython-macos-arm64.tar.gz \
  --assets /approved/product-assets \
  --output release/macos-arm64
```

可选 `--rust-bin`、`--cargo-home` 和 `--target-dir` 指向独立工具链／缓存，不修改系统 Rust。脚本验证 Rust 版本、构建两种 GUI、重新组装锁定 Python 与依赖，运行源码外后台探针，生成 `.app`、ZIP、探针结果和带文件哈希的 `MANIFEST.json`。输出目录已存在则拒绝覆盖，应给每轮候选选择新目录。

最终用户解压后双击 APP，不需要 Python／Node／Rust。当前为 debug 预览，未公证，实际 WebView、完整功能与最低系统仍按 P8 分阶段验收。卡图不从既存用户缓存或数据库隐式复制；资源安装与完整数据更新仍需后续验收。

## API Server

```sh
python3 scripts/packaging/api_server.py \
  --rules /approved/rule-bundle --rule-pin <bundle.json的SHA256> \
  --host <服务器局域网IPv4或DNS> --bind 0.0.0.0 --port 8876 \
  --platform linux/arm64 --output release/api-server
```

默认重新构建当前源码的 API 基础镜像；`--base-image` 只能显式复用与当前四个 Python 包源码完全一致的镜像，存在旧核心／服务代码或缺少源码都会拒绝。仅复制经过 provider 验证的 manifest 组件到专用镜像，不复制整个资源目录。规则身份在最终镜像的解释器中计算并实际激活引擎，写入 Compose；不采用宿主 Python 身份、不加载旧规则。

同时生成独立 PostgreSQL 镜像归档、随机服务器身份和数据库秘密、30 天测试 CA／TLS 证书、`compose.yaml`、独立管理器和 Mac 连接助手。镜像归档使同架构 Docker 主机可离开仓库启动，不需要服务器端卡图／GUI／AI 依赖。换为 `linux/amd64` 必须重新构建并验收，未验证架构不能冒称通过。

可通过 `--postgres-image` 显式固定批准的 PostgreSQL 17 摘要。已有本地镜像会先核对并复用，缺失时才拉取；镜像架构不符则拒绝，应先准备目标架构镜像。清单同时记录实际 PostgreSQL patch、镜像身份和上游摘要，启动不再依赖浮动标签。

默认 public host 为 localhost、仅绑定回环；指定局域网地址时还需显式 `--bind 0.0.0.0`。8874 及既有保留端口被拒绝，避免使用当前 LAN 测试端口。

```sh
cd release/api-server
python3 manage.py verify
python3 manage.py up
python3 manage.py check
python3 manage.py down
```

管理器需要 Python 3.11+ 与 Docker Compose v2，固定操作本候选的独立项目；镜像与清单核对通过后才启动。数据库无宿主端口，先完成 migration 后 API 才启动，healthcheck 使用 TLS 与 `/readyz`。停止保留数据卷，不执行全局 prune，不改变既有 LAN 项目。配置示例使用固定资源预算，不代表已测得并发容量。

Mac 关闭 APP 后运行 `release/api-server/configure-mac.command`，将公开 CA 和测试地址配置到 preview profile，随后重新打开 APP。APP 移动后可通过 `PTCG_APP` 指定路径。已有配置或 CA 拒绝覆盖，原游客身份与卡组保留；不自动运行该配置助手，也不修改真实用户 profile。

## 发布边界

`release/api-server` 含私有 CA、TLS 私钥和数据库密码，目录为 0700，不可作为公开下载上传。公开分享仅取 APP ZIP 和经批准的公共连接信息；发布服务器镜像时另行审查规则许可。清单是完整性与来源记录，不是签名。许可／SBOM、签名公证、干净系统、Windows、备份恢复与容量验收继续按 P8／P7 文档实施。

本轮实际构建与隔离 Compose 冒烟结果生成后记录在各产物清单及 `release/VALIDATION.json`，不将测试身份、私钥、压缩镜像或 APP 纳入 Git。
