# PTCG Lab API Server 一键更新

在原服务器选择与 Docker 主机架构一致的包并解压。安排维护窗口，保留原安装目录、镜像和私有配置。进入解压目录后运行。

```sh
./update.sh
```

更新器从正在运行的 Compose API 容器读取原项目和配置文件路径。若原 API 已停止、存在多个部署，或项目名由原启动脚本指定，可直接给出路径和项目名。

```sh
./update.sh /原部署的绝对路径/compose.yaml 原项目名
```

支持与包内旧规则匹配的单文件 Compose 项目。原配置须直接声明 `api` 和 `migrate` 的镜像、规则 ID 和 pin。对于标准 `server.sh` 离线安装，更新器也替换原目录的 API 镜像归档、镜像清单与校验清单，原启动脚本可以重新导入新版镜像。PostgreSQL 和 Caddy 镜像继续沿用。固定配置 `manage.py` kit、多个 Compose 文件及启动时重新生成配置的自定义脚本需要单独适配。

脚本会检查包与镜像身份，预演配置差异，停止 API，验证 PostgreSQL 备份，在原配置中切换镜像与规则，再迁移并启动。数据库、服务器身份、端口与证书配置沿用原值。成功后脚本确认新规则已就绪并允许开局。上线前仍需通过原域名检查 HTTPS 和 App 重连。

脚本打印的私有备份目录包含旧 Compose 文件和数据库快照。更新标准离线安装时也备份原 API 镜像归档和相关清单。失败时保持 API 停止，保留备份。修正故障后可用同一命令重试，回退则按同一快照恢复旧镜像归档、清单、配置和数据库。
