# iOS 原生界面验收驱动

Apple XCUITest 直接操作已安装的移动预览 App。工程没有产品 App 构建依赖，不修改数据库、注入 IPC 或替换规则；测试中的终止/重开只针对预览 App。本驱动是需要前置资料的有状态验收脚本，不能作为无条件 CI 套件运行。

操作者须先选定可写入测试资料的专用模拟器，明确授权安装 Runner 和原生界面操作。不要使用实体设备、正式身份、正式对战服务或泛指 `booted`。需要已安装候选包、独立 HTTPS 回环 API、公开 CA、本机测试文件和正常协议对手。

将本目录的 Swift 和工程规格复制到全新的私有工作目录；在该目录生成 `PublicServer.json`，内容均为字符串：`ownedSimulatorAcceptance: "true"`、`origin`、`caPem`、`inviteCode`。origin 必须是 `https://127.0.0.1:<20000–65535端口>`。没有显式验收标志会跳过测试；不接受外部服务。配置不含令牌、私钥或真实身份。不要将实际配置、Xcode 工程、测试输出或资料提交到源码。

使用锁定的 XcodeGen 生成工程，显式指定设备 ID，并逐条选择用例：

```sh
xcodegen generate --spec <私有目录>/project.yml
xcodebuild test \
  -project <私有目录>/P8FMobileAcceptance.xcodeproj -scheme Acceptance \
  -destination 'platform=iOS Simulator,id=<专用模拟器ID>' \
  -derivedDataPath <专用构建目录> -parallel-testing-enabled NO \
  -collect-test-diagnostics never \
  -only-testing:Acceptance/Acceptance/<选择的测试方法> \
  -resultBundlePath <全新结果路径>.xcresult
```

文件选择器须能看见 App 的 Documents；预置 `01-deck-60.txt`（4 张 `CN:CSVM2cC:003` 与 56 张 `CN:CSM2.1C:044`）、`02-collection.csv`（同一梦幻印刷版本、数量 2、良好、备注 `P8-F notes`、愿望单 true）、`03-rejected-deck.txt`（未知印刷版本）。这些内容须与候选当前资料匹配，不是规则版本兼容机制。初始卡组已通过 UI 导入并命名“导入的卡组”，冻结版本为 1；CSV 尚未导入。Files 默认打开该测试位置。分享接收方使用本机文件提供器；文件重名时先由操作者选择新的接收位置。

按 01→02→03 执行卡组分享、CSV 导入/重复导入/分享、编辑备注与撤销。04 配置原生 TLS/身份并选取已有冻结卡组；05 需要对手先新建房间并更新 inviteCode；06 在该对局中通过合法界面决策自然结束并读取本人回放。对手必须使用正常公开协议，不能强制状态或认输代替自然结束。该脚本的点击计数不等于服务端已接受的命令数。07 在升级候选后检查原身份/历史/回放及备注重开；08 检查文件面板取消与错误文件拒绝。重复执行有状态用例前，先检查资料状态，不自动清空、卸载或重置。

截图名称中的 06/07 是首次实测候选批次；每次复验必须另存实际候选 SHA、源码 SHA、系统与执行结果。`xcresulttool export attachments` 可导出截图，但原始结果可能包含测试手牌、设备标识和路径，只在私有目录保存。接收方 JSON/CSV 须只读核对内容与摘要；截图不能替代接收文件验证。

09 是独立卡组交换定向用例，需在专用模拟器的 App Documents 预置 `04-deck-exchange.csv`，包含带 BOM 的 `printingId,quantity` 表头、4 张 `CN:CSVM2cC:003` 和 56 张 `CN:CSM2.1C:044`。通过系统文件面板读取 CSV、显式导入、系统分享接收到文件，然后取消一次删除，最后确认删除本次新建的临时测试草稿；不选择已有卡组删除。接收方须只读核对 `ptcg-deck.csv` 实际列名、印刷 ID 和数量；不能仅凭分享面板出现就认为文件内容通过。重复执行须先检查分享接收文件是否重名，不自动清空已有文件。

基础 01–09 方法不覆盖 iCloud 账号、签名真机 Keychain/锁屏或系统回收。桌面 GUI 配对与模拟器生命周期用例见下节；通过局部方法不能将整个 19 项产品验收矩阵标为通过。

## 桌面 GUI 配对及模拟器生命周期

配对端必须是实际桌面 GUI；使用原生壳的隔离 profile 启动入口时，不发送内置 `start-online` 自动旅程指令，卡组导入/保存/冻结、房间和对战操作由已授权的 GUI 驱动执行。单纯 Python 协议对手不能作为双端 GUI 通过证据。

23、25、24 是独立的后台、网络、进程恢复用例。23 需要 iOS 当前能合法结束回合；看到 `P8PAIR_ATOMIC_BACKGROUND_BEGIN` 后，桌面须在 45 秒内通过真实 GUI 推进一回合。回到前台须补齐步骤、清除旧操作权并显式重取。未推进对手时超时属于测试协作条件未满足，不能改成无变化也通过。

25 在专用 HTTPS/WSS 代理上制造约 6 秒断连；标记为 `P8PAIR_NETWORK_OUTAGE`，断连期间刷新，再恢复链路并重连。不要关闭宿主系统网络、放宽 TLS、切换 LAN 服务或使用正式身份。应核对重连订阅携带的游标与本人已接受快照相符。

24 看到 `P8PAIR_ARM_UNKNOWN` 后，代理应将下一条合法命令原样转发，先确认服务器成功接受，再截住响应；记录 commandId/请求体/原响应摘要，禁止改写请求或伪造成功。收到 `P8PAIR_TERMINATED_UNKNOWN` 后可释放被截住的连接。App 重开后必须沿用原身份，恢复原回执，不创建新命令。以代理报告核对原命令仅提交一次、回执 ID 与响应摘要相符、控制身份跨进程保持。代理和阶段标记协调器由操作者另行准备；上述 Xcode 工程不会自动部署或改变任何 API。完整原始网络数据不应保存或输出，尤其不能记录 Authorization、令牌、私钥或全部私有帧。

随后继续 06，以合法操作完成同一自然对局。26 验证已完整加载的本人回放：配置文件另需字符串 `expectedFinalSequence`，填写服务端本次实际终局步骤；不能假定不同随机开局总是同一个长度。它从第 0 帧开始，验证前进、末帧定位、后退和播放到结束，没有认输或控制权入口。WebKit 滑杆不一定提供 XCTest 标准滑杆所需属性，驱动在实际滑杆范围内点击，不直接修改 DOM。回放服务应返回两位成员各自从 0 到最终步骤的连续帧、对手手牌为空、无实时 decision。不要比较双方私有手牌必须相同。

这些用例覆盖模拟器的 Home、专用链路故障和明确终止 App 进程；不等同于真机锁屏、系统因资源压力回收、待确认刷新令牌轮换或故意延迟旧流帧注入。依然需要单独记录实际条件、候选 SHA 和未覆盖项目。
